### 4.6 XML 属性名高亮一致性修复（2026-10-26）

- 用户用 `samples/TEST_BASIC.xml` 人工验收，发现同为 XML 属性名，有的高亮、有的不高亮，颜色还在红/蓝之间不一致。
- 根因有三处：
  1. 非正文标签只生成了 `narrowRule`（仅着色标签名）。注入语法先消费了 `<tag`，宿主 XML 语法不再进入 `meta.tag` 状态，剩余属性名失去任何 scope，显示为正文色。
  2. `openAttribute`（procedure 的开放参数，如 `IN_X.string`）与动态属性名使用 `variable.parameter.xproc4j`，在主题中映射为橙色，与普通属性的红色不一致。
  3. SQL 正文里的嵌套 XML 子标签 `<sql-dialect>` 未先于 `source.sql` 匹配，被 SQL 语法当作比较符/标识符，标签名与 `databases` 属性均未正确着色。
- 修复：
  - 新增 `startTagRule`，用 begin/end 覆盖整个开始标签（`(<)(tag)(?=[\s/>])` … `(/?)>`），在属性段内复用 `attrsPattern`；因此属性可跨行，且不依赖宿主 XML 状态。
  - 非正文标签改为「startTagRule + 结束标签窄规则」；正文标签仍由 bodyRule 覆盖。
  - `openAttribute` 的属性名 scope 改为 `entity.other.attribute-name.xproc4j`，与普通属性统一为红色。
  - `#sqlContent` 在 `source.sql` 之前加入 `sql-dialect` 的嵌套自闭合/正文/结束标签规则。
- 新增回归：语法测试「scopes attributes of non-body tags including multiline start tags」与「keeps nested sql-dialect as XML inside a SQL body」；语法用例由 10 增至 12。
- 生成物统计：`rules=2863 top=249 repository=98 bytes=631321 maxRegex=346`（注入语法文件 1.12 MB）。
- 重新执行 `npm run check`（当时 68 单元 + 12 语法 + gen:check）、`npm run package`、开发目录集成测试与干净 VSIX profile 冒烟，全部通过。

## 8. 已知限制（摘要）

- 不提供 XML/DTD 校验与诊断。
- 不实现 TinyScript/Funic/Funvi/OGNL 的语法与补全。
- 不支持标签→Java 类跳转。
- 第三方语言注入依赖本机已安装语法扩展。
- 多行开始标签可能降低注入覆盖率。
- 虚拟工作区可能无法建立完整索引。
- 工程索引不持久化。
- 原生 Snippets 在 XML 语言内全局可见，无法按根节点进一步门控；这是 VS Code 原生片段的限制。
- 非 XML 变量高亮为纯文本扫描，字符串/注释中的变量也会着色，不支持语法级排除。
- `lang-eval*` 关键字/数值/字符串按正则语义扫描，注释中的匹配也会着色；字符串按 `'[^']*'`/`"[^"]*"` 匹配，未闭合引号会跨行吞到下一个同型引号。

完整清单见 `docs/07-用户使用手册.md` 第 9 节与 `docs/06-问题与经验.md`。
