## 1. 设计概述

### 1.1 设计目标

在 VS Code 中复刻参考插件对 XProc4J XML 的编辑体验，优先级从高到低：

1. **正确识别**：只有根节点为 `procedure` 的 XML 才启用 XProc4J 语义功能。
2. **可用高亮**：标签结构、标签正文、属性值、`$`/`#` 变量按预期着色，且不污染普通 XML。
3. **低打扰补全**：标签、属性、feature、枚举、refid、参数、变量按上下文出现，不打断 XML 扩展的既有能力。
4. **可靠导航**：refid 跨文件跳转与引用查找在索引就绪后稳定、快速。
5. **可控成本**：无语言服务器、无数据库、无网络请求、无运行期脚本执行；大工程可降级。

### 1.2 架构驱动因素

| 类型 | 驱动因素 | 设计响应 |
|---|---|---|
| 功能 | TextMate 注入只能做词法级嵌入，无法加 Java/JS 包装 | 接受语法级高亮边界；不承诺语义分析（FR-03） |
| 功能 | 注入语法静态生效，不能按根节点运行时开关 | 语义功能运行时门控；语法规则只匹配 XProc4J 特有标签/属性，降低污染 |
| 功能 | 需要跨文件 refid 导航 | 轻量工程索引 + 文件监听 + 内存覆盖 |
| 性能 | 激活 ≤300 ms，20,000 XML ≤30 s | 懒激活、懒索引、分批扫描、预过滤、上限与降级 |
| 兼容 | 不破坏 Red Hat XML 等扩展；兼容 VS Code 分支 | 保持 `xml` 语言 ID；只注册 Provider，不停止其他结果 |
| 可维护 | 111 个标签、890+ 属性声明、90 个模板 | 构建期元数据驱动 + 生成物校验 + 人工覆盖表 |
| 可测试 | 语法与语义都要回归 | 领域层不依赖 `vscode`；TextMate token 测试 + 单元/集成测试 |

### 1.3 设计原则

- **关注点分离**：VS Code 适配层只做 API 转换；扫描、索引、补全决策为纯 TypeScript 领域逻辑。
- **静态优先**：能构建期生成的（标签目录、语法、Snippets）不在运行期推导。
- **按需工作**：激活不扫描工作区；索引在首次识别到 XProc4J 文档或显式命令时启动。
- **失败降级**：任何 Provider 异常都返回空结果并记录日志，不影响 XML 基础编辑。
- **单一事实源**：标签/属性以构建期元数据为准；运行期只读，不在代码中散落魔法字符串。
- **可观测**：关键路径有耗时、数量、跳过原因日志，便于定位性能与兼容问题。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| Gate / 门控 | 判断文档是否为 XProc4J procedure 文件，并决定是否启用语义功能 |
| 文档模型 | 对当前 XML 文本做容错扫描得到的元素、属性、范围、层级结构 |
| 工程索引 | 工作区内所有 XProc4J 定义与 refid 引用的内存索引 |
| 开放属性 | 允许任意参数名的标签（如 `procedure-call`） |
| feature | 属性名以 `.` 分隔的修饰符，如 `value.render`、`result.trim` |
| SQL 区域 | `sql-*` 标签正文及其内部动态 SQL 标签正文 |
| 生成物 | `metadata/*.json`、注入语法、Snippets 等由脚本产出的文件 |

### 1.5 本期不设计

- XML 诊断/校验（未知标签、未知属性、结构错误、refid 不存在）。
- 悬停文档、CodeLens、行号区图标。
- 标签名 → Java 节点实现类跳转。
- TinyScript/Funic/Funvi/OGNL 的语言服务、补全、格式化、调试。
- 内嵌 Java/SQL 的语义分析、类型解析、错误检查（仅语法高亮）。
- Oracle 存储过程转换、调试器、工程级语言模板配置。
- 自定义配色主题（仅提供 scope 与文档示例）。

## 2. 总体架构

### 2.1 运行形态

- 单进程 VS Code 扩展（Extension Host，Node.js），不使用语言服务器、Webview、Worker（v1）。
- 语法高亮由 VS Code 的 TextMate 引擎 + 注入语法完成，不经过扩展代码。
- 语义能力（补全、跳转、引用、大纲、折叠、变量语义 token）由扩展注册的 Provider 提供。
- 工程索引在 Extension Host 内异步构建，只驻留内存。

### 2.2 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ L1 接入层（VS Code Adapters）                                 │
│  CompletionProvider  DefinitionProvider  ReferenceProvider   │
│  DocumentSymbolProvider  FoldingRangeProvider                │
│  SemanticTokensProvider  Commands  FileSystemWatcher         │
└───────────────────────────┬──────────────────────────────────┘
                            │ 纯数据 / 偏移量
┌───────────────────────────▼──────────────────────────────────┐
│ L2 应用服务层（Application Services）                         │
│  CompletionService  NavigationService  SymbolService         │
│  VariableService   TemplateService    IndexService (Facade)  │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│ L3 领域层（Domain，纯 TypeScript，不 import 'vscode'）         │
│  XProcDetector  XmlScanner  XProcDocumentModel               │
│  TagCatalog  VariableExtractor  CompletionContextResolver    │
│  CompletionAssemblers  IndexModel  SnippetCatalog            │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│ L4 基础设施层（Infrastructure）                               │
│  VsCodeDocumentAdapter  WorkspaceFs  ConfigStore             │
│  OutputLogger  MetadataLoader  Clock/Disposables             │
└──────────────────────────────────────────────────────────────┘
```

依赖方向只能自上而下。L3 不依赖 `vscode`，保证可以在普通 Node 测试环境运行。

### 2.3 运行时模块全景

```
extension.ts
  ├─ ActivationController
  │   ├─ ConfigStore / OutputLogger / Disposables
  │   ├─ MetadataLoader → TagCatalog / AttributeCatalog / FeatureCatalog
  │   ├─ XProcDetector + DocumentModelCache
  │   ├─ IndexService ── WorkspaceScanner / FileWatcher / IndexModel
  │   ├─ CompletionService ── ContextResolver + Assemblers
  │   ├─ NavigationService ── Definition/Reference adapters
  │   ├─ SymbolService ── DocumentSymbol/Folding adapters
  │   ├─ VariableService ── SemanticTokens adapter
  │   ├─ BlockBackgroundService ── Editor decoration adapter
  │   └─ TemplateService / SnippetCatalog
  └─ Language assets (静态)
      ├─ syntaxes/xproc4j.injection.tmLanguage.json
      ├─ snippets/xproc4j.code-snippets
      └─ templates/procedure.xml.tpl
```

### 2.4 构建期流水线

```
procedure.dtd ─┐
procedure.xml ─┼─→ tools/extract-metadata.mjs ─→ metadata/*.json
覆盖表 overrides ─┘                                   │
                                                      ├─→ tools/generate-grammar.mjs
                                                      │      └─→ syntaxes/xproc4j.injection.tmLanguage.json
IDEA Live Templates ─→ tools/convert-snippets.mjs ────┴─→ snippets/xproc4j.code-snippets
procedure.xml（校验）─────────────────────────────────────→ 生成物差异报告
```

生成物提交到仓库，`npm run gen:check` 在工作区重新生成并比对，防止漂移。运行期不读取 DTD。

### 2.5 关键技术决策摘要

| 编号 | 决策 | 理由 |
|---|---|---|
| DD-001 | v1 不引入 Language Server | 功能以语法高亮、补全、跳转为主；LSP 增加进程/协议/打包成本，收益有限 |
| DD-002 | 保持语言 ID `xml` + 注入语法 | 兼容 XML 扩展与既有文件关联；接受语法注入无法运行时门控的限制 |
| DD-003 | 自研容错 XML 扫描器 | DTD 不严谨、编辑中 XML 常不完整；第三方解析器容错/性能不可控 |
| DD-004 | 语义功能运行时按根节点门控 | 满足 FR-01；语法层通过“只匹配特有标签”降低污染 |
| DD-005 | 索引懒构建、纯内存 | 激活指标与实现复杂度优先；重启后重建成本可接受 |
| DD-006 | 元数据构建期生成并提交 | 111 标签/890+ 属性声明不适合手写；生成物可评审、可回归 |
| DD-007 | 变量高亮混合方案 | 正文变量由 TextMate 负责；已知属性值变量由语义 token 兜底（见 9.5） |
| DD-008 | 单 Provider 编排补全 | 一次上下文判定，多 Assembler 产出，减少重复扫描与候选冲突 |
| DD-009 | 原生 Snippets 为主，Provider 为备选 | 先验证 `<` 触发；不可靠时切换到同一数据源的补全器 |
| DD-010 | 无 Worker、无持久化缓存（v1） | 分批异步已可满足指标；避免序列化与陈旧缓存问题，保留后续优化点 |
| DD-011 | esbuild 打包为单文件 CJS | 启动快、无 node_modules 运行时依赖、VSIX 体积小 |
| DD-012 | 领域层不依赖 `vscode` | 单元测试可在普通 Node 运行，降低测试成本 |

## 3. 业务流程

### 3.1 扩展激活与文档识别

```
VS Code 启动/打开 XML
   │
   ├─ onLanguage:xml 或 onCommand:xproc4j.*
   ▼
activate()
   ├─ 初始化日志/配置/元数据（不扫描工作区）
   ├─ 注册 Provider/命令/监听器
   └─ 若当前编辑器是 XProc4J：调度预热索引（异步，不阻塞激活）
   ▼
文档打开/切换/修改
   ├─ XProcDetector：读取文本，跳过 BOM/XML 声明/注释/DOCTYPE，找根标签
   ├─ 根标签 == procedure ?
   │    ├─ 是：标记 XProc4J，启用语义 Provider；首次触发索引
   │    └─ 否：Provider 直接返回空；语法注入仍由静态语法决定
   └─ 结果按 document.version 缓存，内容变化后失效
```

**设计要点**

- 激活事件只包含 `onLanguage:xml` 与三个命令，不使用 `workspaceContains` 触发全量扫描。
- Gate 缓存使用 `WeakMap<TextDocument, {version, result}>`，避免每次补全重复扫描。
- 对未命名文档（`untitled`）同样识别，支持 FR-06 的未保存文件跳转。
- 根节点判定必须容错：允许 XML 声明、注释、DOCTYPE、前后空白；解析失败时视为非 XProc4J。

### 3.2 补全流程

```
用户输入 (<, $, #, {, ., ", ', ,)
   │
   ▼
CompletionProvider（单入口）
   ├─ 配置开关 / Gate 检查 ──否──→ 返回空
   ├─ 取得当前文档模型（按 version 缓存）
   ├─ CompletionContextResolver 判定：
   │     标签名 / 属性名 / 属性值 / 正文 / 变量 / SQL 区域
   ├─ 依上下文调用 Assembler：
   │     TagAssembler / AttributeAssembler / ValueAssembler
   │     VariableAssembler / SqlKeywordAssembler
   ├─ 合并、去重、分类排序（sortText）
   └─ 转为 vscode.CompletionItem 返回
```

**设计要点**

- 单入口避免多个 Provider 各自扫描文档；Assembler 为纯函数式策略，易测试。
- 所有候选来自内存目录/索引，不做同步文件 I/O。
- 候选上限默认 1,000；超出按优先级截断。
- 与 XML 扩展共存：不调用 `stopPropagation`，使用 `sortText` 前缀保证 XProc4J 候选排序合理。
- 索引未就绪时，refid/参数类候选先返回当前文档可见部分，并触发后台索引；不阻塞用户输入。

### 3.3 refid 定义跳转与引用查找

```
DefinitionProvider
   ├─ Gate + 定位光标所在属性
   ├─ 属性基础名 == refid ?
   ├─ 提取属性值（去引号、反转义）
   ├─ IndexService.findDefinitions(id)
   │     ├─ 索引就绪：返回全部 Location（多目标交给 VS Code）
   │     └─ 未就绪：触发构建，返回当前打开文档中的命中
   └─ 空结果：返回 undefined，不弹错

ReferenceProvider
   ├─ Gate + 定位 id 属性（仅 procedure / script-segment）
   ├─ IndexService.findReferences(id)
   ├─ includeDeclaration 时附带声明位置
   └─ 返回跨文件 Location[]
```

**设计要点**

- `refid` 支持任意标签（覆盖 `sql-call`、`include`），不局限于参考插件显式处理的三个标签。
- 同名 id 全部保留；不做重复诊断。
- 定义/引用范围是整个属性值（不含引号），由文档模型提供精确偏移。
- 未保存文档使用编辑器内存文本覆盖磁盘内容；保存/关闭后恢复磁盘视图。

### 3.4 工程索引构建与增量刷新

```
ensureStarted()
   ├─ 已启动/禁用？→ 返回
   ├─ state = Scanning
   ├─ workspace.findFiles(include, exclude, maxFiles)
   ├─ 分批（默认 64 个/批）：
   │     ├─ 读取文件（workspace.fs，UTF-8/BOM 处理）
   │     ├─ 预过滤：文本不含 <procedure / <script-segment → 跳过
   │     ├─ light scan：提取定义、参数、refid
   │     └─ 提交到 IndexModel；每批 yield 事件循环
   ├─ 超 maxFiles：标记 truncated，输出警告，保留已索引部分
   └─ state = Ready / Degraded

文件事件（create/change/delete/rename）
   ├─ 过滤 include/exclude
   ├─ 防抖 300 ms（按 URI）
   ├─ 重新扫描单文件 → 原子替换该文件的贡献
   └─ 1 s 内反映到查询

文档事件（change/save/close）
   ├─ 脏文档：用内存文本更新覆盖层
   ├─ 保存：以磁盘/文档内容更新
   └─ 关闭：移除覆盖层，回退磁盘版本
```

**设计要点**

- 索引只保存最小数据（id、参数、范围、refid），不保存全文。
- `findFiles` 返回上限用于保护；扫描过程中可被「重建索引」取消并重启（generation token）。
- 事件期间的并发修改进入待处理队列，扫描结束后按 generation 判断是否丢弃。
- 索引禁用时退化为“仅打开文档索引”，同文件 refid 仍可用。

### 3.5 新建 Procedure 文件

```
命令 xproc4j.createProcedureFile
   ├─ 确定目标目录：右键 URI / 当前工作区 / 文件夹选择器
   ├─ 输入 id（默认 procedure，校验非空）
   ├─ 输入文件名（默认 <id>.xml，禁止路径分隔符）
   ├─ 目标已存在？→ 模态确认；拒绝则终止
   ├─ 渲染模板（id/author/date，XML 转义）
   ├─ workspace.fs.writeFile
   └─ 打开文档并显示
```

- 不创建/复制 `procedure.dtd`；README 说明从框架获取。
- 任一步取消均不产生文件；写入失败弹出可读错误并记录日志。

### 3.6 设置变更与错误降级

```
配置变更
   ├─ 语义开关：Provider 每次调用读取最新值（无需重注册）
   ├─ 索引开关：关闭→停止并清空工程索引；开启→标记待构建
   ├─ include/exclude/maxFiles：标记索引过期，防抖后重建
   └─ 日志级别：更新 OutputLogger

任意 Provider 异常
   ├─ 捕获 → 记录 error（含 URI、阶段、堆栈）
   ├─ 返回空结果 / undefined
   └─ 不向用户弹错；命令类错误才提示
```

## 4. 数据流

### 4.1 构建期数据流

| 阶段 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 元数据提取 | `procedure.dtd`、`procedure.xml`、覆盖表 | 容错 token 扫描、属性归一化、差异比对 | `metadata/tags.json`、`attributes.json`、`features.json`、`report.md` |
| 注入语法生成 | 元数据模板、语言映射表 | 生成标签规则、属性规则、动态 SQL 规则 | `syntaxes/xproc4j.injection.tmLanguage.json` |
| Snippets 转换 | IDEA `XProc4j.xml`、`procedure.xml` | 变量转换、拼写修正、结构校验 | `snippets/xproc4j.code-snippets` |
| 校验 | 生成物 + 常量类 + 示例 | 差异检查、JSON Schema、重复项检查 | `gen:check` 结果 |

### 4.2 运行期文档数据流

```
TextDocument (string + version)
   │  Adapter（偏移量，不把 vscode 类型带入领域层）
   ▼
XmlScanner ─→ ScanResult { elements[], byOffset, errors }
   │
   ├─ XProcDocumentModel（当前文档缓存）
   │     ├─ root / procedure / script-segment 节点
   │     ├─ 属性（名、值、范围、baseName、features）
   │     ├─ 变量集合（按 version 缓存）
   │     └─ 行首索引 → Position 转换
   ├─ CompletionContextResolver
   ├─ SymbolService
   └─ VariableService（语义 token）
```

### 4.3 索引数据流

```
Workspace XML ──read──→ light scan ──→ FileIndex
                                           │
                    ┌──────────────────────┼─────────────────────┐
                    ▼                      ▼                     ▼
              files: Map<uri>        byId: Map<id, Entry[]>   refs: Map<id, Ref[]>
                    │                      │                     │
                    └──────────── 查询接口（只读） ◄──────────────┘
                                      │
                     Definition / Reference / Refid Completion
```

### 4.4 补全数据流

```
CompletionContext
   ├─ tagName? / attribute? / valueKind? / prefix / range
   ├─ variables（当前文档，按 version 缓存）
   ├─ targetEntry（refid 解析后的索引项）
   └─ sqlRegion?
        │
        ├─ TagAssembler：TagCatalog
        ├─ AttributeAssembler：AttributeCatalog + Index.params
        ├─ ValueAssembler：EnumCatalog / Index.ids / 模板
        ├─ VariableAssembler：内置变量 + 文档变量
        └─ SqlKeywordAssembler：KeywordsCatalog
             │
             ▼
        merge → dedupe → sortText → CompletionItem[]
```

### 4.5 数据所有权与缓存

| 数据 | 所有者 | 生命周期 | 失效条件 |
|---|---|---|---|
| 标签/属性/feature 目录 | `MetadataLoader`（单例） | 扩展生命周期 | 不失效（版本随扩展） |
| 文档模型 | `DocumentModelCache` | 按 URI 缓存 | `document.version` 变化 |
| 变量集合 | 文档模型派生 | 按 URI+version | 同上 |
| 工程索引 | `IndexService` | 扩展生命周期 | 文件事件/重建/配置变更 |
| 打开文档覆盖 | `DocumentOverlay` | 文档打开期间 | 关闭/保存 |
| Gate 结果 | `XProcDetector` 缓存 | 按 URI+version | 同上 |
| 配置 | `ConfigStore` | 扩展生命周期 | `onDidChangeConfiguration` |

## 5. 状态转移

### 5.1 扩展生命周期

```
Inactive ──onLanguage:xml / onCommand──→ Activating
   Activating ──成功──→ Active
   Activating ──失败──→ ActivationFailed（记录日志；命令不可用）
   Active ──deactivate──→ Disposed
```

`Active` 内部不阻塞索引；索引有独立状态。

### 5.2 索引状态

| 状态 | 进入条件 | 允许操作 | 退出 |
|---|---|---|---|
| `Idle` | 初始化/禁用/清空 | 查询返回空或覆盖层 | `ensureStarted` → `Scanning` |
| `Scanning` | 首次构建/重建 | 查询返回已提交部分；可取消 | 完成 → `Ready`/`Degraded`；取消 → `Idle` |
| `Ready` | 全量完成 | 全量查询 | 文件事件 → `Updating`；重建 → `Scanning` |
| `Updating` | 增量事件 | 查询返回上一稳定版本 | 提交完成 → `Ready` |
| `Degraded` | 超上限/部分失败/禁用 | 部分查询 | 重建 → `Scanning` |
| `Disabled` | `xproc4j.index.enabled=false` | 仅打开文档索引 | 开启 → `Idle` |

### 5.3 文档模型状态

| 状态 | 说明 | 转移 |
|---|---|---|
| `Missing` | 未构建 | 首次补全/大纲/变量 → `Building` |
| `Building` | 正在扫描 | 成功 → `Fresh`；失败 → `Failed` |
| `Fresh` | version 与文档一致 | 文档变化 → `Stale` |
| `Stale` | version 不一致 | 下次请求 → `Building`（旧模型只读可用） |
| `Failed` | 扫描异常/超限 | 文档变化或重试 → `Building`；期间返回空结果 |

### 5.4 配置状态

- 配置读取无状态；每次 Provider 调用取快照。
- 索引相关配置变更写入 `indexDirty=true`，防抖 1 s 后重建（若索引已启动）。
- 非法值在读取时钳制到边界并记录 warn。

### 7.2 为什么不用 Language Server / Webview / Worker

- **LSP**：本扩展的核心是语法注入 + 轻量编辑辅助；LSP 需要独立进程、协议、文档同步与打包，无法改善 TextMate 注入的根本限制，收益低。未来若做跨文件类型分析或诊断，可再演进。
- **Webview**：所有 UI 均可用原生 QuickPick/InputBox/OutputChannel 完成；Webview 增加 CSP、消息协议、可访问性与维护成本。
- **Worker**：首次索引与增量扫描可通过分批 yield 满足指标；Worker 引入序列化、打包与生命周期复杂度，列为性能不达标时的备选优化。

### 7.3 中间件与外部服务

本期**不引入任何中间件/外部服务**：无数据库、缓存服务、消息队列、HTTP 服务、遥测服务。所有数据来自工作区文件与 VS Code 内存模型。

## 9. 核心算法与数据结构

### 9.1 容错 XML 扫描器（核心）

**目标**：在编辑中、未闭合、注释/CDATA/DOCTYPE 混排的情况下，仍能给出可用的元素/属性/范围。

**算法**：单遍字符扫描 + 状态机 + 栈。

```
状态：TEXT / TAG_OPEN / TAG_NAME / ATTR_NAME / ATTR_EQ / ATTR_VALUE / COMMENT / CDATA / PI / DOCTYPE / END_TAG
栈：openElements（记录名称、起始偏移、父索引）
输出：elements[]、attributes[]、issues[]
```

处理要点：

- 跳过 BOM、XML 声明、注释、处理指令；DOCTYPE 内部子集按 `[`/`]` 与引号配对跳过。
- 标签名允许 `[A-Za-z_][\w:.-]*`。
- 属性名允许 `[\w.:-]+`；属性值支持单/双引号；记录值范围（不含引号）。
- 自闭合 `/>` 不入栈；结束标签按名称弹栈，找不到匹配时记录 issue 并忽略。
- 文本中的 `<` 若不是合法标签起始，按文本处理，避免误判。
- 实体解码只对属性值做 `&amp; &lt; &gt; &quot; &apos;` 与数字实体；文本不解码。
- 超过 `maxElements`（默认 100,000）或 `maxDepth`（默认 256）时停止扩展，`truncated=true`。
- 行号转换用 `LineIndex`（行首偏移数组 + 二分），只为需要的偏移计算 Position。

**两种模式**：

- `document`：构建完整元素树，供补全/大纲/折叠/变量使用。
- `index`：不保留子节点数组，只维护名称栈，收集 `procedure`/`script-segment` 定义与 `refid` 属性，降低 20,000 文件的分配压力。

### 9.2 扫描器复用与缓存

- `DocumentModelCache` 以 `uri → {version, model, building?}` 保存。
- 请求时 version 一致直接返回；不一致则重建（同 URI 合并并发请求）。
- 扫描失败保留旧模型只读，返回空结果并记录；下一次请求重试。
- 索引的 light scan 使用独立入口，不复用完整模型，避免为 20,000 文件保留树。

### 9.3 补全上下文判定

输入：文本、光标偏移、当前文档模型。

步骤：

1. 定位光标前最近的未闭合 `<` 或当前属性范围。
2. 若在标签起始区内且 `<` 后无 `>`：`kind=tag`，`prefix` 为标签名前缀。
3. 若在开始标签内：
   - 若在引号内：`kind=value`，取属性名/值范围/值前缀；
   - 否则：`kind=attribute`，解析“基础名 + feature 前缀”；
4. 若在正文：判断是否位于 SQL 区域（最近的祖先标签属于 SQL 集合，或位于动态 SQL 标签内）；若光标前存在 `${`/`$!{`/`#{`/`#!{` 未闭合，标记变量上下文。
5. 否则 `kind=text`（低优先级 SQL/变量候选）。

**属性名解析**：以最后一个 `.` 分隔，前面为 `baseName`，后面为 `featurePrefix`；同时保留完整前缀用于过滤。

**需求映射**：

| 需求项 | 上下文/Assembler | 数据来源 |
|---|---|---|
| C-01 标签名 | Tag | `tags.json`（含动态 SQL） |
| C-02 属性名/feature | Attribute | `attributes.json` + `features.json` + 开放属性表 |
| C-03 procedure/script-segment 参数 | Attribute | 当前文档模型 + 索引中同 id 定义 |
| C-04 调用目标参数 | Attribute | `refid` 解析后的索引 entry |
| C-05 兜底属性 | Attribute | 固定兜底表 |
| C-06 refid 值 | Value | 索引 id 集合（去重，detail 标注路径） |
| C-07~C-12 枚举/布尔/日期/方法 | Value | `enums.json` + `keywords.json` |
| C-13 method | Value | 方法名表 |
| C-14~C-16 数据源/数据库/结果类型 | Value | `enums.json`，支持分隔符逐项替换 |
| C-17 `_lang` | Value | `injections.json` 中已知语言 ID |
| C-18 变量 | Variable | 内置变量 + 文档变量（9.4） |
| C-19 SQL 关键字 | SqlKeyword | `keywords.json`，仅 SQL 区域 |
| C-20 任意位置低优先级 | 不实现 | 避免在 XML 中产生噪音；需求标记为可选 |

### 9.4 变量提取

变量来源（按优先级）：

1. 内置变量（来自 `CompletionHelper.STATIC_EMBED_VARIABLES`，共 42 项，含 `trace.*` 别名）。
2. 当前文档 `procedure`/`script-segment` 的非 `id` 属性名（去掉 feature 后缀）。
3. 当前文档中 `result`、`item` 等输出属性值（去 feature）。
4. 正文与属性值中的 `${name}`、`$!{name}`、`#{name}`、`#!{name}`（去空白；含 `.` 时同时加入根段）。
5. 不解析 TinyScript/Funic 赋值（范围外）。

结果按文档 version 缓存；补全时去重，内置变量排后。

### 9.5 TextMate 语法设计（结构高亮与语言注入）

**文件**：`syntaxes/xproc4j.injection.tmLanguage.json`（生成）。

#### 9.5.1 结构高亮（FR-02）

XML 基础部分（声明、注释、CDATA、DOCTYPE、标点、普通标签）继续由内置 `text.xml` 负责；本扩展只追加 XProc4J 语义 scope，不复制 XML 语法。

| 对象 | scope 约定 | 说明 |
|---|---|---|
| 标签名 | `entity.name.tag.xproc4j` + 分类子 scope，如 `entity.name.tag.sql.xproc4j` | 分类：log/lang/sql/etl/event/context/script/call/dynamic；未知标签不追加 |
| 属性名 | `entity.other.attribute-name.xproc4j` | 基础属性名 |
| feature 后缀 | `entity.other.attribute-name.feature.xproc4j` | `.render`、`.eval-java` 等 |
| 开放/动态参数名 | `entity.other.attribute-name.xproc4j` | 如 `procedure-call` 上的业务参数；与普通属性统一为属性名色 |
| 枚举值 | `constant.language.xproc4j` | propagation、isolation、jdbc-type 等 |
| 布尔值 | `constant.language.boolean.xproc4j` | true/false |
| 数值 | `constant.numeric.xproc4j` | 进制、数字值 |
| refid 值 | `entity.name.reference.xproc4j` | 与定义跳转对应 |
| 语言 ID | `constant.language.language-id.xproc4j` | `_lang` 值 |
| 方法/类/包 | `entity.name.function.xproc4j` / `entity.name.type.xproc4j` / `entity.name.namespace.xproc4j` | method/class/package 等 |
| 变量 | `support.variable.xproc4j` | `$`/`#` 形式，蓝色以与括号/标点一致 |
| 空占位符 | `invalid.illegal.xproc4j` | `${}`、`#{}` 等去空白后为空 |

- 标签名/属性名规则优先只匹配已知名称，减少对普通 XML 的污染；未知标签继承 XML 默认样式。
- 非正文标签用 `startTagRule` 覆盖完整开始标签（`(<)(tag)` 到首个未加引号的 `>`），属性段复用统一 `attrsPattern`，因此属性可跨行，且不依赖宿主 XML 进入 `meta.tag` 状态。
- SQL 正文中的 XML 子标签（如 `sql-dialect`）必须先于 `source.sql` 匹配，否则会被 SQL 语法当作比较符/标识符。
- 主题兼容：只提供稳定 scope，不硬编码颜色；README 给出 `editor.tokenColorCustomizations` 示例。
- 嵌入块背景不通过 TextMate 实现：VS Code 不渲染 token 规则的 background；改由编辑器装饰按正文行绘制，范围来自文档模型。SQL 用浅黄色，`lang-eval*` 用浅绿色，见 DD-025。
- 属性值背景复用同一装饰器：范围直接取扫描器的 `valueRange`（不含引号），所有属性统一使用更浅的绿色，不经过元数据过滤。
- `lang-eval*` 关键字高亮同样用装饰：领域层按词边界匹配联合关键字，适配层用 `color: '#1E90FF'` 强制前景色。TextMate/语义 token 颜色受主题映射影响，无法保证 dodgerblue；装饰只覆盖关键字本身，不改变注入语法与背景。
- `lang-eval*` 数值与字符串字面量沿用装饰：数值蓝色、字符串绿色，按主题选明度以与浅绿整行背景、dodgerblue 关键字区分；字符串内部作为保护区，内部的关键字/数字不再二次着色。见 DD-027。
- 非 XML 变量高亮不复用语义 token Provider：VS Code 同一语言只使用评分最高的一个语义 token Provider，为 yaml/java 注册会顶掉语言扩展自身的 token。改由 `RawVariableHighlightDecorator` 对配置后缀的可见编辑器绘制定位装饰，XML 仍走原有语义 token；默认后缀为 `xml`、`yaml`、`yml`、`java`。见 DD-026。

#### 9.5.2 语言注入（FR-03）

**贡献方式**：

`syntaxes/xproc4j.injection.tmLanguage.json` 内部：

```json
{
  "scopeName": "xproc4j.injection",
  "injectionSelector": "L:text.xml",
  "patterns": [ ... ]
}
```

`package.json` 的 `contributes.grammars` 中声明注入目标：

```json
{
  "scopeName": "xproc4j.injection",
  "path": "./syntaxes/xproc4j.injection.tmLanguage.json",
  "injectTo": ["text.xml"]
}
```

**规则分组**：

1. **标签正文规则**：按目标语言分组，`begin` 匹配 `<tag ...>`，`end` 匹配 `</tag>`，内容先包含变量规则，再包含目标语言 scope。
2. **动态 SQL 规则**：`if`/`where`/`set`/`trim`/`foreach`/`choose`/`when`/`otherwise`/`bind`/`include`/`dialect*`，在 SQL 正文规则内部生效，递归嵌套；正文继续 SQL，属性值走基础/表达式规则。
3. **Java 容器规则**：`lang-eval-java` 正文按 Java；其中出现 `lang-java-import`、`lang-java-member`、`lang-java-body` 时，标签结构按 XML、正文按 Java，与容器正文规则并列。
4. **`_lang` 规则**：按字面值 `sql/java/javascript/json/xml/yaml/shell/css/markdown/groovy/...` 分别生成规则；只匹配开始标签内出现该字面值的场景。
5. **属性值规则**：匹配已知属性名（含 feature 后缀），为枚举/常量/类型/表达式/方法设置 scope；`*.eval-java` 等按目标语言注入。
6. **变量规则（正文）**：`$`/`#` 形式，空占位符使用 invalid scope。
7. **不注入清单**：`lang-body`、`lang-catch`、`lang-finally`、`script-segment`、`lang-synchronized`、`lang-async`、`sql-scope` 等容器不整体注入；`lang-eval`（OGNL）、`lang-eval-ts`/`lang-eval-tinyscript`/`lang-eval-funic` 也不注入。

#### 9.5.3 变量（FR-04）

- 变量（正文与属性值）统一由 `SemanticTokensProvider` 输出为主路径：token type `variable`，经 `contributes.semanticTokenScopes` 映射到 `support.variable.xproc4j`；空占位符使用 modifier `xprocEmptyPlaceholder`，映射到 `invalid.illegal.xproc4j`。仅对 XProc4J 文档、≤2 MB 生效，天然按根节点门控。
- TextMate 注入语法仍在正文内提供变量规则，作为语义 token 关闭或 provider 未生效时的兜底；两者并存不会报错，颜色以语义 token 为准。
- 语义 token 关闭时，属性值变量可能无色；正文变量由 TextMate 兜底（文档记录）。

#### 9.5.4 关键限制与对策

- 正文规则会消费开始标签，导致同一标签开始标签内的属性值注入可能不生效；因此：
  - 变量统一由 **SemanticTokensProvider** 作为主路径（仅识别为 XProc4J 文档时、≤2 MB），TextMate 变量规则只做兜底；
  - 属性值语言注入（如 `*.eval-java`）优先覆盖非正文注入标签；正文注入标签的属性级语言注入列为已知限制；
  - 早期 spike 验证是否可用 `lookbehind` 或嵌套规则消除该限制；若可行，可增强属性语言注入，但语义 token 主路径不变（DD-013）。
- `_lang` 需在开始标签同一行可见；跨行写法的 `_lang` 不保证生效（文档记录）。
- 标签→语言映射完全按需求 FR-03 表落到 `metadata/injections.json`，语法生成与文档共用；未知 `_lang` 值保持普通文本。
- 不添加不可见的 Java import/class/method 包装；Java 片段只做词法高亮，可能不如完整编译单元准确；JS 同理。
- 第三方 scope 未安装时静默退化；不尝试在运行期探测/切换语法。
- 语法对普通 XML 的污染通过“只匹配 XProc4J 特有标签/属性名”控制；动态 SQL 泛用标签只在 SQL 标签正文内注入。
- 语法静态生效，`xproc4j.enable` 无法关闭注入高亮；文档明确。

### 9.6 索引增量算法

```
updateFile(uri, text):
  old = files.get(uri)
  if old: removeContributions(old)
  next = lightScan(text)
  files.set(uri, next)
  addContributions(next)
  generation++
```

- 定义贡献：每个 entry 加入 `byId[id]`；重复 id 追加。
- 引用贡献：每个 ref 加入 `refsById[refid]`。
- 删除/重命名：移除旧 URI 的全部贡献。
- 覆盖层：`overlay: Map<uri, {version,text}>`；查询时优先使用覆盖层文件索引。
- 提交为同步操作，JS 单线程保证查询不会看到半更新状态（单次 `updateFile` 内完成）。
- 全量重建使用新 Map 构建，完成后整体替换，避免查询看到空索引。

### 9.7 大文件/大工程保护

| 保护 | 默认 | 行为 |
|---|---|---|
| `maxDocumentSizeKB` | 2048 | 超过：语义 Provider/语义 token 返回空；语法仍生效 |
| `maxFiles` | 20000 | 超过：停止扫描，保留已索引部分，输出警告 |
| `maxElements` | 100000 | 超过：扫描截断，模型 `truncated`，功能降级 |
| `maxDepth` | 256 | 超过：不再深入，记录 issue |
| 补全候选上限 | 1000 | 按类别优先级截断 |
| 索引文件大小 | 2048 KB | 超过：跳过索引并记录 |

### 9.8 Snippets 与新建文件模板

**Snippets**

- 数据源：参考插件 `assets/xproc4j/liveTemplates/XProc4j.xml` 的 90 个 Live Template。
- 转换：`$VAR$` → `${n:default}`；`$END$` → `$0`；`fileName()` → `TM_FILENAME`；`lineNumber()` → `TM_LINE_NUMBER`；修正 `$DATASURCE$`、`$FEATUERE$` 等拼写。
- 输出：`snippets/xproc4j.code-snippets`，前缀保留 `<tag` 形式，scope 为 `xml`。
- 校验：生成后与 `procedure.xml` 的标签集合/结构比对；自研 DSL 模板保留 XML 骨架但不含 DSL 高亮。
- 触发：S0 验证原生 Snippet 对 `<` 的触发；若不可靠，使用同一 `SnippetCatalog` 通过 `CompletionItemProvider`（`triggerCharacters: ['<']`、`InsertTextFormat.Snippet`）提供，二者择一，避免重复候选。
- Snippets 仅作为建议出现，不自动插入；用户可在 VS Code Snippet 管理中关闭。

**新建文件模板**

- `templates/procedure.xml.tpl` 包含：XML 声明、`<!DOCTYPE procedure SYSTEM "procedure.dtd">`、`<procedure id="${id}">`、作者/日期注释、空行缩进。
- 渲染时对 `id` 做 XML 属性转义；文件名默认 `${id}.xml`，禁止路径分隔符。
- 目标存在时模态确认；写入使用 `workspace.fs.writeFile`，一次性写入完整内容。
- 不创建/复制 DTD；README 给出获取方式。

## 11. 可靠性与故障恢复

### 11.1 异常边界

- 每个 Provider 入口 `try/catch`：记录 error，返回空/undefined。
- 每个异步任务带 `CancellationToken` 检查；索引 generation 不一致时丢弃结果。
- 文件读取失败、解码失败、扫描失败：按文件跳过，不失败整批。
- 配置读取失败：使用默认值并记录 warn。
- 命令流程分步确认；任一步异常给出可读消息并清理临时状态。

### 11.2 降级矩阵

| 条件 | 高亮 | 补全 | 跳转/引用 | 大纲/折叠 | 说明 |
|---|---|---|---|---|---|
| 非 procedure XML | 静态语法可能有限匹配 | 无 | 无 | 无 | Gate 关闭 |
| 文档 >2 MB | 有 | 无 | 无 | 无 | 语义跳过 |
| 索引禁用 | 有 | 当前文档 | 当前文档 | 有 | 覆盖层索引 |
| 索引超 maxFiles | 有 | 部分 | 部分 | 有 | 标记 truncated |
| 单文件解析失败 | 有 | 该文件无 | 该文件无 | 该文件无 | 记录日志 |
| 第三方语法未安装 | 该区域普通文本 | 不受影响 | 不受影响 | 不受影响 | 静默 |
| 语义高亮被用户关闭 | 正文变量有；属性变量可能无色 | — | — | — | 文档说明 |
| 扩展激活异常 | 静态语法仍有 | 无 | 无 | 无 | 日志+命令不可用 |
| 工作区无 XML | 有 | 当前文档 | 当前文档 | 有 | 不扫描 |

### 11.3 并发、取消与竞态

- 单线程事件循环；所有 I/O 异步。
- 全量扫描每批 `await yieldToEventLoop()`；响应取消。
- 文件事件按 URI 防抖 300 ms；批量提交；同一 URI 的旧任务被新任务取消。
- 覆盖层优先于磁盘；脏文档关闭时移除覆盖层。
- `generation` 令牌防止旧扫描结果覆盖新配置/新重建。
- 查询始终读取已提交状态，不等待正在构建的文件。

### 11.4 启动与恢复

- 无持久化索引：重启后按需重建，不会读取陈旧数据。
- 工作区信任状态不影响只读功能；不执行任何工作区代码。
- 扩展崩溃/重载后，Provider 重新注册；已打开文档重新识别。
- 新建文件写入失败时保留用户输入上下文，可重试；不产生半写文件（先渲染完整内容再一次性写入）。

## 13. 性能设计

### 13.1 指标与机制

| 指标 | 目标 | 机制 |
|---|---|---|
| 激活 | ≤300 ms | 不扫描、不解析大文件；元数据 JSON 小且懒加载；Provider 注册轻量 |
| 首次索引 5,000 XML | ≤8 s | 预过滤、light scan、64/批、无完整 AST、UTF-8 快速解码 |
| 首次索引 20,000 XML | ≤30 s | 同上 + maxFiles/大小上限 + 跳过无关键标签文件 |
| 增量更新 | ≤1 s | 单文件扫描 + 300 ms 防抖 + 原子替换 |
| 补全 P95 | ≤300 ms | 缓存模型、内存目录、单次上下文判定、无 I/O、候选上限 |
| 定义 P95 | ≤500 ms | Map 查询；索引未就绪时返回部分并后台构建 |
| 大纲 10,000 行 | ≤150 ms | 单遍扫描 + 复用缓存；超限文档跳过 |
| 索引内存 | ≤50 MB | 只存 id/参数/范围/refid；不存全文；上限 |
| 语法高亮 | 交互流畅 | TextMate 逐行、规则数量受控、避免超宽正则 |

### 13.2 性能工程措施

- 生成语法时合并相同 begin 前缀，减少规则数；避免灾难性回溯（禁用嵌套量词）。
- 索引预过滤先用 `indexOf('<procedure')` / `indexOf('<script-segment')`，再扫描。
- 文档模型缓存按 version；补全期间不重复扫描。
- 变量集合缓存；只对需要的属性/文本做提取。
- 大文档阈值可配置；超过后所有语义 Provider 立即返回，不做扫描。
- 记录每个阶段耗时（debug 级别），提供基准脚本 `test/bench/`（开发期）。
- 若实测不达标：优先调批大小/跳过策略；仍不达标再评估 Worker（DD-010 备选）。

## 14. 兼容性设计

- **VS Code 1.90+**：仅使用稳定 API；不使用 proposed API；`engines.vscode: ^1.90.0`。
- **Cursor/Windsurf**：不依赖 VS Code 专有扩展点；语义 token、Provider、命令均为基础 API。
- **XML 扩展共存**：语言 ID 不变；不停止其他补全；折叠合并；语法注入仅追加 scope。
- **主题**：只提供 scope，不强制颜色；文档给出可选 token 颜色示例。
- **编码**：编辑器文档由 VS Code 解码；索引读取支持 UTF-8（含 BOM）与 UTF-16 BOM，其他编码按 UTF-8 容错；无法解码时跳过并记录。
- **多根工作区**：索引覆盖所有 workspace folder；URI 作为键；补全 detail 显示相对路径。
- **远程/虚拟文件系统**：通过 `workspace.fs` 读取；不假设本地路径；新建文件使用 URI。
- **Windows/macOS/Linux**：路径处理使用 URI，不拼接分隔符。
- **无 Web 支持**：`browser` 字段不提供；文档说明。

## 15. 测试与验收策略

### 15.1 测试分层

| 层级 | 工具 | 覆盖 |
|---|---|---|
| 单元 | Vitest（Node） | 扫描器、行号、实体、检测器、上下文判定、变量提取、各 Assembler、索引增量、模板渲染、Snippet 转换 |
| 语法 | `vscode-textmate` + `vscode-oniguruma` + 测试专用基础 XML 语法 | 标签正文/属性/变量/动态 SQL 的 scope 断言；规则性能 |
| 集成 | `@vscode/test-electron`（可选 CI） | 激活、Gate、补全、跳转、引用、符号、折叠、命令、配置开关 |
| 手工 | 检查清单 | 主题、第三方语法、大工程、Cursor/Windsurf、离线安装 |

### 15.2 Fixture 设计

- 以 `procedure.xml` 按类别拆分为多个 fixture：日志、语言控制、SQL、ETL、事件、上下文、动态 SQL。
- 补充边界 fixture：未闭合标签、注释内伪标签、CDATA、属性内 `>`、单引号、feature 组合、同名 id、跨文件 refid、超大文件（生成）、深层嵌套。
- 每个 fixture 标注期望 scope 与期望补全/导航结果。

### 15.3 验收对应

- 功能验收沿用需求第 10.1 节 1~10 项；每项映射到测试用例。
- 性能验收用基准脚本记录数据；CI 可选运行轻量基准。
- 覆盖率目标：核心领域逻辑 ≥80%；语法规则以 fixture 覆盖率为准。

## 18. 风险与待验证项

| 风险/待验证 | 影响 | 计划 |
|---|---|---|
| TextMate 正文注入消费开始标签，属性值注入受限 | FR-03/FR-04 部分属性 | S0 spike；语义 token 兜底；验证 lookbehind/嵌套规则 |
| `<` 前缀原生 Snippet 是否触发 | FR-07 体验 | S0-04 已通过；原生单路，未采用 Provider 兜底 |
| `_lang` 跨行/动态值 | 注入不生效 | 文档限制；仅支持同行字面值 |
| 第三方 scope 名称不一致 | 注入不生效 | 维护已知映射；文档列出；未安装静默 |
| DTD 缺类型/重复声明 | 元数据错误 | 容错提取 + 覆盖表 + 差异报告 + golden 测试 |
| 动态 SQL 嵌套中断 SQL scope | 高亮不连续 | 递归规则 + fixture；spike 验证 |
| 大工程扫描耗时/内存 | 体验下降 | 预过滤、分批、上限、基准；必要时 Worker |
| 与 XML 扩展补全重复 | 候选噪音 | sortText、去重、文档说明、开关 |
| 语义 token 被用户关闭 | 属性变量无色 | 文档说明；正文变量仍由语法提供 |
| 语义注入对普通 XML 的污染 | 误高亮 | 只匹配特有标签/属性；动态 SQL 限定父级 |

**S0 技术验证清单（实现第 1 周）**

1. 注入语法能否稳定作用到 `text.xml`，并与内置 XML 语法共存。
2. SQL 正文中的动态 SQL 标签嵌套后 SQL scope 是否连续。
3. 正文注入消费开始标签后，属性值注入/变量高亮的影响范围；语义 token 兜底是否满足 FR-04。
4. `_lang` 同行字面值规则是否可用；跨行限制确认。
5. 原生 Snippet 对 `<` 前缀的触发行为。
6. 未安装 Groovy 等第三方语法时是否静默退化。
7. 扫描器对 2,048 KB、10,000 行、未闭合 XML 的耗时与正确性。
8. `workspace.findFiles` + 分批读取在 5,000/20,000 文件下的耗时/内存。

## 20. 设计决策记录

| 编号 | 决策 | 备选 | 结论/理由 |
|---|---|---|---|
| DD-001 | 不引入 LSP | LSP、纯静态 | 功能与成本不匹配；保留未来演进 |
| DD-002 | 保持 `xml` + 注入 | 新语言 ID、复制 XML 语法 | 兼容 XML 扩展；接受运行时门控限制 |
| DD-003 | 自研容错扫描器 | `@xml-tools/parser`、SAX、DOM | 容错/性能/零依赖可控 |
| DD-004 | 语义功能 Gate | 语法级门控 | 语法静态无法门控；语义可精确控制 |
| DD-005 | 索引纯内存、懒构建 | 持久化缓存、启动全量 | 简单可靠；重启重建可接受 |
| DD-006 | 元数据构建期生成 | 运行期解析 DTD、手写常量 | 避免 DTD 不严谨与运行期开销 |
| DD-007 | 变量高亮：语义 token 主路径 + TextMate 兜底 | 全 TextMate、全语义 | 规避注入边界；属性变量可门控；DD-013 进一步明确 |
| DD-008 | 单补全 Provider + Assembler | 多 Provider | 一次上下文判定、去重容易、性能稳定 |
| DD-009 | 原生 Snippets 单路 | 直接 Provider | S0-04 已确认 `<` 触发与 `xml` 限定；不设 Provider 兜底 |
| DD-010 | v1 无 Worker/无持久化 | Worker、缓存 | 满足指标前提下降低复杂度 |
| DD-011 | esbuild 单文件打包 | tsc、webpack | 启动快、依赖少 |
| DD-012 | 领域层零 `vscode` 依赖 | 直接使用 API | 可单测、可维护 |

> DD-013~DD-024（语义 token 主路径、`_lang` 限定、索引行范围、原生 Snippets 单路、新建文件 WorkspaceEdit、日志脱敏、第三方语法 scope、DTD 不分发等）记录在[详细设计 §16](04-详细设计.md#16-详细设计决策记录)，本文档不重复。
