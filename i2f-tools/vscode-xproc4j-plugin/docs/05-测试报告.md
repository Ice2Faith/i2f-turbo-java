## 4. 未自动化/待人工确认

以下项目依赖真实编辑器渲染、交互、第三方扩展或大规模工作区，当前版本未完全纳入自动化门禁，发布前应按清单人工确认：

1. 在真实编辑器中观察 SQL/Java/JavaScript/Shell 等注入配色是否符合主题；重点用 `samples/` 检查 `${}`、`${x}`、`$!{x}`、`#{x}` 变量是否明显区别于正文，空占位符 `${}` 是否显示为错误色。变量 scope 已按 VS Code Light 主题计算为蓝色 `#0550AE`，仍需用户复验。
2. 属性名一致性：所有 XML 属性名（含 procedure 开放参数、多行开始标签、嵌套 `sql-dialect`）应统一为属性名红色 `#E50000`，不应出现正文色或橙色混用；scope 已自动化验证，最终渲染仍需目测。
3. 打开 `pom.xml`、Spring 配置、MyBatis Mapper：无 XProc4J scope、无语义补全/大纲/语义 token（已自动化）；确认原生片段建议出现时不会自动插入，并按需通过片段设置关闭。
4. 安装/卸载 Groovy、VTL、FreeMarker、Thymeleaf、SpEL 扩展，确认缺失时降级为普通文本，安装后嵌入高亮生效。
5. 与 Red Hat XML、Java 等扩展同时启用，确认语义 token 与属性补全无冲突。
6. 多行开始标签写法下的注入降级是否可接受，变量与属性是否仍高亮。
7. 「新建 Procedure 文件」交互：目录选择、id 校验、重名覆盖确认、取消流程、写入后打开（模板渲染与校验已有单元测试）。
8. 索引 watcher：新增/修改/删除/重命名 XML 后的补全刷新；未保存文档覆盖层；关闭文档恢复磁盘内容（索引逻辑有单元测试，真实 watcher 仍需人工）。
9. 配置开关补充检查 `index.enabled`：状态栏、重建索引命令与禁用后的补全降级；其余开关已由集成测试覆盖。
10. 大工作区性能：5,000 / 20,000 个 XML 的索引耗时、内存、补全延迟。
11. 嵌入块背景：多行 `sql-update` / `sql-query-object` / 嵌套 `sql-dialect` 应显示连续浅黄色整行背景；`lang-eval` / `lang-eval-java` / `lang-eval-ts` 等应显示连续浅绿色整行背景，起止标签行均包含在内；切换 Light/Dark 主题后正文仍可读；关闭 `xproc4j.blockBackground.enabled` 后两类背景立即消失；普通 XML 与非 procedure 文档不出现背景。
12. 属性值背景：所有 XML 属性值（`a="b"` 中的 `b`）显示比 `lang-eval*` 更浅的绿色，且不包含两侧引号；单/双引号、多行属性值、开放参数与未知属性均应生效；无值布尔属性与 `a=""` 不出现色块；关闭 `xproc4j.attributeValueBackground.enabled` 后立即消失，且不影响嵌入块背景。
13. lang-eval* 关键字高亮：`lang-eval` / `lang-eval-java` / `lang-eval-ts` 等正文中的 Java、JavaScript、SQL99 关键字应呈 dodgerblue（`#1E90FF`），与绿色背景和注入语法配色均能区分；`format`、`imported`、`classy`、`whileLoop` 等标识符不应被染色；Light/Dark 主题下颜色一致；关闭 `xproc4j.evalKeywordHighlight.enabled` 后立即恢复主题色，且不影响块背景与属性值背景。
14. 多后缀变量高亮：默认在 `xml`、`yaml`、`yml`、`java` 文件中高亮 `${x}`、`$!{x}`、`#{x}`、`#!{x}` 与 `$name`。确认 XML 仍以语义 token 呈现（procedure 根节点 + 已知标签/属性），YAML/Java 以装饰呈现（Light `#0550AE` / Dark `#9CDCFE`）；修改 `xproc4j.variableHighlight.extensions`（含 `.yml`、`*.java` 写法）后立即生效；移除 `xml` 只影响 XML 变量 token，refid 仍高亮；设为空数组后所有变量高亮关闭；主题切换后非 XML 变量颜色跟随刷新。已知限制：非 XML 为纯文本扫描，字符串/注释内的变量也会被染色。
15. lang-eval* 数值与字符串字面量：正文中的整数/小数（如 `0`、`1.25`）呈蓝色，字符串字面量（单/双引号、空串，含引号）整体呈绿色；Light 下 `#1565C0`/`#2E7D32`、Dark 下 `#90CAF9`/`#81C784`，与浅绿整行背景、dodgerblue 关键字均可区分；字符串内的数字与关键字不被二次染色；SQL 块不参与；Light/Dark 切换后颜色跟随刷新；关闭 `xproc4j.evalLiteralHighlight.enabled` 后立即恢复主题色，且不影响关键字与两类背景。

## 5. 缺陷与回归

本阶段发现并修复的关键缺陷：

| 编号 | 缺陷 | 回归用例 |
|---|---|---|
| I-05 | 扩展 ID 与清单不一致导致集成测试找不到扩展 | 集成测试「激活与命令注册」 |
| I-06 | 行首裸 `<` 后换行无法触发标签补全 | 单元测试「行首裸 < 后接换行仍进入标签补全」、集成「标签补全」 |
| I-07 | SQL 比较符 `<` 被误判为标签 | 单元测试「SQL 正文中的 < 比较符不触发标签补全」 |
| I-08 | 光标位于结束标签起点时变量补全被吞 | 单元测试「script-segment 正文中的占位符变量补全」、集成「变量补全」 |
| I-09 | 生成物含时间戳/绝对路径导致 `gen:check` 失败 | `npm run gen:check` |
| I-16 | vsce 因相对链接与缺失 repository 失败 | `npm run package` |
| I-17 | Windows 临时目录清理 EPERM | 集成测试可重复运行 |
| I-21 | `${}`/`#{}`/`$!{}` 变量在 VS Code Light 等主题下不可见，用户进一步要求与括号同色：scope `variable.other.xproc4j` 命中主题的 `variable.other` 正文色规则，`variable.parameter` 虽可见但为橙色 | 语法测试「scopes ${}, #{}, $!{} and #!{} variable forms」、单元测试「覆盖已知标签正文与非正文注入标签的属性变量」；主题计算确认 `support.variable.xproc4j` 为 `#0550AE` |
| I-23 | XML 属性名高亮不一致：非正文标签被注入窄规则先消费 `<tag`，宿主 XML 无法进入 `meta.tag`，属性名失去 scope 显示为正文色；procedure 开放参数使用 `variable.parameter` 显示橙色；SQL 正文中的 `<sql-dialect>` 被当作 SQL 比较符/标识符 | 语法测试「scopes attributes of non-body tags including multiline start tags」「keeps nested sql-dialect as XML inside a SQL body」；人工样例 `TEST_BASIC.xml` 复验 |

## 6. 结论

自动化门禁全部通过，核心功能（高亮规则、补全、跨文件 refid 导航、大纲/折叠、模板、索引）具备可交付质量。
VSIX 已在干净临时 profile 中安装并通过同一套集成测试，排除了“开发目录可用、打包后不可用”的风险。
门控与配置开关已补入自动化：POM/Spring/MyBatis 无 XProc4J scope 与语义候选；`completion.enabled`、`enable`、`symbols.enabled`、`folding.enabled`、`maxDocumentSizeKB`、`refid.enabled` 均已验证。
变量 scope 已从 `variable.other.xproc4j` 调整为 `support.variable.xproc4j`：前者在 VS Code Light 下被映射为正文色，后者解析为与括号/标点一致的蓝色 `#0550AE`；`${}`、`#{}`、`$!{}`、`#!{}`、短变量与空占位符均有语法/单元回归。
XML 属性名 scope 已统一：非正文标签改用覆盖整个开始标签的 `startTagRule`，属性名不再依赖宿主 XML 状态；procedure 开放参数与普通属性统一为 `entity.other.attribute-name.xproc4j`（VS Code Light 下红色 `#E50000`）；SQL 正文中的嵌套 `sql-dialect` 先于 `source.sql` 匹配并按 XML 标签着色。多行开始标签属性与嵌套 SQL 标签均有语法回归。
原生片段按 `xml` 作用域全局建议，POM 中可能出现 `procedure-call` 等片段候选；这是 FR-07 允许的行为，不会自动插入，已写入 README 与用户手册的已知限制。
多后缀变量高亮已合入：XML 继续使用语义 token，YAML/Java 等非 XML 文件使用装饰，避免与语言扩展的语义 token Provider 竞争；后缀归一化、短变量去重与路径边界均有单元回归，打包后集成测试仍为 7 项全通过。
第 4 节剩余人工检查项不影响代码交付，但属于发布前必须完成的体验与第三方兼容性验证；未完成前不应宣称“全平台/全扩展组合已验证”。
