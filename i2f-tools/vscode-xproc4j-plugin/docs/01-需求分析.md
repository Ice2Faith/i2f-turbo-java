## 1. 背景与目标

### 1.1 背景

`i2f-jdbc-procedure`（XProc4J，XML Procedure for Java）使用 XML 描述数据库存储过程式的业务流程。现有 `i2f-jdbc-procedure-idea-plugin` 为 IntelliJ IDEA 提供了 XML 节点语法高亮、语言注入、补全、引用跳转、实时模板等编辑能力。

团队当前的开发环境正在向 VS Code 及其兼容分支迁移，需要在 VS Code 中获得与 IDEA 插件核心编辑体验对齐的能力，降低编写 `procedure.xml` 的门槛，减少标签、属性、变量和 `refid` 的手写错误。

### 1.2 目标

1. 在 VS Code 中为根节点为 `procedure` 的 XML 文件提供 XProc4J 专用的 XML 语法高亮。
2. 将标签正文和属性值中的 SQL、Java、JavaScript 等语言，复用 VS Code 已有语法进行高亮。
3. 提供适合 XProc4J 的补全、`refid` 跳转、Snippets、新建文件模板和大纲能力。
4. 保持与现有 XML 语言扩展的兼容，不破坏普通 XML 文件的编辑体验。
5. 交付可离线安装的 VSIX、中文用户手册、开发指导手册和项目文档。

### 1.3 成功标准

- 打开一个典型的 `procedure.xml`，无需额外配置即可看到 XProc4J 标签/属性高亮、`$` 变量高亮、SQL/Java/JavaScript 注入高亮。
- 在 `procedure-call` 的 `refid` 上使用「转到定义」，可跨文件跳转到对应 `procedure` / `script-segment` 的 `id`。
- 输入属性名/属性值时，能获得枚举、`refid`、参数、变量等符合框架语义的补全。
- 输入 `<sql-query-list` 等前缀时，能触发对应 Snippets。
- 对 Maven POM、Spring XML、MyBatis Mapper 等普通 XML 文件，不产生可见的高亮污染、补全污染或性能回退。
- 在 5,000 个 XML 文件的工作区中，初次索引和日常补全达到第 7 节的性能目标。

## 3. 用户与使用场景

### 3.1 目标用户

- 使用 XProc4J 编写数据库存储过程、ETL、数据同步逻辑的后端开发人员。
- 已经熟悉 IDEA 插件，希望迁移到 VS Code 或 Cursor/Windsurf 的团队。
- 需要离线、内网环境开发，不能依赖在线服务的团队。

### 3.2 典型场景

1. **编写 SQL 节点**：在 `sql-query-list` 中编写 SQL，SQL 关键字、字符串、注释、`${}` 变量正确着色；输入 `$` 或 `${` 时获得变量补全。
2. **编写 Java 脚本节点**：在 `lang-eval-java` 中编写 Java 片段，复用 VS Code Java 语法高亮。
3. **调用子过程**：在 `procedure-call` 中输入 `refid`，获得工程内所有 procedure/script-segment 的 id 补全；点击跳转定义；输入参数名时获得目标过程的参数补全。
4. **编写动态 SQL**：在 `sql-query-list` 内嵌 `<if>`、`<where>`、`<foreach>` 等 MyBatis 风格标签，正文继续按 SQL 高亮，`test` 属性按表达式高亮。
5. **使用模板**：输入 `<sql-query-list`、`<lang-eval-java` 等前缀生成完整片段。
6. **新建文件**：通过命令创建带 DOCTYPE、`<procedure>` 骨架和作者信息的文件。
7. **浏览结构**：使用大纲/面包屑查看 procedure、script-segment 和各类节点的层级。

| VS Code Web（vscode.dev/github.dev） | 用户选择桌面版；Web 端无本地文件系统与索引能力 |
| Marketplace 上架 | 用户选择离线 VSIX + 兼容分支；上架物料后续可补 |
| 自定义配色主题 | 仅提供 scope；配色由用户主题决定，文档给出可选定制示例 |
| XML 格式化/重排 | 不重复实现；可继续使用 XML 扩展或编辑器格式化 |

## 6. 功能需求

### FR-01 procedure 文件识别与激活（P0）

**描述**

- 扩展在 XML 文档中识别根元素（忽略 XML 声明、DOCTYPE、注释、处理指令、空白）是否为 `procedure`。
- 文件语言保持为 `xml`，**不切换语言 ID**，以兼容现有 XML 扩展。
- 所有需要语义的能力（补全、跳转、索引、大纲、折叠）在运行时检查根元素；非 procedure 文件直接返回空结果，零副作用。
- 高亮通过 TextMate 注入语法实现；注入规则只匹配 XProc4J 已知标签名和已知属性名，避免污染普通 XML。

**规则**

- 根元素本地名必须为 `procedure`；命名空间不限制（当前框架不使用命名空间）。
- `script-segment` 可出现在 `procedure` 内部或独立文件中；独立文件不作为根节点识别，但会作为索引候选参与 `refid` 目标扫描（只要其父级存在 procedure 根）。
- 文件编码按 VS Code 文档内容处理，不额外读取磁盘。
- 未保存的文档以内存内容为准。

**验收**

- 打开 `procedure.xml`、Maven POM、Spring XML、MyBatis Mapper，只有前者启用补全/跳转/大纲。
- 普通 XML 中不出现 `${}`/`$var` 的 XProc4J 变量着色（已知标签之外的区域不受影响）。
- 根元素从 `procedure` 改为其他名称后，语义功能在下一次文档变化后失效。

### FR-02 XProc4J XML 结构语法高亮（P0）

**描述**

在 VS Code 内置 XML 语法之上，通过注入语法为 XProc4J 结构增加专用 scope：

1. **标签名分类**
   - 根/片段：`procedure`、`script-segment`、`script-include`
   - 流程控制：`lang-if`、`lang-choose`、`lang-when`、`lang-otherwise`、`lang-while`、`lang-do-while`、`lang-foreach`、`lang-fori`、`lang-break`、`lang-continue`、`lang-try`、`lang-catch`、`lang-finally`、`lang-retry`、`lang-throw`、`lang-return`、`lang-body`
   - SQL/数据处理：`sql-*`、`etl-*`、`sql-transactional`
   - 脚本/求值：`lang-eval*`、`lang-java-*`、`lang-invoke`
   - 调用：`procedure-call`、`function-call`、`java-call`
   - 日志/输出：`log-*`、`debugger`、`lang-printf`、`lang-println`
   - 并发/线程：`lang-async*`、`lang-synchronized`、`lang-lock`、`lang-latch*`、`lang-sleep`、`lang-thread-pool*`
   - IO/文件：`lang-file-*`、`lang-shell`
   - 上下文/事件：`context-*`、`event-*`、`lang-new-params`、`lang-listener`、`lang-ai`
   - 动态 SQL 子标签：`if`、`where`、`set`、`trim`、`foreach`、`choose`、`when`、`otherwise`、`bind`、`include`、`dialect`、`dialect-choose`、`dialect-when`、`dialect-otherwise`
2. **属性名高亮**
   - 已知属性使用 `entity.other.attribute-name.xproc4j.*`。
   - 带特性后缀的属性（如 `value.int`、`result.trim`、`value.eval-java`）整体识别。
   - 开放属性标签（`procedure`、`script-segment`、`procedure-call`、`function-call`、`script-include`、`lang-new-params`、`lang-println`、`lang-printf`、`lang-thread-pool-submit`、`event-send`、`event-publish`）不限定属性名，未识别属性保持 XML 默认 scope。
3. **属性值高亮**
   - 布尔值：`true` / `false`。
   - 枚举：`propagation`、`isolation`、`time-unit`、`jdbc-type`、`database`、`databases`、`datasource`、`datasources`、`result-type` 等。
   - 日期格式：`pattern`、`date-format`、`format`。
   - 数值：`.int`、`.long`、`.float`、`.double`、`.short`、`.byte`、`.char`、`radix`。
   - 类型/类名：`class`、`type`、`jdbc-type`、`result-type`、`package`、`rollback-for`、`no-rollback-for` 等。
   - 引用：`refid` 与索引中的 id 匹配时使用引用样式；不匹配时保持默认（不报错）。
4. **XML 基础结构**
   - 注释、CDATA、DOCTYPE、处理指令、实体引用沿用 VS Code XML 语法。
   - 自闭合标签、大小写、属性引号（单/双）正确处理。
5. **未知标签/属性**
   - 保持 VS Code XML 默认样式，不做诊断、不报错。
6. **主题兼容**
   - 只提供标准/自定义 scope，不强制颜色；在文档中给出可选 `editor.tokenColorCustomizations` 示例。
   - 在默认 Dark+/Light+ 主题下，不出现不可读或与背景冲突的颜色。
7. **嵌入块背景（2026-10-26 增补）**
   - SQL 正文区域显示浅黄色整行背景；`lang-eval*`（`lang-eval`、`lang-eval-java`、`lang-eval-ts` 等）显示浅绿色整行背景，便于按颜色识别嵌入块类型。
   - 起止标签所在行包含在色块内；背景只作用于 procedure 根节点，可通过 `xproc4j.blockBackground.enabled` 关闭。
   - 所有 XML 属性值（`a="b"` 中的 `b`，不含引号与等号）显示比 `lang-eval*` 更浅的绿色背景，可通过 `xproc4j.attributeValueBackground.enabled` 单独关闭；无值布尔属性与空值不显示。
   - 使用编辑器装饰实现，不依赖主题是否支持 token background。
8. **lang-eval* 关键字高亮（2026-10-26 增补）**
   - 对 `lang-eval*` 正文按词边界匹配 Java、JavaScript、SQL99 关键字与字面量（如 `for`、`while`、`if`、`else`、`continue`、`break`、`let`、`var`、`const`、`class`、`private`、`public`、`protected`、`select`、`drop`、`create`），统一显示为 dodgerblue（`#1E90FF`）。
   - 只标记关键字本身，不改变背景与 XML/注入语法；可通过 `xproc4j.evalKeywordHighlight.enabled` 单独关闭，与两类背景开关互不影响。
   - 颜色由编辑器装饰强制指定，保证 Light/Dark 主题下都呈 dodgerblue。
9. **多后缀变量高亮（2026-10-27 增补）**
   - 变量高亮默认覆盖 `xml`、`yaml`、`yml`、`java` 四类文件后缀，可通过 `xproc4j.variableHighlight.extensions` 增删；支持 `xml`、`.xml`、`*.xml` 写法，空数组表示关闭。
   - XML 仍要求 procedure 根节点，并只在已知标签/属性内匹配；yaml/yml/java 只做原始文本扫描，匹配 `${x}`、`$!{x}`、`#{x}`、`#!{x}` 与 `$x`，不要求 XProc 结构。
   - 非 XML 文件使用编辑器装饰着色，避免注册语义 token Provider 顶掉 yaml/java 扩展自身的语义 token；颜色随 Light/Dark 主题切换。
   - 仍遵守 `xproc4j.enable`、文档大小上限与不受支持的 scheme 限制；非 XML 为纯文本扫描，字符串与注释中的变量也会被着色，不做语法级排除。
10. **lang-eval* 数值与字符串字面量高亮（2026-10-27 增补）**
    - `lang-eval*` 正文中的数值字面量（`\d+(\.\d+)?`，整数或小数）显示为蓝色，字符串字面量（`'[^']*'` 或 `"[^"]*"`，含两侧引号）显示为绿色。
    - 颜色必须与现有视觉元素区分：蓝色与关键字 dodgerblue（`#1E90FF`）不同明度，绿色与 `lang-eval*` 整行浅绿背景、属性值浅绿背景不同明度；Light/Dark 主题分别选色保证可读。
    - 字符串字面量内部的关键字与数字不再按关键字/数值着色，保证字符串整体呈绿色；字符串内部优先作为保护区。
    - 使用编辑器装饰实现；可通过 `xproc4j.evalLiteralHighlight.enabled` 单独关闭，与关键字高亮、两类背景开关互不影响。

**验收**

- 对包含全部标签类别的 fixture，`Developer: Inspect Editor Tokens and Scopes` 能看到预期 scope。
- 标签名大小写和 `-` 分隔符匹配正确。
- 多行 SQL 块显示连续浅黄背景，`lang-eval*` 块显示连续浅绿背景，起止标签行与正文行颜色一致；关闭配置后背景立即消失。
- 属性值背景只染色引号内的值，不包含引号；空值与无值属性不出现色块；单/双引号与多行属性值均正确。
- `lang-eval*` 正文中的 Java/JavaScript/SQL99 关键字呈 dodgerblue，标识符（如 `format`、`imported`、`classy`）不被误染；关闭配置后关键字立即恢复主题色。
- 数值字面量（如 `0`、`1.25`）呈蓝色，字符串字面量（`'hello'`、`"world"`、空串）整体呈绿色且引号包含在内；字符串内的数字与关键字不被二次染色；SQL 块不参与；Light/Dark 主题下颜色均可读且与浅绿背景、dodgerblue 关键字区分；关闭 `xproc4j.evalLiteralHighlight.enabled` 后立即恢复主题色。
- 默认后缀下，`.yaml`、`.yml`、`.java` 与 procedure XML 中的变量均高亮；不在列表中的后缀不高亮；`variableHighlight.extensions=[]` 时全部关闭；XML 去掉 `xml` 后不再生成变量语义 token，但 refid 着色保留。
- 单引号/双引号属性、带 `>` 的属性值、CDATA 中的内容不导致跨行误匹配。
- Maven POM、Spring XML、MyBatis Mapper 的高亮与安装前一致（无 XProc4J scope 注入）。

- TextMate 语法不能根据配置动态改变注入目标；本期采用固定映射表。`_lang` 的未知值保持普通文本。

**验收**

- SQL 标签正文中 `SELECT`、字符串、数字、注释、`${}` 变量按 SQL/变量 scope 高亮。
- `lang-eval-java` 正文中 `public`、`String`、`return`、字符串、注释按 Java scope 高亮。

- `_lang="json"` 的正文按 JSON 高亮。

- SQL 正文中的 `<if test="${x}">` 结构与变量高亮正确，SQL 高亮不因嵌套标签而中断。

### FR-04 `$` / `#` 变量高亮（P0）

**描述**

- 识别以下形式：
  - `${name}`、`$!{name}`
  - `#{name}`、`#!{name}`
  - `$name`（短变量，`[a-zA-Z0-9_]+`）
- 作用域：**仅 XProc4J 已知标签的正文与属性值内**，包括 SQL/Java/JS 注入区域中的变量。
- scope：普通变量使用 `support.variable.xproc4j`（蓝色，与括号/标点一致）；空占位符（去空白后包含 `{}`）使用 `invalid.illegal.xproc4j`。
- 不修改文档内容，不提供诊断。
- 大文档保护：单文件 >2 MB 时仍由 TextMate 语法处理（语法本身逐行匹配，性能可接受）；扩展侧语义功能跳过。

**验收**

- `sql-update` 正文中的 `${V_TABLE}`、`#{STATUS}`、`$user`、`$!{empty}`、`#!{x}` 均着色。
- `procedure` 根标签之外的普通 XML 文本不出现该着色。
- 空 `${}` / `#{}` 使用错误色 scope。
- `<lang-eval-tinyscript>` 正文中的 `${x}` 仍着色（变量高亮属于 XML 层，不属于 DSL 层）。

- 值补全支持 `,`、`;`、`|`、`/` 分隔的多值场景：只替换当前段，不覆盖已输入的其他段。

**验收**

- 在不同标签、属性、属性值位置触发补全，结果符合表中定义。
- `procedure-call` 的 `refid` 为空时不显示参数补全；设置 `refid` 后显示目标参数。
- 输入 `${` 后补全当前文件变量，并自动补 `}`（若未输入）。
- Maven POM 中不出现 XProc4J **语义**补全项；原生片段建议由 FR-07 单独约定，可通过 VS Code 片段设置关闭。
- 补全响应时间满足第 7 节目标。

### FR-06 `refid` 定义跳转与 `id` 查找引用（P1）

**描述**

- **定义跳转（DefinitionProvider）**
  - 位置：任意标签的 `refid` 属性值（至少覆盖 `procedure-call`、`function-call`、`script-include`、`sql-call`、`include`）。
  - 目标：工程索引中所有 `procedure` / `script-segment` 的 `id` 定义（含嵌套 `script-segment`）。
  - 多个同名 id：返回多个 `Location`，由 VS Code 显示选择器。
  - 索引未命中：返回空，不弹错误提示。
  - 跳转范围为整个属性值（不含引号）。
- **查找引用（ReferenceProvider）**
  - 位置：`procedure` / `script-segment` 的 `id` 属性值。
  - 结果：所有引用该 id 的 `refid` 属性值位置，跨文件。
  - 包含声明本身与否遵循 VS Code 默认（`context.includeDeclaration`）。
- **索引**
  - 扫描工作区内的 `*.xml`，按 `xproc4j.projectScan.include/exclude` 配置过滤。
  - 预过滤：文件文本包含 `<procedure` 或 `<script-segment` 才解析。
  - 解析容错；无法解析的文件跳过并记录日志，不阻塞其他文件。
  - 打开中的文档使用内存内容覆盖磁盘内容。
  - 文件创建/修改/删除触发增量更新，防抖 300 ms。
  - 提供「XProc4J: 重建工程索引」命令。
- **同名 id 策略**
  - 全部保留；跳转时多目标选择；补全时去重后显示（detail 标注文件相对路径）。
  - 不提供重复 id 诊断（本期无诊断）。

**验收**

- 在 A.xml 的 `procedure-call refid="B"` 上执行「转到定义」，跳转到 B.xml 中 `id="B"` 的 `procedure` 或 `script-segment`。
- 在 B.xml 的 `id="B"` 上执行「查找所有引用」，列出 A.xml 中的 `refid`。
- 修改 B.xml 的 id 后，索引在 1 秒内更新，旧 refid 不再跳转。
- 未保存的新文件中定义的 id 可被同文件 refid 跳转。
- 20,000 个 XML 文件时索引不崩溃，超过上限时按策略降级并提示。

### FR-07 Snippets（P1）

**描述**

- 将参考插件 `XProc4j.xml` 中的 **90 个 Live Template** 迁移为 VS Code Snippets。
- 触发前缀保持 IDEA 的 `<tag` 形式（如 `<sql-query-list`、`<lang-eval-java`、`<procedure`）。
- 作用域：`xml`。
- 变量转换：
  - IDEA `$VAR$` → VS Code `${1:default}` 占位符；
  - `$END$` → `$0`；
  - `fileName()` → `TM_FILENAME`；
  - `lineNumber()` → `TM_LINE_NUMBER`；
  - 默认值保留；无默认值的变量生成可跳转占位符。
- 如 VS Code 原生 Snippet 对 `<` 前缀不触发（需在实现早期验证），改由 `CompletionItemProvider` 的 `triggerCharacters: ['<']` 提供同等条目，用户输入 `<` 后仍能看到 `<tag` 前缀的建议。此改动不改变用户可见的触发方式。
- 对自研 DSL 的模板（`<lang-eval-tinyscript`、`<lang-eval-ts`、`<lang-eval-funic`）保留 XML 骨架，但正文不高亮、不补全。
- 对参考模板中的拼写问题（如 `$DATASURCE$`、`$FEATUERE$`）以功能等价为准修正占位符名称。
- Snippets 不包含格式化/重排逻辑。

**验收**

- 90 个模板均可通过前缀触发，生成的 XML 结构完整、可折叠、可继续补全。
- `<procedure` 生成的骨架包含 DOCTYPE、`id`、作者/日期注释。
- `<sql-query-list` 等 SQL 模板生成后，正文按 SQL 高亮。
- 在 Maven POM 中输入 `<` 时，如出现候选，可通过 VS Code 的 Snippet 管理关闭；不得自动插入内容。

### FR-08 新建 XProc4J procedure 文件（P1）

**描述**

### FR-09 大纲、面包屑与折叠（P1）

**描述**

- **DocumentSymbolProvider**
  - 层级：`procedure` → `script-segment` / 节点 → 子节点。
  - 名称：`标签名` + 关键属性（`id`、`refid`、`result`、`name`、`test`、`datasource` 等），如 `sql-query-list result=userList`。
  - `range` 覆盖整个元素（含结束标签），`selectionRange` 覆盖标签名。
  - 自闭合标签的 `range` 覆盖整个标签。
  - 未知标签也纳入大纲（以标签名显示），保证结构完整。
  - 注释、文本、CDATA 不纳入。
- **折叠**
  - 为元素范围提供 `FoldingRange`，支持多行元素折叠；与 XML 扩展的折叠不冲突（VS Code 会合并）。
  - 单行自闭合标签不产生折叠。
- **面包屑**
  - 由 DocumentSymbol 自动提供。

**验收**

- 大纲层级与 XML 结构一致，点击可跳转。
- 折叠/展开正常，不破坏 XML 扩展的折叠。
- 10,000 行文件的大纲生成时间满足第 7 节目标。

### FR-10 工程索引与刷新（P1）

**描述**

- 索引内容：文件 URI、根/嵌套 procedure 与 script-segment 的 id、参数名及 feature、标签范围（用于跳转定位）、文件 mtime/版本。
- 生命周期：
  - 首次需要补全/跳转/大纲时惰性构建；
  - 监听 `workspace.createFileSystemWatcher`，增量更新；
  - 打开文档变化时更新内存覆盖；
  - 命令「XProc4J: 重建工程索引」强制重建；
  - 输出通道 `XProc4J` 记录扫描文件数、耗时、跳过原因、错误。
- 配置：
  - `xproc4j.projectScan.include`，默认 `["**/*.xml"]`；
  - `xproc4j.projectScan.exclude`，默认 `["**/node_modules/**","**/.git/**","**/target/**","**/build/**","**/out/**","**/dist/**","**/logs/**"]`；
  - `xproc4j.projectScan.maxFiles`，默认 20000；
  - `xproc4j.index.enabled`，默认 true。
- 降级：
  - 超过 `maxFiles`：停止继续扫描，保留已索引部分，输出警告，补全/跳转仍可用但不完整；
  - 单文件解析失败：跳过并记录；
  - 工作区无 XML：不启动扫描。

**验收**

- 首次打开大工作区，UI 不卡顿（扫描在异步任务中执行，分批 yield）。
- 新增/删除/重命名 procedure 文件后，refid 补全与跳转在 1 秒内反映变化。

- 错误信息写入输出通道，包含文件、行号、原因、建议。

### 7.5 可维护性

- DTD 只用于构建期生成，不随扩展在运行期解析。

### 8.2 元数据目录结构（建议）

- `metadata/tags.json`：标签名、分类、允许子标签、是否开放属性、简介。
- `metadata/attributes.json`：属性名、所属标签、类型（boolean/enum/string/expression/class/refid）、枚举值、是否支持 feature 后缀。
- `metadata/features.json`：feature 列表及说明。
- `metadata/injections.json`：标签/属性 → 语言 scope 映射。
- `metadata/keywords.json`：SQL 关键字、内置变量、日期模板、方法名等。
- `syntaxes/xproc4j.injection.tmLanguage.json`：由脚本生成或手写并引用生成片段。
- `snippets/xproc4j.json`：由 IDEA 模板转换。

### 8.3 索引数据模型

```ts
interface ProcedureIndexEntry {
  id: string;
  kind: 'procedure' | 'script-segment';
  uri: string;
  idRange: Range;
  tagRange: Range;
  parentId?: string;
  params: Array<{ name: string; features: string[] }>;
}

interface ProjectIndex {
  version: number;
  entries: ProcedureIndexEntry[];
  refs: Array<{ refid: string; uri: string; range: Range }>;
}
```

- `version` 用于缓存失效。
- `refs` 可在查询时从文档扫描，也可持久化；实现阶段决定。
- 所有 Range 使用 VS Code 的 0-based 行列。

## 9. 可行性与技术限制

### 9.1 结论

本期 P0/P1 范围在 VS Code 桌面版上**技术可行**，但「语言注入」只能达到语法高亮级别，无法达到 IDEA 的语义注入级别。需要在文档和验收中明确边界。

### 9.2 关键可行性判断

| 能力 | 可行性 | 说明 |
|---|---|---|
| XML 标签/属性/变量高亮 | 高 | TextMate 注入语法 + 内置 XML 语法 |
| SQL/Java/JS/JSON 等高亮 | 高 | 通过 `include` 复用内置 scope |
| 动态 SQL 嵌套高亮 | 中高 | 需要递归 begin/end 语法，需充分测试 |
| 第三方语言高亮 | 中 | 依赖用户安装扩展及 scope 名称稳定 |
| XML 补全 | 高 | CompletionItemProvider + 自建上下文判定 |
| refid 跳转 | 高 | 工作区扫描 + 索引 + Definition/ReferenceProvider |
| Snippets | 高 | 静态 JSON；`<` 前缀触发需早期验证 |
| 大纲/折叠 | 高 | DocumentSymbol/FoldingRange Provider |
| Java/SQL 语义补全 | 低 | 需虚拟文档 + 语言客户端，本期不做 |
| 标签→Java 类跳转 | 中 | 用户确认不做 |
| 诊断 | 中 | 用户确认不做 |

### 9.3 需要早期验证的技术点（实现阶段第 1 周）

1. **TextMate 注入到 `text.xml`**：注入语法是否能稳定覆盖标签正文与属性值，是否与内置 XML 语法冲突。
2. **递归 SQL 注入**：`sql-query-list` 内嵌 `<if>`/`<where>` 时，SQL scope 是否连续，嵌套层级是否正确。
3. **`<` 前缀 Snippets**：VS Code 原生 Snippet 是否在输入 `<` 后触发；若不触发，CompletionItemProvider 方案是否体验一致。
4. **第三方 scope 探测**：未安装语法时 `include` 是否静默退化；安装后是否即时生效。
5. **XML 解析器选型**：`@xml-tools/parser` 或自研扫描器在未闭合标签、属性内 `>`、CDATA 下的容错与位置准确性。
6. **大工作区扫描**：`workspace.findFiles` + 分批读取在 5,000/20,000 文件下的耗时与内存。
7. **DTD 元数据提取**：自定义扫描器能否稳定处理缺类型声明、重复 ATTLIST 与 feature 后缀，并与 `procedure.xml`、常量类对齐。

| 风险 | 影响 | 对策 |

## 10. 验收标准

### 10.1 功能验收

1. **高亮**：以 `procedure.xml` 为基线拆分的 fixture 覆盖全部标签类别、属性类型、变量形式；scope 断言通过；普通 XML 无污染。
2. **注入**：SQL、Java、JavaScript、JSON、Shell、XML、YAML、CSS、Markdown 在对应标签/属性中按预期高亮；第三方语言未安装时静默退化。
3. **变量**：`${}`、`$!{}`、`#{}`、`#!{}`、`$var` 在已知标签内高亮；空占位符使用错误色 scope。
4. **补全**：C-01~C-20 逐项验收；响应时间达标；无普通 XML 污染。
5. **跳转**：跨文件 refid 定义/引用；同名多目标选择；未命中无错误提示。
6. **Snippets**：90 个模板全部可触发；生成结构正确；`<procedure` 模板包含 DOCTYPE。
