# 用户使用手册

> 适用版本：XProc4J for VS Code 0.1.0
> 适用平台：桌面版 VS Code 1.90.0 及以上（Windows / macOS / Linux）
> 文档语言：中文

## 1. 软件是什么

XProc4J 是一个 VS Code 扩展，为 `i2f-turbo-java` 的 XML 存储过程（procedure）提供编辑支持。
它只处理**根节点为 `<procedure>`** 的 XML 文件，普通 XML 文件不会被补全、索引或诊断打扰。

主要能力：

- XProc4J 标签、属性、feature 与变量高亮
- SQL、Java、JavaScript、JSON、YAML、Shell 等正文语言注入
- 标签、属性、feature、枚举、refid、变量与 SQL 关键字补全
- 跨文件 refid 定义跳转与引用查找
- 大纲、面包屑、折叠
- 90 个代码片段
- 新建 procedure 文件

## 2. 安装前准备

1. 安装 VS Code 1.90.0 或更高版本。
2. 确认可以访问本地文件系统（虚拟工作区不支持完整的跨文件索引）。
3. 建议用「打开文件夹」方式打开包含 procedure XML 的工作区；单文件窗口仍可使用补全与高亮，但无法建立跨文件索引。

## 3. 安装与卸载

### 3.1 从 VSIX 安装

图形界面：

1. 打开扩展视图。
2. 点击右上角 `...`，选择「从 VSIX 安装...」。
3. 选择 `vscode-xproc4j-0.1.0.vsix`。
4. 安装完成后重新加载窗口。

命令行：

```bash
code --install-extension vscode-xproc4j-0.1.0.vsix
```

安装后扩展标识为 `ice2faith.xproc4j`，显示名为 `XProc4J`。

### 3.2 卸载

在扩展视图中搜索 `XProc4J`，选择「卸载」并重新加载窗口；或执行：

```bash
code --uninstall-extension ice2faith.xproc4j
```

卸载不会修改工作区中的 XML 文件。

## 4. 第一次使用

1. 打开包含 procedure XML 的文件夹。
2. 打开一个根节点为 `<procedure>` 的 XML 文件。
3. 输入以下内容验证：

```xml
<procedure id="demo">
    <sql-update datasource="main">
        select * from sys_user where id = ${id}
    </sql-update>
</procedure>
```

预期结果：

- `<procedure>`、`<sql-update>` 显示 XProc4J 标签配色。
- `select`、`from`、`where` 按 SQL 关键字着色。
- `${id}` 显示为变量。
- 在 `<sql-update ` 后输入空格，出现属性候选。
- 在 `refid="` 后出现工作区 id 候选（索引就绪后）。

如果没有任何效果，先检查第 8 节「常见问题」。

## 5. 功能操作

### 5.1 语法高亮与语言注入

- 标签名、属性名、feature 后缀使用独立 scope 着色。
- 正文按标签映射注入语言：

| 标签 | 注入语言 |
|---|---|
| `sql-query-list`、`sql-query-row`、`sql-query-object`、`sql-query-columns`、`sql-update`、`sql-dialect`、`sql-script` | SQL |
| `lang-eval-java`、`lang-java-import`、`lang-java-member`、`lang-java-body` | Java |
| `lang-eval-javascript`、`lang-eval-js` | JavaScript |
| `lang-shell` | Shell |
| `lang-string`、`lang-render` | 根据 `_lang` 属性切换；未指定时仅变量高亮 |

`lang-string` / `lang-render` 的 `_lang` 支持：`sql`、`java`、`javascript`/`js`、`json`、`xml`、`yaml`、`shell`/`bash`、`css`/`sass`、`markdown`/`md`、`typescript`、`regex`、`groovy`、`vtl`/`velocity`、`freemarker`、`thymeleaf`、`spel`、`el`/`expr`。
其中 Groovy、VTL、FreeMarker、Thymeleaf、SpEL 需要本机安装对应语法扩展；未安装时按普通文本显示。

SQL 正文（`sql-query-*`、`sql-update`、`sql-script`、`sql-dialect`）会额外显示浅黄色整行背景；以 `lang-eval` 开头的标签（如 `lang-eval`、`lang-eval-java`、`lang-eval-ts`）显示浅绿色整行背景。起止标签所在行也包含在内，便于快速识别嵌入块类型与边界。该背景由 `xproc4j.blockBackground.enabled` 控制（默认开启）；其他注入语言暂不添加背景色。

所有 XML 属性值（`a="b"` 中的 `b`，不含引号）会显示更浅的绿色背景，便于快速定位参数值。属性值背景由 `xproc4j.attributeValueBackground.enabled` 单独控制（默认开启），与嵌入块背景互不影响；无值布尔属性与空值不显示背景。

`lang-eval*` 正文中的 Java、JavaScript 与 SQL99 关键字（如 `for`、`while`、`if`、`else`、`continue`、`break`、`let`、`var`、`const`、`class`、`private`、`public`、`protected`、`select`、`drop`、`create`）会显示为 dodgerblue（`#1E90FF`），便于快速区分语句结构。该效果由 `xproc4j.evalKeywordHighlight.enabled` 单独控制（默认开启），不影响两类背景；匹配按词边界与大小写不敏感执行，注释中的关键字也会被着色，字符串内部的关键字交给字符串装饰统一着色。关闭后关键字立即恢复主题原色。

同一正文中的数值字面量（整数或小数，如 `0`、`1.25`）会显示为蓝色，字符串字面量（单引号或双引号包裹、含引号与空串）显示为绿色；Light 主题下为 `#1565C0`/`#2E7D32`，Dark 主题下为 `#90CAF9`/`#81C784`，与浅绿整行背景和 dodgerblue 关键字保持区分。该效果由 `xproc4j.evalLiteralHighlight.enabled` 单独控制（默认开启）。字符串按 `'[^']*'` / `"[^"]*"` 原始正则匹配，不解析转义，未闭合引号会跨行吞到下一个同型引号；注释中的数字与字符串也会被着色。

变量高亮默认覆盖 `xml`、`yaml`、`yml`、`java` 四种文件后缀，识别 `${name}`、`$!{name}`、`#{name}`、`#!{name}` 与短变量 `$name`。XML 仍要求根节点为 `<procedure>`，且只处理已知标签/属性；YAML/Java 等非 XML 文件按纯文本扫描。XML 变量跟随主题的语义 token 颜色，非 XML 变量使用装饰颜色（Light `#0550AE`、Dark `#9CDCFE`）。后缀列表可通过 `xproc4j.variableHighlight.extensions` 修改，支持 `xml`、`.xml`、`*.xml` 三种写法；设置为空数组可关闭全部变量高亮。非 XML 为纯文本扫描，字符串与注释中的变量也会被着色，这是已知限制。

### 5.2 补全

在 procedure 文件内：

| 输入位置 | 候选 |
|---|---|
| `<` 之后 | 标签名（111 个标签 + 14 个动态 SQL 标签） |
| 标签内空格后 | 属性名；已出现属性自动排除 |
| 属性名后输入 `.` | feature 后缀，如 `timeout.int` |
| 属性值内 | 枚举、布尔、时间单位、JDBC 类型、方法、数据库、数据源、结果类型等 |
| `refid="` 内 | 工作区中已索引的 id |
| 调用目标属性内 | 目标 procedure 的参数名与 feature |
| 正文 | 当前文件变量、42 个内置变量、SQL 关键字 |
| 注释/CDATA 内 | 不补全 |

变量形式：

- `${name}`、`$!{name}`、`#{name}`、`#!{name}`
- 短变量 `$name`

### 5.3 代码片段

输入 `<` 开头的片段前缀（例如 `<sql-update`），在建议列表中选择带片段图标的项，按 Tab 展开。
片段前缀保持上游 IntelliJ Live Template 的 `<tag` 风格，共 90 个。

### 5.4 导航

- **转到定义**：在 `refid="..."` 的值上按 F12 或右键「转到定义」，跳到同文件或跨文件的 `id` 定义。
- **查找所有引用**：在 `id="..."` 的值上按 Shift+F12，列出工作区内所有调用。
- **大纲/面包屑**：在资源管理器的大纲视图查看 procedure、script-segment 与语言节点。
- **折叠**：点击行号旁折叠箭头折叠元素正文。

跨文件导航依赖工程索引；索引未就绪时最多等待约 400 ms，超时先返回本地结果。

### 5.5 新建 Procedure 文件

方式一：在资源管理器中右键目标文件夹，选择「XProc4J: 新建 Procedure 文件」。
方式二：命令面板执行 `XProc4J: 新建 Procedure 文件`。

流程：

1. 选择目标目录（右键时自动带入）。
2. 输入 procedure id。
3. 输入文件名；未写扩展名时自动补 `.xml`。
4. 若文件已存在，弹出覆盖确认。
5. 生成并打开文件。

生成模板包含 XML 声明、`procedure.dtd` DOCTYPE、`id`、作者与日期时间注释。
作者取自操作系统当前用户；日期时间取自本机时区。

### 5.6 工程索引

默认在需要时自动构建，也可手动重建。

- 包含：`xproc4j.projectScan.include`，默认 `["**/*.xml"]`。
- 排除：`xproc4j.projectScan.exclude`，默认常见构建目录。
- 上限：`xproc4j.projectScan.maxFiles`，默认 20000。
- 只索引根节点为 procedure 的文件。
- 跳过二进制、超大（`xproc4j.maxDocumentSizeKB`）文件。
- 未保存的编辑器内容优先于磁盘内容。
- 文件新增/修改/删除/重命名会自动增量更新，防抖 300 ms。

手动重建：命令面板执行「XProc4J: 重建工程索引」。完成后通知会显示文件数、id 数与耗时；达到上限时会提示结果不完整。

## 6. 配置项

在「设置」中搜索 `xproc4j`。

| 配置 | 默认 | 说明 |
|---|---|---|
| `xproc4j.enable` | `true` | 语义功能总开关；关闭后注入语法仍生效 |
| `xproc4j.index.enabled` | `true` | 工程索引开关 |
| `xproc4j.projectScan.include` | `["**/*.xml"]` | 索引包含规则 |
| `xproc4j.projectScan.exclude` | 常见构建目录 | 索引排除规则 |
| `xproc4j.projectScan.maxFiles` | `20000` | 最大索引文件数（1~100000） |
| `xproc4j.completion.enabled` | `true` | 补全开关 |
| `xproc4j.completion.sqlKeywords` | `true` | SQL 关键字补全 |
| `xproc4j.completion.builtinVariables` | `true` | 内置变量补全 |
| `xproc4j.refid.enabled` | `true` | refid 导航与 refid 语义着色 |
| `xproc4j.symbols.enabled` | `true` | 大纲与面包屑 |
| `xproc4j.folding.enabled` | `true` | 折叠 |
| `xproc4j.blockBackground.enabled` | `true` | SQL 浅黄色、`lang-eval*` 浅绿色整行背景 |
| `xproc4j.attributeValueBackground.enabled` | `true` | XML 属性值的更浅绿色背景（不含引号） |
| `xproc4j.evalKeywordHighlight.enabled` | `true` | `lang-eval*` 正文关键字的 dodgerblue 前景色 |
| `xproc4j.evalLiteralHighlight.enabled` | `true` | `lang-eval*` 正文数值蓝色、字符串绿色的前景色 |
| `xproc4j.variableHighlight.extensions` | `["xml","yaml","yml","java"]` | 启用变量高亮的文件后缀；支持 `xml`/`.xml`/`*.xml`；空数组关闭 |
| `xproc4j.maxDocumentSizeKB` | `2048` | 超过大小跳过语义分析 |
| `xproc4j.trace.server` | `off` | 预留项，不产生 LSP 日志 |

修改索引相关配置后会自动重建（300 ms 防抖）。修改 `enable` 或文档大小上限会清理缓存并刷新语义 token；修改 `blockBackground.enabled`、`attributeValueBackground.enabled`、`evalKeywordHighlight.enabled` 或 `evalLiteralHighlight.enabled` 会立即重绘对应装饰；修改 `variableHighlight.extensions` 会刷新 XML 变量 token 并重绘所有可见的非 XML 变量装饰。

## 7. 命令与输出

| 命令 | 用途 |
|---|---|
| `XProc4J: 新建 Procedure 文件` | 创建 procedure XML |
| `XProc4J: 重建工程索引` | 手动刷新索引 |
| `XProc4J: 显示输出` | 查看激活、索引与错误信息 |

输出通道只记录数量、耗时与错误类型，不记录文档内容、属性值、SQL 文本或凭据。

## 8. 常见问题

### 8.1 打开 XML 没有任何高亮

- 确认窗口右下角语言模式为 `XML`。
- 确认文件根节点是 `<procedure>`；本扩展只处理该根节点。
- 检查 `xproc4j.enable` 是否为 `true`。
- 确认扩展已激活：执行「XProc4J: 显示输出」查看激活日志。

### 8.2 有高亮但没有补全

- 确认光标在开始标签或正文中，而不是注释/CDATA/结束标签内部。
- 检查 `xproc4j.completion.enabled`。
- 文件超过 `xproc4j.maxDocumentSizeKB` 时语义功能会关闭。
- 尝试按 `Ctrl+Space` 手动触发（部分输入法/平台不会自动触发空格补全）。

### 8.3 refid 没有跨文件候选或无法跳转

- 确认已用「打开文件夹」打开工作区。
- 检查 `xproc4j.index.enabled` 与 `xproc4j.refid.enabled`。
- 执行「XProc4J: 重建工程索引」，查看通知与输出。
- 目标文件必须是根节点 procedure，且未被 include/exclude 规则排除。
- 文件数超过 `maxFiles` 时结果可能不完整，通知会提示。

### 8.4 SQL/Java 正文没有着色

- SQL/Java 属于 VS Code 内置语法，正常应生效。
- 如果正文跨多行开始标签，注入可能降级；变量仍由语义 token 显示。
- 关闭 `xproc4j.enable` 只会关闭语义功能，不影响注入；若注入也失效，检查扩展是否被禁用或与其他 XML 语法扩展冲突。

### 8.5 Groovy/VTL/FreeMarker/Thymeleaf/SpEL 没有着色

这些语言不在 VS Code 内置范围，需要安装对应语法扩展。未安装时按普通文本显示，这是预期降级。

### 8.6 新建文件失败

- 检查目标目录写权限。
- 确认没有同名文件被其他程序占用。
- 查看错误弹窗与「XProc4J: 显示输出」中的详细信息。

### 8.7 大项目变慢

- 缩小 `xproc4j.projectScan.include` 范围。
- 增加 `xproc4j.projectScan.exclude` 排除目录。
- 降低 `xproc4j.projectScan.maxFiles`。
- 降低 `xproc4j.maxDocumentSizeKB`，让超大文件跳过语义分析。
- 如不需要跨文件导航，可关闭 `xproc4j.index.enabled`。

### 8.8 与 Red Hat XML 等扩展同时使用

本扩展不注册 XML 校验诊断，不会主动与校验扩展冲突。若出现补全候选重复或颜色异常，可分别禁用扩展定位；XML 变量/refid 使用语义 token，主题可能覆盖颜色，可在 `editor.semanticTokenColorCustomizations` 中调整。非 XML 变量使用本扩展装饰，不注册语义 token Provider，因此不会压掉 YAML/Java 扩展自带的语义高亮。

### 8.9 YAML/Java 中的变量没有高亮

- 检查 `xproc4j.variableHighlight.extensions` 是否包含对应后缀；默认是 `["xml","yaml","yml","java"]`。
- 后缀支持 `yaml`、`.yaml`、`*.yaml`；列表为空时所有变量高亮关闭。
- 确认 `xproc4j.enable` 为 `true`，且文件未超过 `xproc4j.maxDocumentSizeKB`。
- 非 XML 变量按纯文本扫描，字符串/注释中的变量也会显示；若颜色与主题不协调，可切换主题复验（Light 使用 `#0550AE`，Dark 使用 `#9CDCFE`）。

## 9. 已知限制

- 不提供 XML/DTD 校验与诊断。
- 不实现 TinyScript、Funic、Funvi、OGNL 的语法与补全。
- 不支持标签到 Java 类的跳转。
- 第三方语言注入取决于本机已安装的语法扩展及其 scope 名。
- 90 个原生代码片段的作用域是 `xml`，在 POM/Spring/MyBatis 等普通 XML 的 `<` 建议中也可能出现；不会自动插入，可通过 VS Code 的片段设置关闭。
- 多行开始标签可能降低注入覆盖率。
- 补全从光标向前最多回溯 4096 个字符；超长开始标签可能无法定位补全上下文。
- 虚拟工作区可能无法建立完整索引。
- 工程索引是内存快照，不持久化；窗口重启后按需重建。
- 非 XML 文件的变量高亮是纯文本扫描，字符串、注释与文档无关文本中的 `${...}`、`#{...}`、`$name` 也会被着色；不支持语法级排除。
- `lang-eval*` 关键字/数值/字符串按正则语义扫描，注释中的匹配也会着色；字符串字面量按 `'[^']*'` / `"[^"]*"` 匹配，不解析转义，未闭合引号会跨行吞到下一个同型引号。

## 10. 隐私与安全

- 扩展不联网，不执行 XML 内容。
- 索引只读取工作区文件；写操作仅发生在用户显式执行「新建 Procedure 文件」时。
- 日志不包含文档正文、属性值、变量值、SQL 文本或凭据。
- 工作区信任（Workspace Trust）不影响本扩展的核心功能；扩展声明支持不受信任工作区。

## 11. 获取帮助

1. 执行「XProc4J: 显示输出」，记录报错类型与时间。
2. 确认 VS Code 版本、扩展版本、操作系统。
3. 提供最小复现 XML（删除业务字段与敏感信息后）。
4. 在项目仓库提交 issue 时附上上述信息。
