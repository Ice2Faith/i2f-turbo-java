# 开发指导手册

> 适用版本：XProc4J for VS Code 0.1.0
> 面向读者：需要继续开发、维护或审计本扩展的工程师。
> 配套文档：`docs/03-概要设计.md`、`docs/04-详细设计.md`、`docs/05-测试报告.md`、`docs/06-问题与经验.md`。

## 1. 开发环境

| 工具 | 版本要求 |
|---|---|
| Node.js | 20 LTS 或更高（当前在 Node 24 验证） |
| npm | 随 Node 安装 |
| VS Code | 1.90.0 或更高（当前在 1.113.0 验证） |
| TypeScript | 随 devDependencies 安装（5.5+） |

初始化：

```bash
npm install
npm run gen
npm run check
```

`npm run check` 依次执行：类型检查、ESLint、单元测试、语法测试、生成物一致性校验。
首次克隆没有 `metadata/`、`syntaxes/`、`snippets/`、`src/generated/` 时，必须先执行 `npm run gen`。

## 2. 快速运行与调试

1. 执行 `npm run build`（或 `npm run watch` 持续构建）。
2. 按 F5 使用 `.vscode/launch.json` 的「运行 XProc4J 扩展」，会以 `test/fixtures/workspace` 打开扩展宿主。
3. 在扩展宿主中打开 `a.xml` 或新建 procedure XML 验证。
4. 修改源码后重新构建并「Reload Window」；使用 `watch` 时只需重载窗口。

调试提示：

- 扩展代码中的 `console` 不会显示在普通终端；使用「帮助 > 切换开发人员工具」查看 Extension Host 控制台。
- 业务日志写入「XProc4J」输出通道，不记录文档内容。
- 激活失败时先检查 `package.json` 的 `main`、`activationEvents` 与扩展 ID。

## 3. 入口与启动链路

```
src/extension.ts
  └─ activate(context)
       └─ src/core/activation.ts::activateExtension()
            ├─ Logger / StatusBar
            ├─ readConfig()            配置快照
            ├─ DocumentModelCache      文档模型缓存
            ├─ DocumentGate            XML/根节点/大小/开关门控
            ├─ IndexService           索引生命周期、watcher、覆盖层
            ├─ XProcSemanticTokensProvider
            ├─ 补全 / 定义 / 引用 / 大纲 / 折叠 Provider
            ├─ 文档与配置监听器
            └─ 命令注册
```

所有资源都挂到 `context.subscriptions`；`deactivate` 不需要额外清理。

## 4. 分层与模块职责

| 目录 | 职责 | 约束 |
|---|---|---|
| `src/domain` | 扫描器、文档模型、补全上下文/装配、索引数据与查询、导航、符号、折叠、模板、变量与 token 构建 | **禁止 import `vscode`**；纯函数/纯数据，便于单测 |
| `src/adapters` | VS Code Provider、命令、文档门控、类型转换 | 只做协议适配，不堆业务算法 |
| `src/infrastructure` | 索引服务、glob、文件监听、读盘 | 允许依赖 VS Code API |
| `src/core` | 激活、配置读取、日志、状态栏、系统信息 | 装配与运行期基础设施 |
| `src/generated` | 构建期生成的元数据与模板 | 禁止手改，变更走生成器 |
| `tools` | 元数据/语法/片段/模块生成器与 vendored 源 | 入口脚本只编排，逻辑放 `tools/lib/` |

关键文件：

| 文件 | 说明 |
|---|---|
| `src/domain/xml/scanner.ts` | 容错 XML 扫描，元素、属性、保护区间、实体解码 |
| `src/domain/xml/document-model.ts` | 行索引、元素模型、变量名、缓存 |
| `src/domain/completion/context.ts` | 补全上下文判定（标签/属性/值/正文） |
| `src/domain/completion/orchestrator.ts` | 候选装配、去重、取消与错误隔离、1000 上限 |
| `src/domain/index/index-scan.ts` | 单文件轻量提取（id、参数、refid、range） |
| `src/domain/index/query.ts` | 基础快照 + 覆盖层查询 |
| `src/domain/semantics/block-background.ts` | SQL / `lang-eval*` 正文范围计算、类型标注与同类型嵌套合并（纯函数） |
| `src/domain/semantics/attribute-value-background.ts` | XML 属性值范围提取（直接用扫描器 `valueRange`，去引号、跳过空值） |
| `src/domain/semantics/eval-keywords.ts` | `lang-eval*` 正文的 Java/JavaScript/SQL99 联合关键字匹配（正则词边界，返回精确范围，字符串内部跳过） |
| `src/domain/semantics/eval-literals.ts` | `lang-eval*` 正文的数值（`\d+(\.\d+)?`）与字符串（`'[^']*'`/`"[^"]*"`）字面量匹配；字符串范围作为数字/关键字的保护区 |
| `src/domain/semantics/variable-file-extensions.ts` | 变量高亮后缀归一化（`xml`/`.xml`/`*.xml`）与路径后缀匹配 |
| `src/infrastructure/index-service.ts` | 全量/增量索引、watcher、状态、就绪等待 |
| `src/adapters/document-gate.ts` | 语义 Gate（语言、根节点、scheme、大小、开关）与 `decideRaw`（非 XML 变量只查 scheme/大小/开关） |
| `src/adapters/block-background-adapter.ts` | 可见编辑器的装饰（SQL/eval 整行、属性值精确范围、关键字/数值/字符串前景色）、防抖与配置刷新 |
| `src/adapters/raw-variable-highlight-adapter.ts` | 非 XML 文件的变量装饰：按后缀筛选、主题色重建、可见编辑器/文档/配置变化刷新 |
| `src/adapters/new-file-command.ts` | 目录解析、校验、覆盖确认、WorkspaceEdit 写入 |
| `src/domain/templates/render.ts` | `{{placeholder}}` 模板渲染 |
| `src/domain/semantics/variable-extractor.ts` | 变量与占位符提取 |
| `src/domain/semantics/variable-tokens.ts` | 语义 token 条目构建 |

## 5. 数据与生成流水线

```
tools/sources/
  procedure.dtd / procedure.xml / TagConsts.java / ...
        │  tools/extract-metadata.mjs
        ▼
metadata/*.json + metadata/report.md
        │  generate-grammar.mjs / convert-snippets.mjs / generate-metadata-module.mjs
        ▼
syntaxes/xproc4j.injection.tmLanguage.json
snippets/xproc4j.code-snippets
src/generated/metadata.ts
src/generated/procedure-template.ts
```

命令：

| 命令 | 作用 |
|---|---|
| `npm run gen` | 依次执行四个生成器 |
| `npm run gen:metadata` | DTD/常量/示例解析，输出 JSON 与报告 |
| `npm run gen:grammar` | 生成 TextMate 注入语法 |
| `npm run gen:snippets` | IDEA Live Template → VS Code Snippets |
| `npm run gen:module` | JSON + 模板 → TS 模块 |
| `npm run gen:check` | 以 `XPROC4J_DRY_RUN=1` 重跑生成器并比对，不写文件 |
| `npm run source:update` | 源文件变化后重新生成 `tools/sources/SHA256SUMS.json` |
| `npm run source:check` | 单独校验 vendored 源完整性 |

生成器约定：

- 输出必须确定：不得包含时间戳、随机数、绝对路径、机器名。
- 新增元数据字段时同时更新 `docs/04` 与 `metadata/report.md` 的说明。
- 修改 `tools/sources/` 后必须重新生成并提交生成物。
- `gen:check` 失败时根据 `[gen:check]` 输出定位过期文件，不要手改生成物。

## 6. 补全实现要点

1. `resolveCompletionContext` 先检查保护区间，再从光标向前寻找仍处于其中的开始标签。
2. 开始标签使用局部解析器 `parseStartTagPrefix`，允许未闭合引号、未闭合标签与光标在属性各阶段。
3. 非开始标签场景使用正文上下文；`findVariablePrefix` 识别 `${}`、`$!{}`、`#{}`、`#!{}` 与短变量。
4. 装配器按上下文分别产出候选，`assembleCompletions` 统一去重、限流并隔离异常。
5. `CompletionItemProvider` 把领域候选转换为 VS Code Item，替换范围来自上下文或候选自带 range。

修改补全时的回归点：

- 行首裸 `<` 后换行；
- SQL 正文比较符 `<`；
- 结束标签起点；
- 注释/CDATA；
- 已出现属性排除；
- 多值属性当前段替换；
- 未知标签兜底属性；
- 索引未就绪/关闭时降级。

## 7. 索引与导航实现要点

- `IndexService` 依赖 `vscode.workspace.findFiles` 与 `createFileSystemWatcher`，因此位于 `infrastructure`。
- 全量构建分批读取（每批 64），检查大小、NUL 字节、`<procedure`/`<script-segment` 预过滤，再调用 `indexFile`。
- 快照包含文件、条目、id 映射、引用与统计；查询采用基础快照 + 覆盖层合并。
- 编辑器打开/修改/保存/关闭维护覆盖层；覆盖层 URI 会屏蔽同 URI 的基础贡献。
- 关闭文档后延迟重新读盘，避免与保存竞态。
- watcher 使用 300 ms 防抖；删除/重命名移除覆盖层并重扫。
- 定义/引用 Provider 在索引启用时最多等待 400 ms，超时使用当前结果，不阻塞编辑器。

修改索引时的回归点：

- 覆盖层优先与关闭恢复；
- 当前文件排序优先；
- `maxFiles` 截断提示；
- 超大/二进制/非 procedure 跳过；
- 空快照安全；
- 删除/重命名；
- 取消构建保留旧快照。

## 8. 语义 token 与 TextMate 分工

- TextMate 负责标签、属性、feature、正文语言注入与正文变量兜底。
- 语义 token 负责变量（`variable`）与已解析 refid（`xprocRefid`），空占位符使用 `xprocEmptyPlaceholder` 修饰符。
- `semanticTokenScopes` 把 token 映射到 `support.variable.xproc4j`、`entity.name.reference.xproc4j`、`invalid.illegal.xproc4j`。
- refid token 只在 `refid.enabled && index.enabled` 时解析，避免无索引时的错误着色。
- 语义 token 上限 10,000 条；超出时截断，避免超大文档卡顿。

## 9. 测试

```bash
npm run test:unit        # Vitest 单元测试
npm run test:grammar     # vscode-textmate 语法测试
npm run test:integration # 构建后启动本机 VS Code Extension Host
npm run check            # 发布前门禁
```

集成测试说明：

- `test/integration/runTest.mjs` 自动查找本机 VS Code；找不到时可由 `VSCODE_EXECUTABLE` 指定。
- 使用临时 `--user-data-dir` 与 `--extensions-dir`，不污染日常配置。
- Windows 上临时目录清理可能因文件句柄延迟失败，已做重试与降级。
- 断言扩展 ID 必须是 `ice2faith.xproc4j`；修改 `package.json` 的 `name`/`publisher` 时同步修改 `suite.js`。

语法测试说明：

- `test/grammar/harness.ts` 把注入语法合并进 `text.xml` 根规则，模拟 VS Code 根级注入。
- `vscode-textmate` 不支持跨语法注入，因此测试不能直接验证 VS Code 的注入调度，只能验证规则本身。
- 新增语言注入时同时补充 `test/grammar/vendor` 对应语法与用例。

## 10. 构建与打包

```bash
npm run build   # dist/extension.js + sourcemap
npm run package # gen + check + build + vsce + SHA256
```

打包约定：

- 扩展 ID 由 `publisher=ice2faith` 与 `name=xproc4j` 组成。
- VSIX 只包含 `dist/extension.js`、`syntaxes/`、`snippets/`、`README`、`CHANGELOG`、`LICENSE`、`NOTICE`、`package.json`。
- `src/`、`test/`、`tools/`、`metadata/`、`templates/`、`docs/`、source map 不进入 VSIX。
- 无远端仓库时使用 `--allow-missing-repository`；README 不使用相对 Markdown 链接。
- `dist/SHA256SUMS.json` 记录 VSIX 的算法、文件名、版本、大小与 SHA256。
- 发布前必须在干净 profile 中安装 VSIX 做一次冒烟（见 `docs/05-测试报告.md` 第 4 节）。

## 11. 扩展元数据/语法

新增或修改标签、属性、feature：

1. 更新 `tools/sources/` 中对应的 DTD/常量/示例（保持上游来源与 GPL 署名）。
2. 如分类规则变化，修改 `tools/lib/classify.mjs` 或 `build-injections` 相关逻辑。
3. 执行 `npm run gen`。
4. 检查 `metadata/report.md` 的异常统计与 `metadata/injections.json` 映射。
5. 执行 `npm run test:grammar` 与 `npm run gen:check`。
6. 如新增语言注入，更新 `package.json` 的 `embeddedLanguages` 与 `metadata` 生成映射。

注意：

- 不要直接编辑 `syntaxes/`、`snippets/`、`src/generated/`。
- 不要把所有标签 × 所有语言都预生成；当前只对固定映射与 `lang-string`/`lang-render` 动态语言生成，避免语法体积失控。
- 文本规则避免灾难性回溯；生成器已有 `maxRegex` 检查与规则预算。
- 非正文标签必须用 `startTagRule`（begin/end 覆盖完整开始标签），不能只写标签名的 `match`：注入规则消费 `<tag` 后宿主 XML 不会进入 `meta.tag`，属性名会失去 scope。属性统一用 `attrsPattern`，属性名 scope 统一为 `entity.other.attribute-name.xproc4j`。
- SQL 正文中允许出现的 XML 子标签（当前为 `sql-dialect`）必须排在 `source.sql` 之前生成规则，否则会被 SQL 语法当作比较符/标识符。
- 修改语法后至少运行 `npm run test:grammar`；涉及属性/嵌套标签时补一条 token scope 断言，不要只靠人工看颜色。
- 嵌入块背景不走 TextMate：VS Code 不渲染 token background。范围与 `sql`/`eval` 类型由 `src/domain/semantics/block-background.ts` 计算，`src/adapters/block-background-adapter.ts` 为每种类型创建独立 decoration type，并用 `isWholeLine` 绘制；新增着色类型时先扩展领域函数的分类与合并逻辑并补单元测试，再在适配层补充色值与装饰类型。
- 属性值背景直接使用扫描器的 `attribute.valueRange`（已排除引号），不要用正则再次解析原文；无值属性与空值通过 `start === end` 跳过。该背景不是整行装饰，与块背景共用刷新节流但使用独立开关。
- `lang-eval*` 关键字用装饰 `color: '#1E90FF'` 强制前景色，因为 token 前景受主题映射影响，无法保证 dodgerblue；匹配逻辑在 `eval-keywords.ts`，只覆盖关键字范围，不要改动注入语法。关键字表可扩充，但需保持小写并用 `\b` 词边界；字符串内部的关键字已被跳过，修改语义前先更新文档与测试。
- 数值/字符串字面量在 `eval-literals.ts` 计算：先收集字符串范围作保护区（数字与关键字都要跳过字符串内部），再收集数字。适配层按主题选色（Light `#1565C0`/`#2E7D32`、Dark `#90CAF9`/`#81C784`），主题变化时重建 decoration type；改色时先与浅绿整行背景、dodgerblue 关键字做明度对比，避免叠色或不可读。
- 背景与关键字装饰在文档变化后 200 ms 防抖，只处理 `visibleTextEditors`；不要在每次 tokenization 或全工作区扫描时重算。
- 非 XML 变量高亮不要注册语义 token Provider：VS Code 同一语言只采用评分最高的 Provider，注册后会压掉 YAML/Java 扩展自带的 token。应使用 `RawVariableHighlightDecorator` 装饰，后缀由 `variable-file-extensions.ts` 归一化；主题变化时重建 decoration type，文档关闭时清理防抖定时器。
- XML 变量 token 由 `variableHighlightExtensions.includes('xml')` 控制；关闭 XML 变量时仍要输出 refid token，避免 `refid.enabled` 效果被误伤。

## 12. 编码约束

- TypeScript strict；单文件建议 < 1000 行，单函数建议 < 100 行。
- 领域层零 `vscode` 依赖；发现依赖方向错误时移动文件而不是放宽规则。
- 输入必须校验；错误信息包含可操作的修复提示。
- 资源必须释放；监听器、watcher、定时器、输出通道统一挂到 `context.subscriptions`。
- 禁止记录文档正文、属性值、变量值、SQL 文本、凭据。
- 不提供诊断/校验；不要引入 `DiagnosticCollection` 做语法检查。
- 无明确需求不要新增第三方依赖；优先复用 VS Code 与现有生成器。
- 所有 `if/for/while` 语句体使用花括号；避免深层嵌套，优先卫语句。

## 13. 常见开发问题

| 现象 | 排查 |
|---|---|
| 扩展激活但无补全 | 根节点是否 procedure；`xproc4j.enable`；文档是否超限；语言 ID 是否 xml |
| 集成测试找不到扩展 | 检查 `package.json` 的 `publisher/name` 与 `suite.js` 的 `EXTENSION_ID` |
| `gen:check` 失败 | 是否有时间戳/绝对路径；是否忘记 `npm run gen`；查看 `[gen:check]` 输出 |
| vsce 打包失败 | 是否缺少 `repository`；README 是否含相对链接；`files`/`.vscodeignore` 是否排除必需文件 |
| 语法测试通过但编辑器无颜色 | 主题是否覆盖 scope；其他 XML 扩展是否抢占注入；语义 token 是否被主题禁用 |
| 索引一直构建中 | 文件数/大小是否触顶；输出通道与通知；`workspace.findFiles` 在虚拟工作区是否可用 |
