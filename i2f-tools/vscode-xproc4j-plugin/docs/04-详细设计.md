## 1. 设计范围与基线

### 1.1 上游依据

- 功能范围以 `docs/01-需求分析.md` 的 FR-01~FR-12 为准，共 12 条功能需求；C-01~C-20 为补全矩阵编号。
- 架构、模块边界、技术选型以 `docs/03-概要设计.md` 为准；本文档新增的技术决策编号从 DD-013 开始。
- 参考实现行为以 `docs/appendix/A-参考实现分析.md` 为准；元数据来源以 `docs/appendix/B-框架标准参考文档分析.md` 为准。
- 需求已确认，本文档不扩大范围；发现的需求缺口只记录在“已知限制/待验证项”，不擅自增加功能。

### 1.2 本期实现与不实现

| 类别 | 实现 | 不实现 |
|---|---|---|
| 高亮 | XProc4J 标签/属性/feature/枚举/变量 scope；已知标签正文语言注入 | 诊断、错误波浪线、格式化 |
| 补全 | 标签、属性、feature、参数、refid、枚举、布尔、日期、方法、数据源、数据库、结果类型、`_lang`、变量、SQL 关键字 | 类名/包名语义补全、方法签名推断、跨语言语义补全 |
| 导航 | `refid` → `id` 定义跳转、`id` 查找引用 | 标签 → Java 实现类跳转（D-006） |
| 结构 | 大纲、面包屑、折叠 | 调用层级、类型层级 |
| 模板 | 90 个 Snippets、新建 procedure 文件命令 | 文件模板组、代码格式化 |
| 索引 | 工作区 `*.xml` 懒加载索引、增量刷新、手动重建 | 持久化索引、跨工作区共享 |
| DSL | 仅变量着色；TinyScript/Funic/Funvi/OGNL 不做语法/补全/注入 | 自研 DSL 语言服务、调试器 |
| 平台 | 桌面 VSIX；兼容远程/虚拟工作区 | Web 扩展入口 |

### 1.3 平台能力边界

| 能力 | VS Code 事实 | 设计应对 |
|---|---|---|
| 语言注入 | 只有 TextMate 注入语法，不能添加不可见前后缀 | 只做词法级嵌入；Java/JS 不提供语义补全 |
| 跨语法引用 | TextMate 可用 `include: "source.xxx"` 引用已注册语法 | S0-01 验证；缺失时退化为纯文本 |
| 运行时门控语法 | 注入语法静态生效，无 API 按文件关闭 | 语法只匹配 XProc4J 特有名称；语义功能用 Gate 门控 |
| XML AST | 无内置 XML AST | 自研容错扫描器（纯 TS） |
| 索引 | 无内置工程索引 | 纯内存索引 + 文件监听 |
| 行号区图标 | 无 | 用定义跳转/引用查找替代 |
| 语义 token | 可覆盖 TextMate scope，但只能输出 token type/modifier | 变量、refid 匹配态用语义 token 兜底 |
| 文件模板 | 无文件模板组 | 命令 + 模板文件 + 渲染器 |

### 1.4 术语

| 术语 | 含义 |
|---|---|
| XProc 文件 | 根元素为 `procedure` 的 XML 文件 |
| 已知标签 | `metadata/tags.json` 中的 111 个标签（含 14 个 DTD-only 动态 SQL 标签） |
| 基础属性 | 去掉尾部 feature 链后的属性名，如 `value.body-text.trim` → `value` |
| feature | 框架属性修饰符，如 `int`、`render`、`eval-java`，共 58 个 |
| 开放属性标签 | 允许任意参数名作为属性的 11 个标签 |
| 正文注入 | 把标签开始标签与结束标签之间的文本按目标语言着色 |
| 覆盖层 | 打开文档的内存索引，优先于磁盘索引 |
| 索引快照 | 某一时刻不可变的索引数据集合，重建时整体替换 |

### 1.5 强制设计约束

1. 单个源代码文件 ≤ 1,000 行；单个函数 ≤ 100 行；超出必须拆分。
2. 领域层（`src/domain/**`）不得 `import 'vscode'`；VS Code 类型只出现在 `src/adapters/**` 与 `src/extension.ts`。
3. 运行期零第三方依赖；所有依赖在构建期打包进 `dist/extension.js`。
4. 不执行文档内容、不 `eval`、不发网络请求、不写遥测。
5. 所有生成物必须可重复生成；`npm run gen:check` 必须与仓库内容逐字节一致。
6. 所有用户可见文案中文优先；日志、异常消息包含可定位的 URI/偏移。
7. 任何 Provider 不得向 VS Code 抛异常；统一捕获、记录、返回空结果。
8. 大文件/大工程必须有硬上限与降级，不依赖用户机器性能。

### 1.6 S0 验证门（编码第 1 阶段）

| 编号 | 待验证行为 | 验证方法 | 通过标准 | 未通过 Fallback |
|---|---|---|---|---|
| S0-01 | 注入语法内 `include: "source.sql"` / `source.java` / `source.js` / `source.shell` 可解析并着色 | `vscode-textmate` 加载宿主 `text.xml` + 注入语法 + 目标语法，断言 token | 目标语言关键字/字符串/注释出现预期 scope | 仅设置 `contentName`/`embeddedLanguages`，正文退化为单色；FR-03 降级并在文档记录 |
| S0-02 | 注入规则的 `beginCaptures` 内嵌 `patterns` 可对开始标签属性重新分词 | 构造 `<sql-update result="x">`，断言标签名、属性名、属性值、变量 scope | 属性名/值按预期着色，无跨标签污染 | 开始标签只保留标签名 scope；属性交给宿主 XML；属性变量仍由语义 token 兜底 |
| S0-03 | 注入语法不会改变 POM/Spring/MyBatis 的既有 scope | 对三个 fixture 比较启用/禁用扩展的 token 序列 | 差异只出现在已知标签名（若有），属性/文本无差异 | 收紧标签名白名单，移除低价值结构规则 |
| S0-04 | 原生 Snippet 对 `<` 前缀的触发行为 | 在 VS Code 1.90/最新版输入 `<sql-query-list` | 候选出现且可插入 | 改用 `CompletionItemProvider`（`triggerCharacters: ['<']`，`InsertTextFormat.Snippet`），关闭 `contributes.snippets` 或不再注册同前缀 |
| S0-05 | 语义 token 的自定义修饰符/`semanticTokenScopes` 可映射到 `invalid.illegal.xproc4j` | 用 `editor.semanticTokenColorCustomizations` 与默认主题检查空占位符颜色 | 空占位符显示为错误色或可通过配置显示 | 空占位符只由 TextMate 着色；属性内空占位符记录为限制 |
| S0-06 | 自闭合优先规则可避免正文规则吞到 EOF | fixture：`<sql-update .../>` 后跟普通 XML | 后续内容不被 SQL scope 覆盖 | 为每个注入标签增加 `while`/结束保护，或仅对非自闭合标签启用正文注入 |
| S0-07 | 多行开始标签的降级路径稳定 | fixture：`<sql-update\n  result="x"\n>` | 标签/属性可着色，正文不注入，后续 XML 正常 | 接受“多行开始标签不注入正文”，文档记录 |
| S0-08 | 外部语法缺失时注入不崩溃 | 卸载 Groovy 扩展后打开 `lang-eval-groovy` | 无异常，正文为普通文本/变量色 | 移除该语言的 `include`，仅保留 `contentName` |

S0 结论写入 `docs/06-问题与经验.md`（编码阶段创建），并回填本文档对应小节。

与概要设计目录的差异：

- 新增 `domain/**` 与 `adapters/**` 明确分层，避免“领域层零 vscode 依赖”只停留在约定。
- 新增 `start-tag-prefix.ts`、`builtin-attributes.ts`、`glob.ts`，分别承担补全上下文、内置属性、watcher 排除。
- `index-service.ts` 因直接依赖 `vscode` 放在 `infrastructure/`；`domain/index` 只保留数据模型与查询。
- `domain/recognition/gate.ts` 的实际实现为 `adapters/document-gate.ts`，避免领域层依赖 `TextDocument`。
- `protected-ranges.ts` 合入 `scanner.ts`；`navigation/definition.ts` 与 `references.ts` 合并为 `navigation/navigation.ts`。
- `generated/metadata.ts` 代替运行期读 JSON：元数据打包进 bundle，避免 VSIX 路径与异步 I/O；`gen:check` 仍校验 JSON 源。
- `snippets.json` 作为中间产物，最终只输出原生 Snippets；S0-04 验证通过，未启用 Provider 兜底。
- 生成器逻辑放 `tools/lib/`，入口脚本只做参数解析与编排，便于单测。
- 本期仅中文文案，不设 `i18n/` 间接层；后续需要多语言时再抽取。

### 3.2 DTD 容错 Tokenizer

DTD 只有 1,267 行，但存在缺类型声明、重复 ATTLIST、跨行声明、注释、参数实体。实现一个专用 tokenizer，不引入严格解析器。

**词法单元**：

```
COMMENT      <!-- ... -->
DECL_OPEN    <!ELEMENT | <!ATTLIST | <!ENTITY | <!NOTATION | <!OTHER
NAME         [A-Za-z_][A-Za-z0-9_.:-]*
STRING       "..." | '...'
ENUM         ( a | b | c )
KEYWORD      #REQUIRED | #IMPLIED | #FIXED
SYMBOL       ( ) | , > <
EOF
```

**扫描规则**：

1. 跳过 BOM、空白、`<!-- ... -->`；注释未闭合到 EOF 记 issue。
2. 识别 `<!ELEMENT`、`<!ATTLIST`，其余 `<!...>` 跳过到匹配的 `>`（引号内的 `>` 不结束）。
3. 读取名称时允许 `-`、`_`、`.`、`:`；DTD 标签名均为小写短横线。
4. 字符串支持单/双引号；不处理参数实体展开，遇到 `%name;` 跳过并记 info。
5. 枚举类型 `(a|b)` 解析为字符串数组；`#FIXED "x"` 记录默认值。
6. 所有 offset 仅用于报告，不进入运行期数据。

**ELEMENT 解析**：

```
<!ELEMENT name model>
```

- `model` 只保存原始文本（用于报告/未来校验），本期不生成内容模型。
- 重复 ELEMENT：保留第一个，记录 warn；实测无重复。

**ATTLIST 解析伪代码**：

```ts
function parseAttlist(tokens, tagName) {
  const attrs = [];
  while (!tokens.eof() && tokens.peek() !== '>') {
    const name = tokens.expectName();
    let type = 'CDATA';
    let defaultValue: string | undefined;
    let malformed = false;

    const next = tokens.peek();
    if (next.kind === 'KEYWORD' || next.kind === 'STRING') {
      // 缺类型声明：<!ATTLIST lang-set value.double #IMPLIED>
      malformed = true;
    } else if (next.kind === 'ENUM') {
      type = next.text;
      tokens.next();
    } else if (next.kind === 'NAME') {
      type = tokens.next().text; // CDATA / ID / IDREF / ...
    }

    const def = tokens.peek();
    if (def.kind === 'KEYWORD') {
      if (def.text === '#FIXED') {
        tokens.next();
        defaultValue = tokens.expectString();
      } else {
        tokens.next(); // #REQUIRED / #IMPLIED
      }
    } else if (def.kind === 'STRING') {
      defaultValue = tokens.next().text; // 缺省字面量
    } else if (!malformed) {
      malformed = true;
    }

    attrs.push({ name, type, defaultValue, malformed });
  }
  return attrs;
}
```

容错原则：

- 缺类型时按 `CDATA` 处理，并计入 `malformedDeclarations`；非法类型（如 `result trim` 中的 `trim`）同样按 `CDATA` 处理并单独计数；不因此中断整个 DTD。
- 声明末尾缺 `>` 时，把已解析的属性保留，记 issue，跳到下一个 `<!`。
- 一个标签的多条 ATTLIST 按出现顺序合并；同名属性保留第一次声明（记录重复）。
- 属性名区分大小写（`jdbc-type` 与 `jdbcType` 是两个名字，均保留）。

|---|---|

### 3.3 属性归一化

**目标**：把 DTD 中的 `value.double`、`result.body-text.trim.render` 归一为“基础名 + feature 链”。

算法：

```
normalizeAttribute(rawName):
  segments = rawName.split('.')
  if segments.length == 1: return { baseName: rawName, features: [] }
  features = []
  i = segments.length - 1
  while i >= 1 and FEATURES.has(segments[i]):
    features.unshift(segments[i])
    i--
  if features.isEmpty: return { baseName: rawName, features: [] }  // 点号是名字的一部分
  return { baseName: segments.slice(0, i+1).join('.'), features }
```

规则：

- 只剥离**尾部连续**的已知 feature；`a.int.b` 中 `b` 不是 feature，整个名字保留。
- `feature` 集合来自 `FeatureConsts.java`（58 个），构建期解析并校验数量。
- 基础名允许包含点（业务参数名可能带点）；只有尾部 feature 被剥离。
- 同名基础属性的不同 feature 组合合并为一条目录项：`{ name, baseName, features, usages: [{tag, rawName, type}] }`。
- `value` 与 `value.int` 是同一基础属性；补全时给基础名，值补全按 feature 决定（`.int` 提示数值）。
- DTD 中 `jdbc-type` 与 `jdbcType` 不合并（大小写/拼写不同），但共享值枚举。
- `_lang`、`id`、`refid`、`return`、`result` 等特殊属性即使未声明也进入属性目录（来自 `AttrConsts` 与兜底表），标记 `source: 'builtin'`。
- 开放属性标签允许任意属性，目录中只列 DTD/builtin 属性，补全时追加“常用属性”。

**Feature 分组**（用于补全详情与语法生成）：

| 组 | features |
|---|---|
| 类型转换 | `string`、`int`、`long`、`short`、`char`、`byte`、`float`、`double`、`boolean`、`date`、`null` |
| 方向 | `in`、`out` |
| 文本处理 | `trim`、`align`、`spacing-left`、`spacing-right`、`spacing`、`lower`、`upper`、`body-text`、`body-xml`、`render` |
| 位置 | `location`、`location-file`、`location-line`、`location-tag` |
| 求值/上下文 | `eval`、`eval-java`、`eval-js`、`eval-tinyscript`、`eval-ts`、`eval-groovy`、`eval-funic`、`test`、`visit`、`context`、`executor`、`node`、`class`、`not`、`dialect` |
| 空值判断 | `is-null`、`is-not-null`、`is-empty`、`is-not-empty` |
| 生成值 | `date-now`、`uuid`、`current-time-millis`、`snow-uid`、`new-map`、`new-list`、`new-set`、`hashcode` |

### 3.4 标签分类

### 4.1 核心类型（最终）

```ts
// src/domain/types.ts
export interface TextRange {
  start: number; // inclusive, UTF-16 code unit
  end: number;   // exclusive
}

export interface LinePosition {
  line: number;      // 0-based
  character: number; // 0-based, UTF-16
}

export interface LineRange {
  start: LinePosition;
  end: LinePosition;
}

export type Quote = '"' | "'" | null;

export interface XmlAttributeModel {
  name: string;          // 原始名：value.render
  baseName: string;      // value
  features: string[];    // ['render']
  rawValue: string;      // 未解码
  value: string;         // 已解码（仅 XML 实体）
  nameRange: TextRange;
  valueRange: TextRange; // 引号内；空值 start === end
  valueStart: number;    // 第一个值字符（无引号时同 valueRange.start）
  valueEnd: number;      // 结束引号位置（无引号时同 valueRange.end）

}

export interface XmlElementModel {
  name: string;
  nameRange: TextRange;
  startOffset: number;      // '<'
  startTagEnd: number;      // 开始标签 '>' 之后；未闭合为 -1
  startTagClosed: boolean;
  selfClosing: boolean;
  endTagStart: number;      // '</' 的 '<'；无结束标签为 -1
  endOffset: number;        // 整个元素结束之后；未闭合为文本长度
  closed: boolean;
  parentIndex: number;      // -1 根
  depth: number;            // 根为 0
  attributes: XmlAttributeModel[];
}

export type ProtectedKind = 'comment' | 'cdata' | 'pi' | 'doctype' | 'declaration';

export interface ProtectedRange extends TextRange {
  kind: ProtectedKind;
}

export type ScanIssueCode =
  | 'unclosed-comment' | 'unclosed-cdata' | 'unclosed-doctype' | 'unclosed-pi'
  | 'unclosed-start-tag' | 'unclosed-attribute-value' | 'unclosed-element'
  | 'unexpected-end-tag' | 'mismatched-end-tag' | 'max-elements' | 'max-depth';

export interface ScanIssue {
  offset: number;
  code: ScanIssueCode;
  message: string;
}

export interface ScanResult {
  elements: XmlElementModel[];        // pre-order
  rootIndex: number;                  // -1 无根
  protectedRanges: ProtectedRange[];  // 按 start 排序
  issues: ScanIssue[];                // 最多 100 条
  issueCount: number;                 // 总数
  truncated: boolean;
  truncatedReason?: 'max-elements' | 'max-depth';
}

export interface XProcDocumentModel {
  uri: string;
  version: number;
  textLength: number;
  isXProc: boolean;
  rootTag: string | null;
  rootTagOffset: number;
  scan: ScanResult;
  procedureIndexes: number[];         // procedure / script-segment 在 elements 的下标
  variableNames: string[];            // 当前文档变量（不含内置）

  builtAt: number;
```

设计说明：

- `startTagEnd` 是“之后”偏移，便于正文范围 `[startTagEnd, endTagStart ?? endOffset)`。
- `endTagStart` 为 -1 表示没有显式结束标签（自闭合或无结束标签）。
- `endOffset` 对未闭合元素取文本长度，保证区间可查询；`closed=false` 供大纲/折叠降级。
- `valueStart/valueEnd` 用于多值替换与引号定位；`valueRange` 始终在引号内。
- `procedureIndexes` 保存下标而非对象引用，避免模型序列化/复制时的环。
- `refidValues` 只保存当前文档中 `refid` 属性值，供语义 token 判断匹配态。

### 4.2 容错扫描器算法

入口：

```ts
export interface ScanOptions {
  maxElements?: number; // 默认 100_000
  maxDepth?: number;    // 默认 256
  maxTextLength?: number; // 默认 2_000_000；超过仍扫描但截断模型
  indexMode?: boolean;  // 索引模式：不保留 attributes，仅回调
  onElement?: (element: XmlElementModel) => void;
}

export function scanXml(text: string, options?: ScanOptions): ScanResult;
```

实现采用单遍字符扫描，指针 `i` 从 0 到 `text.length`。不使用正则驱动主流程，避免灾难性回溯与跨行误判。

**状态表**：

| 状态 | 进入条件 | 处理 | 退出 |
|---|---|---|---|
| `TEXT` | 默认 | 查找下一个 `<`；其余跳过 | 命中 `<` 后按下一字符分派 |
| `COMMENT` | `<!--` | `indexOf('-->', i+4)` | 未找到 → issue、到 EOF |
| `CDATA` | `<![CDATA[` | `indexOf(']]>', i+9)` | 未找到 → issue、到 EOF |
| `PI` | `<?` | `indexOf('?>', i+2)` | 未找到 → issue、到 EOF |
| `DOCTYPE` | `<!DOCTYPE`（大小写不敏感） | 跳过引号与内部子集 `[...]`，直到顶层 `>` | 未找到 → issue、到 EOF |
| `DECLARATION` | `<!` 其它 | 跳过引号内内容到 `>` | 未找到 → issue、到 EOF |
| `END_TAG` | `</` | 读名称，跳到 `>`；按名称弹栈 | 无匹配 → issue、丢弃该结束标签 |
| `START_TAG` | `<` + 名称起始字符 | 创建元素，解析名称/属性 | `>` 或 `/>` 或 EOF |
| `ATTR_NAME` | 开始标签内非空白 | 读到空白/`=`/`>`/`/` | 进入 `AFTER_ATTR_NAME` |
| `AFTER_ATTR_NAME` | 名称后 | 跳过空白；遇 `=` → `BEFORE_ATTR_VALUE`；否则记录无值属性 | 下一个属性/标签结束 |
| `BEFORE_ATTR_VALUE` | `=` 后 | 跳过空白；引号 → 引号状态；其它 → 无引号值状态 | 值结束 |
| `ATTR_VALUE_QUOTED` | 引号 | 找匹配引号；记录 `valueRange`/`quote` | 引号闭合/EOF |
| `ATTR_VALUE_UNQUOTED` | 无引号 | 读到空白/`>`/`/` | 值结束 |
| `AFTER_ATTR_VALUE` | 值后 | 跳过空白，继续属性 | 下一个属性/标签结束 |

**元素创建与栈**：

```
onStartTag(name, nameRange, startOffset):
  parentIndex = stack.top?.index ?? -1
  depth = stack.length
  element = { name, nameRange, startOffset, startTagEnd: -1, startTagClosed: false,
              selfClosing: false, endTagStart: -1, endOffset: text.length,
              closed: false, parentIndex, depth, attributes: [] }
  elements.push(element)
  if (depth >= maxDepth) { truncated='max-depth'; stop }
  if (elements.length >= maxElements) { truncated='max-elements'; stop }
  暂存 pending 元素，等待标签结束
```

标签结束：

- `>`：`startTagEnd = i+1`，`startTagClosed = true`，非自闭合 → 入栈。
- `/>`：`startTagEnd = i+2`，`startTagClosed = true`，`selfClosing = true`，`closed = true`，`endOffset = startTagEnd`，不入栈。
- EOF：`startTagEnd = -1`，`startTagClosed=false`，记录 `unclosed-start-tag`，不入栈（避免后续内容被误认为子节点）。

结束标签处理：

```
name = readEndTagName()
while stack not empty:
  top = stack.pop()
  if top.name == name:
     top.endTagStart = ltOffset
     top.endOffset = afterGt
     top.closed = true
     break
  else:
     top.endOffset = ltOffset
     top.closed = false
     issue(mismatched/ unclosed-element)
```

- 找到匹配时，中间未闭合元素以当前结束标签的 `<` 作为边界，保证区间不交叉。
- 栈空时遇到结束标签 → `unexpected-end-tag`，不创建元素。

**名称规则**：

- 起始字符：`[A-Za-z_:]`；后续：`[A-Za-z0-9_.:-]`。
- 标签名保留大小写；匹配已知标签时大小写敏感。
- 属性名起始同标签名；允许点号（feature 链）。
- 低于 XML 严格规范的名称按“容错”处理：遇到非法字符停止名称读取，不中断扫描。

**文本中的 `<`**：

- `<` 后不是名称起始、`/`、`!`、`?` 时按普通文本处理，`i++`。
- 这样 SQL 正文中的 `a < b` 不会误开标签，但正文注入规则会先消费 SQL 文本；扫描器仍需容错。

**实体解码**：

```ts
export function decodeXmlEntities(raw: string): string;
```

- 仅解码 `&amp;`、`&lt;`、`&gt;`、`&quot;`、`&apos;`、`&#123;`、`&#x1F;`。
- 数字实体越界或非法 → 原样保留。
- 不递归解码（`&amp;lt;` → `&lt;`，不继续变成 `<`）。
- 只用于属性值；正文文本不解码，变量提取直接基于原文。

**性能**：

- 主循环 O(n)；注释/CDATA/PI/DOCTYPE 使用 `indexOf` 跳跃。
- 属性数组只在 `indexMode=false` 时保留；索引模式用回调收集，避免为 20,000 文件保留完整模型。
- 字符串切片只在需要 `rawValue`/`value` 时发生；索引模式不保存值，只保存 id/refid/参数名。
- 2 MB 文档目标 ≤30 ms（Node 20，桌面）；测试基准见 12.5。

### 4.3 开始标签局部解析（补全专用）

扫描器模型适合完整文档；补全时光标常位于未完成的开始标签内。为避免依赖“最后一次扫描结果”，实现独立的局部解析器：

```ts
export type StartTagState =
  | 'tag-name' | 'attr-name' | 'after-attr-name'
  | 'before-value' | 'in-value' | 'after-value' | 'closed' | 'invalid';

export interface PartialAttribute {
  name: string;
  nameRange: TextRange;
  value: string;
  valueRange: TextRange;
  quote: Quote;
  hasEquals: boolean;
  valueClosed: boolean;
}

export interface StartTagContext {
  startOffset: number;
  tagName: string;
  tagNameRange: TextRange;
  state: StartTagState;
  attributes: PartialAttribute[];
  currentAttributeName: string;
  currentAttributeRange: TextRange;
  currentValue: string;
  currentValueRange: TextRange;
  currentQuote: Quote;
  closed: boolean;
  selfClosing: boolean;
}

export function parseStartTagPrefix(text: string, startOffset: number, upto: number): StartTagContext;
```

算法：

1. `startOffset` 必须是 `<`；跳过 `<` 读标签名到空白/`>`/`/`。
2. 循环：
   - 跳过空白；
   - `>` → `closed=true`；`/>` → `closed=true,selfClosing=true`；
   - 读属性名到空白/`=`/`>`/`/`；
   - 跳过空白；若无 `=` → 记录无值属性，状态 `after-attr-name`；
   - `=` 后跳过空白；若无引号 → 读到空白/`>`/`/`；若有引号 → 读到匹配引号或 `upto`；
   - 若到 `upto` 时仍在引号内 → `state='in-value'`，`valueClosed=false`。
3. 当 `upto` 落在标签名内 → `state='tag-name'`；落在属性名内 → `attr-name`；落在 `=` 后空白 → `before-value`；落在值内 → `in-value`；落在值后 → `after-value`。
4. 任何非法字符 → `invalid`，调用方返回无补全。

定位开始标签：

- 优先从 `XProcDocumentModel.elements` 找包含 `offset` 的开始标签（`startOffset <= offset` 且 `startTagEnd === -1 || offset <= startTagEnd`），取 `startOffset` 最大者。
- 若模型没有（例如刚输入 `<` 尚未形成元素），从 `offset` 向前找最近的 `<`，要求其后到 `offset` 之间没有未被引号包裹的 `>`；用简化反向扫描：向前最多 4,096 字符，遇到 `>` 且不在引号内则停止。
- 找不到 `<` → 非开始标签。

该解析器与主扫描器共享字符规则；两者一致性由单测覆盖（同一 fixture 的模型与局部解析结果对比）。

### 4.4 LineIndex、实体与根节点识别

**LineIndex**：

```ts
export class LineIndex {
  static build(text: string): LineIndex;
  positionAt(offset: number): LinePosition;
  offsetAt(position: LinePosition): number;
  lineRange(range: TextRange): LineRange;
}
```

- 行首数组：`[0]`，遇到 `\n` 时 push `i+1`；`\r\n` 的行首在 `\n` 后，`\r` 属于上一行字符。
- `positionAt` 二分查找最后一个 `lineStart <= offset`；`character = offset - lineStart`，上限为 `lineEnd - lineStart`。
- `offsetAt` 钳制行号与字符，避免越界。
- 用于：索引文件的位置换算、语义 token 的 delta、无 `vscode.Position` 的领域单测。

**根节点识别**：

```ts
export interface RootInfo {
  rootTag: string | null;
  rootTagOffset: number;
  rootTagNameRange: TextRange;
  hasDoctype: boolean;
  isProcedure: boolean;
}

export function detectRoot(text: string, maxScan = 65_536): RootInfo | null;
```

步骤：

1. 跳过 BOM（`\uFEFF`）与空白。
2. 跳过 `<?xml ...?>` 及其它 `<? ... ?>`。
3. 跳过 `<!-- ... -->`。
4. 跳过 `<!DOCTYPE ...>`，包括 `[...]` 内部子集与引号内 `>`；记录 `hasDoctype`。
5. 跳过其它 `<!...>` 声明。
6. 读取第一个开始标签名；若在 `maxScan` 内未找到，返回 `null`。
7. `rootTag` 保留大小写；`isProcedure = rootTag === 'procedure'`。

缓存：

- `DocumentGate` 以 `uri + version` 缓存 `RootInfo`，LRU 50。
- 文档版本变化立即失效；`onDidCloseTextDocument` 清理。
- 根识别不解析完整文档，首屏开销 <1 ms（65 KB 上限）。

**DocumentGate**：

```ts
export interface GateDecision {
  allowed: boolean;
  reason?: 'disabled' | 'not-xml' | 'not-xproc' | 'too-large' | 'unsupported-scheme';
  root?: RootInfo;
}

export function decideGate(document, config, purpose: 'completion'|'navigation'|'symbols'|'semantic'): GateDecision;
```

规则：

- `languageId !== 'xml'` → 拒绝。
- `config.enable === false` → 拒绝（语义功能）。
- `scheme` 为 `file`、`untitled`、`vscode-vfs`、`vscode-remote` 等允许；`output`、`debug` 等拒绝。
- `purpose === 'semantic'` 且长度 > `maxDocumentSizeKB*1024` → 拒绝。
- 其它语义目的同样受 `maxDocumentSizeKB` 限制；索引另有大文件上限。
- 根节点不是 `procedure` → 拒绝。
- 拒绝原因只写 debug 日志，不打扰用户。

### 4.5 文档模型缓存


### 4.6 变量提取

**内置变量**：42 个，顺序固定（见 3.7）。`return` 是内置变量，也是框架保留属性名；补全时两者都显示，去重。

**文档变量来源**：

1. `procedure`/`script-segment` 的属性名（基础名），排除：
   `id`、`refid`、`return`、`params-share`、`_lang`、`__file`、`__line`。
2. 任意元素上 `result`、`item` 属性的值；值去空白，去掉尾部 feature 链（按 3.3 规则），若含 `.` 同时加入根段。
3. 属性值与正文中的占位符（`${}`、`$!{}`、`#{}`、`#!{}`）内容；去空白；合法名称（`[A-Za-z0-9_$.\-]+`）才加入；含 `.` 同时加入根段。
4. 不解析 TinyScript/Funic/Groovy/Java 赋值语句。

**占位符正则**：

```
/[#$]!?\{[^{}]*\}/g      // 含空占位符，支持跨行
/\$[A-Za-z0-9_]+/g       // 短变量
```

- 占位符优先；短变量匹配若与占位符区间重叠则丢弃。
- 不匹配 `#{` 后缺少 `}` 的片段（未闭合）；补全上下文另行识别未闭合。
- 空占位符不加入变量名集合，但产生 `empty` 的 token。

**作用域过滤**：

- 只处理“已知标签”的元素（`catalog.getTag(element.name) !== undefined`），根 `procedure` 也算。
- 属性值：允许；标签名、属性名、结束标签：跳过。
- 注释、CDATA、PI、DOCTYPE：跳过（`ProtectedRange`）。
- 未知标签的正文/属性：跳过。

**实现算法**（单遍 + 元素栈）：

```ts
export interface VariableOccurrence {
  name: string;
  range: TextRange;      // 整个占位符或 $name
  nameRange: TextRange;  // 名称部分
  empty: boolean;
  form: 'placeholder' | 'short';
  elementIndex: number;
}

export function extractVariableOccurrences(
  text: string,
  scan: ScanResult,
  catalog: MetadataCatalog
): { occurrences: VariableOccurrence[]; names: string[] };
```

1. 合并占位符与短变量匹配，按 start 排序，去除重叠。
2. 维护 `elementCursor` 与 `activeStack`：
   - 将 `elements` 中 `startOffset <= match.start` 的元素依次压栈；
   - 弹出 `endOffset <= match.start` 的栈顶；
   - 栈顶即最内层元素。
3. 判断偏移是否在 `ProtectedRange` 内（二分查找）。
4. 判断是否在开始标签内：
   - 若 `match.start < element.startTagEnd` 且不在任一属性 `valueRange` 内 → 跳过。
5. 判断是否在结束标签内：`element.endTagStart <= match.start` → 跳过。
6. 已知标签才收集。
7. 名称规范化：占位符取 `{...}` 内容 `trim()`；短变量去掉 `$`。
8. 文档变量集合按字典序排序；内置变量单独提供。

**性能**：

- 正则单遍；2 MB 文本目标 <20 ms。
- 变量数量上限 10,000；超过截断并记录 warn。
- 结果随模型缓存；语义 token 与补全共用，避免重复扫描。

### 4.7 语义 token（变量与 refid）

**注册**：

```ts
const legend = {
  tokenTypes: ['variable', 'xprocRefid'],
  tokenModifiers: ['xprocEmptyPlaceholder']
};

vscode.languages.registerDocumentSemanticTokensProvider(
  { language: 'xml' },
  provider,
  legend
);
```

**`contributes.semanticTokenScopes`**：

```jsonc
[
  {
    "language": "xml",
    "scopes": {
      "variable": ["support.variable.xproc4j"],
      "variable.xprocEmptyPlaceholder": ["invalid.illegal.xproc4j"],
      "xprocRefid": ["entity.name.reference.xproc4j"]
    }
  }
]
```

作用：在主题没有为自定义语义 token 配色的情况下，回退到稳定 TextMate scope 的颜色；S0-05 验证。

**Provider 行为**：

1. `decideGate(document, config, 'semantic')`；拒绝则返回空。
2. 取模型；若 `variableNames` 尚未计算则计算。
3. 生成变量 token：
   - `typeIndex=0`；普通 modifier 0；空占位符 modifier `1<<0`。
   - 每个 occurrence 一个 token；长度 = `range.end - range.start`。
4. 生成 refid token：
   - 只处理属性名 `refid` 的值；值去空白后非空。
   - 若 `indexService.peekId(value)` 存在（当前快照，不触发构建），`typeIndex=1`，范围 `valueRange`。
   - 若索引未就绪或未命中，不输出 token（保持 XML 字符串颜色）。
5. 排序：按 `start` 升序；同 start 按长度降序；去重（同一范围只保留一个，变量优先于 refid）。
6. 编码：delta line/start + length + type + modifiers；超过 10,000 个 token 截断并记录。
7. `token.isCancellationRequested` 检查在提取前后各一次。

**为什么变量用语义 token 兜底**：

- TextMate 正文规则一旦进入 SQL 字符串/注释，就无法再让变量规则匹配字符串内部；IDEA 的高亮器是独立于语言注入的，能覆盖字符串内变量。
- 语义 token 在渲染层覆盖 TextMate，能保证 SQL/Java/JS 字符串中的 `${x}`、`#{x}` 可见。
- TextMate 变量规则仍保留，用于语义 token 被用户关闭或 provider 未生效的场景；两者并存不会导致错误，只是颜色优先级不同。
- 该调整修正了概要设计 DD-007 的“仅属性变量走语义 token”，记录为 DD-013。

**refid 条件着色**：

- TextMate 无法查询工程索引，不能判断 `refid` 是否命中；语义 token 只在 `peekId` 命中时输出 `xprocRefid`，满足 FR-02 “匹配时引用样式、不匹配保持默认”。
- 索引未构建时 `peekId` 为空，不输出；等索引完成后，语义 token 下次刷新会更新。VS Code 在文档编辑时重新请求；索引完成后可主动触发一次 `onDidChangeSemanticTokens`。

### 5.2 上下文判定

```ts
export type CompletionContext =
  | { kind: 'none'; reason: string }
  | { kind: 'tag'; prefix: string; replaceRange: TextRange }
  | {
      kind: 'attribute';
      prefix: string;             // 完整属性名前缀
      baseName: string;           // 最后一个点之前

  | {
      kind: 'value';
      attributeName: string;
      baseName: string;
      features: string[];
      prefix: string;

      valueRange: TextRange;
      quote: Quote;
      tag: TagMeta | undefined;
      tagName: string;
      valueKind: ValueKind;
    }
  | { kind: 'text'; prefix: string; replaceRange: TextRange; sqlRegion: boolean; variablePrefix: VariablePrefix | null };
```

`ValueKind`：

```ts
type ValueKind =
  | 'refid' | 'propagation' | 'isolation' | 'boolean' | 'time-unit'
  | 'jdbc-type' | 'date-pattern' | 'method' | 'database' | 'datasource'
  | 'result-type' | 'language-id' | 'numeric' | 'eval-java' | 'eval-js'
  | 'eval-groovy' | 'variable' | 'plain';
```

**判定顺序**：

1. `decideGate(..., 'completion')`；拒绝 → `none`。
2. 偏移落在 `ProtectedRange` → `none`（注释/CDATA/DOCTYPE/PI 内）。
3. 用模型找包含偏移的开始标签；调用 `parseStartTagPrefix`：
   - `state === 'tag-name'`：
     - 若文本在 `<` 后以 `/` 或 `!`/`?` 开头 → `none`；
     - 前缀 = 标签名部分；`replaceRange = [nameStart, offset]`；→ `tag`。
   - `state === 'attr-name'`：
     - 解析 `baseName`/`featurePrefix`；
     - `replaceRange` 为当前属性名 token 的范围（从 token 开始到光标；若光标后有字符，扩展到 token 结束）；
     - → `attribute`。
   - `state === 'before-value'` 或 `'in-value'`：
     - 属性名、值范围、引号；
     - `valueKind = resolveValueKind(...)`；
     - `prefix` = 从值起点（多值则为当前段起点）到光标；
     - → `value`。
   - `state === 'after-value'`：若光标在属性之间，按属性名上下文（空前缀）；否则 `none`。
   - `state === 'closed'`：光标在 `>` 后 → 正文 `text`。
4. 不在开始标签内：
   - 用模型找最内层元素；若在结束标签内 → `none`。
   - 判断 SQL 区域（见本节「SQL 区域判定」）。
   - 识别变量前缀（未闭合的 `${`、`$!{`、`#{`、`#!{`、`$`）。
   - → `text`。

**属性名解析**：

```ts
function splitAttributeName(name: string): { baseName: string; featureChain: string[] } {
  const parts = name.split('.');
  if (parts.length === 1) return { baseName: name, featureChain: [] };
  return { baseName: parts[0], featureChain: parts.slice(1) };
}
```

- 补全时如果光标前有 `.`，`featurePrefix` 是最后一个点后的内容；建议只插入 feature 名，不重复 base 和点。

- 已知属性目录按基础名匹配；`value.body-text` 视为 `value` + features。

**SQL 区域判定**：

```
function isSqlRegion(element, catalog): boolean {
  let cur = element;
  while (cur) {
    if (excludedSqlContainers.has(cur.name)) return false; // lang-body、sql-scope 等
    if (sqlBodyTags.has(cur.name)) return true;
    if (dynamicSqlTags.has(cur.name)) { cur = parent(cur); continue; }
    if (hasSqlLang(cur)) return true; // _lang 值按分隔符拆分后含 sql
    cur = parent(cur);
  }
  return false;
}

function hasSqlLang(element): boolean {
  const lang = element.attributes.find((a) => a.baseName === '_lang');
  if (!lang) return false;
  return lang.value.split(/[,;|/]/).some((v) => v.trim().toLowerCase() === 'sql');
}
```

- `sqlBodyTags` 来自 `injections.json` 的 `body` 中 `id === 'sql'`。
- 动态 SQL 标签自身不决定区域，继续向上找。
- `_lang` 值包含 `sql`（大小写不敏感，按 `,;|/` 分割）时，该元素正文为 SQL 区域。
- 排除容器优先于 SQL 标签：`sql-scope` 在 `sql-update` 内时，其正文不是 SQL。

**变量前缀识别**（正文/值内）：

```ts
type VariablePrefix =
  | { form: 'placeholder'; opener: '${' | '$!{' | '#{' | '#!{'; namePrefix: string; replaceStart: number; needsClosingBrace: boolean }
  | { form: 'short'; namePrefix: string; replaceStart: number };
```

- 从光标向前最多 200 字符，匹配 `/([#$]!?\{)([A-Za-z0-9_$.\-]*)$/`；
- 检查从 opener 到光标之间没有 `}`（若有，说明不在占位符内）；
- 若匹配，`replaceStart = openerEnd`；`needsClosingBrace =` 光标后没有 `}`；
- 否则匹配 `/\$([A-Za-z0-9_]*)$/` → 短变量；
- 只在正文或属性值内识别；不在标签名/属性名内。

### 5.4 标签补全（C-01）

- 候选：`catalog.tags` 全部 111 个（含动态 SQL 标签）。
- 排序：
  - 精确前缀匹配优先（VS Code 自身过滤，`sortText` 只决定同分顺序）；
  - 在当前标签内（若光标位于某标签正文）时，动态 SQL 标签排序 `0_1_`，其它 `0_2_`；
  - 顶层时动态 SQL 标签 `0_9_`，避免喧宾夺主；
  - 同组按名称字典序。
- 插入：仅标签名，**不插入 `>`、不自动闭合**，避免与 XML 扩展的自动闭合冲突。
- `label = name`，`filterText = name`，`detail = 标签 · <category>`；`documentation` 第一行 `XProc4J 标签 <name>`，第二行分类，第三行可选“插入后请补充属性”。
- 动态 SQL 标签的文档注明“仅在 SQL 标签正文中有效”。
- 若光标前是 `</` 或 `<!`：不返回标签候选。
- 空前缀时（刚输入 `<`）：返回全部；VS Code 会按字母过滤。
- 与 Snippets 重复：S0-04 若原生 Snippets 生效，标签补全仍保留（覆盖动态标签与未提供模板的标签）；候选可能重复，`sortText` 让 Snippet 先显示（Snippet 的 label 以 `<` 开头，通常排序靠前）。

### 5.5 属性名与 feature（C-02~C-05）

**普通属性**：

1. 当前标签 `catalog.getTag(tagName)`。
2. 候选集合：
   - 标签 DTD 属性（基础名去重）；
   - `builtin` 通用属性：`id`、`refid`、`result`、`value`、`return`、`_lang`、`__file`、`__line`（按标签出现情况筛选？设计：全部提供，详情注明“通用属性”，避免漏掉动态属性）。
3. 排除已出现的属性名（同一标签内已写过的），避免重复；若用户正在编辑同名属性，保留当前。
4. `label/insertText = baseName`；`detail = 属性 · <tagName>`；`documentation` 列出常见 feature 组合（来自 `AttributeMeta.features`，最多 5 个）。
5. 若 `tagName` 是开放属性标签：
   - 追加 `params`（C-03/C-04）；
   - 追加 `#paramAttrName` 提示？补全无法枚举任意参数名；只提供“已有项目参数名”（C-03/C-04）与通用属性。
6. 若当前标签未知：
   - 只给 C-05 兜底属性，`sortText` `8_`。
7. 若标签已知但无任何候选（DTD 无属性且非开放标签）：
   - 给 C-05 兜底属性，`sortText` `8_`。
8. 属性名候选**不插入 `=""`**；用户自行输入等号。整段参数模板除外（见 5.6）。

**整段参数模板**：

- 仅 C-03/C-04，且参数数量 1..30。
- label：`参数模板（N 项）`；`insertText`：

```
arg1=""
arg2=""
...
```

- `InsertTextFormat.Snippet`，每个值写成 `${1}`? 若写成空占位符，用户按 Tab 依次跳转；但会插入 `$` 片段语法。设计：`arg1="$1"`、`arg2="$2"`…… 光标落在引号内；最后 `$0` 放在模板末尾。超过 30 项不提供，避免巨大插入。
- 替换范围：当前属性 token（通常为空）。
- `detail = 参数模板 · 来源`；`documentation` 列出参数名。
- 该条目排在普通属性之后（`1_9_`），避免误选。

**C-03 参数来源**：

- 当前文档所有 `procedure`/`script-segment` 属性（排除保留名），以及索引中所有 procedure/script-segment 的参数。
- 设计取舍：参考实现在 `procedure` 上用“所有 procedure 的参数集合”；在 `script-segment` 上也用所有 meta。为保持行为，当前文档 + 索引全部合并、去重。
- 参数名按基础名去重；feature 组合按出现过的完整名提供（最多 3 条/参数）。
- `detail` 标注“当前文件”或“工程索引 · 相对路径”。

**C-04 调用目标参数**：

- 触发标签：`procedure-call`、`function-call`、`script-include`（与参考实现一致）；`sql-call`、`include` 目前仅导航，不提供参数补全（参考实现未做）。
- 读取当前元素 `refid` 属性值：
  - 缺失/空/含 `$`/`#`/`{` → 不提供；
  - 去空白后查索引；
  - 多个命中：同文件优先，其次 URI 字典序；`detail` 标注“目标：<相对路径> · 共 N 处”；
  - 目标参数使用 `IndexedEntry.params`。
- 当前元素在编辑中可能尚未被模型识别；用 `parseStartTagPrefix` 的 `attributes` 查找 `refid`（支持部分输入）。
- `refid` 值补全（C-06）与参数补全互不阻塞。

**C-05 兜底**：

```
_lang, id, refid, __file, __line, return, result, value
```

- 顺序固定；`detail = 通用属性`。
- 只在无标签属性候选或标签未知时追加；开放标签的通用属性已在普通候选中，不重复。

**Feature 补全（`.` 后）**：

- 当 `featurePrefix !== null`（属性名包含 `.` 且光标在最后一个点后）：
  - 候选：58 个 feature，按分组排序；已出现在链中的 feature 仍显示（允许重复？设计：过滤掉已出现的，避免 `value.int.int`）。
  - `insertText = feature`；`replaceRange = [lastDot+1, tokenEnd]`。
  - `detail = 修饰符 · <group>`；`documentation` 给一句说明。
  - 若当前 baseName 是已知属性，且 DTD 中该属性出现过特定 feature 组合，把这些组合排在前面（`2_0_`），全部 feature 在后（`2_1_`）。
  - 输入 `value.` 时，`AttributeAssembler` 不提供基础属性，只提供 feature。
  - 输入 `value.body-` 时，VS Code 用 `filterText` 过滤；`insertText` 只替换 `body-` 后的部分？设计：`replaceRange` 从最后一个点后到光标，插入完整 feature（`body-text`），因此会把已输入的 `body-` 一起替换，避免重复。`filterText = feature`。

### 5.6 属性值补全（C-06~C-17）

**通用**：

- 值上下文才触发；替换范围默认整个值（不含引号）。
- 多值属性（数据库/数据源/`_lang`）按 5.7 计算当前段。
- 候选 label = 插入值；`filterText = 值`；`detail` 带来源（`枚举 · propagation` 等）。
- 排序：完全匹配当前前缀的项由 VS Code 过滤；同分按配置顺序。
- 值内变量（C-18）与枚举可同时存在：枚举 `3_`，变量 `4_/5_`；用户可继续输入 `$` 切换到变量。

**C-06 refid**：

- 数据：索引 `allIds`（去重）。
- 每项 `detail = 定义 · <相对路径>`；重复 id 时 `detail = 定义 · <首个路径> · 共 N 处`，`documentation` 列出最多 10 个路径。
- 排序：当前文件 id 优先（`3_0_`），其余 `3_1_`；同组按 id 字典序。
- 上限 500；超过按字典序截断，日志记录。
- 插入完整 id；不插入引号。
- `refid` 值以 `$` 开头时仍提供 id 列表？需求未禁止；保留，但输入 `$` 时变量候选排序更高。

**C-07/C-08**：

- `propagation` 7 项；`isolation` 5 项（带 `TRANSACTION_` 前缀）。
- 需求说 isolation 允许带/不带前缀；补全只给带前缀的 5 项，避免 10 项噪音；用户手输不带前缀也算合法（无诊断）。
- `detail = 枚举 · propagation/isolation`。

**C-09 布尔**：

- `true`、`false`；`detail = 布尔值`。
- 属性名列表 11 个，来自 `booleanAttributes`；feature `.boolean` 也触发。

**C-10 time-unit**：7 项；`detail = 枚举 · TimeUnit`。

**C-11 jdbc-type**：39 项；`detail = 枚举 · JDBCType`；按枚举声明顺序。

**C-12 日期格式**：9 项；`detail = 模板 · 日期格式`；不做校验。

**C-13 method**：21 项；`detail = 方法`；`documentation` 给简短说明（如 `String.valueOf`）。

**C-14 数据库**：6 项；多值；`detail = 枚举 · 数据库`。

**C-15 数据源**：4 项；多值；`detail = 枚举 · 数据源`。

**C-16 结果类型**：6 项；`detail = 枚举 · 结果类型`。

**C-17 `_lang`**：

- 语言 ID 来自 `injections.json` 的 `langDynamic.values` 键 + 固定语言列表（sql/java/javascript/js/json/xml/yaml/shell/bash/css/sass/markdown/md/regex/regexp/groovy/vtl/velocity/freemarker/thymeleaf/spel/el/expr/typescript）。
- 去重排序；`detail = 语言 ID`；多值按 `,;|/`。
- `documentation` 注明“需安装对应语法扩展才能获得高亮”。

**数值/布尔/类型属性**：

- `.int`/`.long`/... 不提供具体候选（无数值范围）；只靠用户输入。
- `.boolean` 提供 true/false。
- `class`/`type`/`package` 等不提供候选（无 Java 索引）；文档说明可由 Java 扩展提供，但本扩展不注册。
- `test`/`collection` 不提供表达式候选；变量候选可用。

### 5.7 多值替换算法

```ts
function valueSegment(text: string, valueRange: TextRange, offset: number, separators: string[]): TextRange {
  let start = valueRange.start;
  let end = valueRange.end;
  for (let i = offset - 1; i >= valueRange.start; i--) {
    if (separators.includes(text[i])) { start = i + 1; break; }
  }
  for (let i = offset; i < valueRange.end; i++) {
    if (separators.includes(text[i])) { end = i; break; }
  }
  while (start < end && /\s/.test(text[start])) start++;
  while (end > start && /\s/.test(text[end - 1])) end--;
  return { start, end };
}
```

- 只在 `valueKind` 为 `database`/`datasource`/`language-id` 时使用；其它属性整个值替换。
- 分隔符来自 `enums.multiValueSeparators`；`databases` 含 `/`，`datasources` 不含。
- 插入候选时只替换段，保留分隔符与其它段。
- 前缀用于过滤：从段起点到光标（去前导空白）。
- 若光标在分隔符上，视为前一段末尾；段范围按上述逻辑。

### 5.8 变量补全（C-18）

**候选集合**：

- 文档变量（`model.variableNames`）：`detail = 变量 · 当前文件`，`sortText 4_`。
- 内置变量（配置 `completion.builtinVariables` 为 true）：`detail = 变量 · 内置`，`sortText 5_`。
- 去重：同名文档变量优先；内置顺序固定。

**插入**：

- 占位符上下文：`insertText = name + (needsClosingBrace ? '}' : '')`；替换 `[openerEnd, offset]`。
- 短变量上下文：`insertText = name`；替换 `[$位置+1, offset]`，`$` 保留。
- `label = name`；`filterText = name`；`documentation` 说明来源。
- 若变量名含 `.`，补全仍插入完整名；用户可继续输入。

**触发**：

- 属性值内：`$`、`#`、`{` 触发；`"` 后输入 `$` 也触发。
- 正文内：仅当变量前缀匹配；普通字母不触发变量（避免与 SQL 关键字/XML 文本补全冲突）。
- 空前缀（刚输入 `${`）：返回全部变量；VS Code 显示列表。
- 已输入部分名称：按前缀过滤。
- 光标后已有 `}`：不补 `}`，避免 `}}`。
- 若变量前缀未闭合且光标位于 SQL 字符串内：仍可补全；语义 token 后续着色。

**变量集合边界**：

- 变量采集只针对已知标签；属性名中的 `$` 不算变量（不在值内）。
- `procedure`/`script-segment` 的 `id` 不作为变量；`result` 作为产出变量。
- 内置 `return` 与属性 `return` 同名；去重后只显示一次，detail 标注“内置/参数”。

### 5.9 SQL 关键字补全（C-19）

- 条件：`isSqlRegion === true`；配置 `completion.sqlKeywords`；非变量前缀上下文。
- 当前单词：从光标向前匹配 `/[A-Za-z_][A-Za-z0-9_]*$/`；替换该单词。
- 候选：`sqlKeywords` 大写 + `sqlFunctions`（函数排序靠后）。
- `label = 关键字`，`insertText = 关键字`，`kind = Keyword`，`detail = SQL 关键字`。
- 排序 `6_0_`（关键字）/`6_1_`（函数）；同组按字母。
- 若当前前缀为空（刚输入空格），不返回全部关键字，避免每次空格弹出巨大列表；仅在已有字母前缀时返回。C-19 触发方式为“字母输入”，符合。
- SQL 区域内的 XML 别名/表名不补全（无数据库连接）。
- 与变量候选并存时，变量 `4_/5_` 优先；用户输入 `$` 后关键字不再匹配。

### 5.10 去重、排序、上限与文档

**去重键**：`kind + '\u0000' + label + '\u0000' + insertText`。同一键保留先加入者（高优先级 Assembler 先执行）。

**排序**：

- `sortText` 采用 `组_子组_名称`；VS Code 先按 sortText，再按过滤质量。
- 组顺序：标签/属性 `0`，参数 `1`，feature `2`，值 `3`，变量 `4/5`，SQL `6`，兜底 `8`。
- 同组内：当前标签/当前文件优先；精确匹配优先（由 VS Code 过滤保证）；名称字典序。
- 不使用 `preselect`，避免误插入。

**上限**：

- 总候选 1,000；按组顺序截断，记录 debug 日志。
- 单组上限：refid 500、变量 1,000、SQL 关键字 200。
- 超出时设置 `isIncomplete=false`（仍然完整过滤后的结果），不实现分页。

**文档**：

- `documentation` 使用 `MarkdownString`，`isTrusted=false`；内容只来自静态元数据，不插入文档原文（防 Markdown 注入）。
- 第一行：名称/值；第二行：来源；第三行：说明（如有）。
- 不加载远程图片/链接。

**错误处理**：

- `provideCompletionItems` 外层 try/catch；任一 Assembler 抛错只跳过该 Assembler，继续其它。
- 取消令牌在每个 Assembler 前检查；取消返回空数组（VS Code 会忽略）。
- 日志包含 URI、offset、tag、context kind；不记录文档内容。

### 5.11 典型交互示例

1. **标签**：输入 `<sql-` → 候选 `sql-query-list` 等；选择后得到 `<sql-query-list`，光标在名称后，不自动补 `>`。
2. **属性**：在 `<sql-update |` 输入空格触发 → 候选 `result`、`datasource`、`id` 等；选择 `result` 得到 `result`，用户输入 `="`。
3. **feature**：输入 `result.` → 58 个 feature；选择 `body-text` 得到 `result.body-text`。
4. **参数**：在 `<procedure-call refid="B" |` → 目标 B 的参数；选择整段模板一次插入多行属性。
5. **refid 值**：`refid="|` → 工程 id 列表；重复 id 的 detail 标注路径。
6. **枚举**：`propagation="|` → 7 项；`database="mysql,|` → 6 项且只替换当前段。
7. **变量**：`result="|` 输入 `$` → 变量列表；选择 `userList` 插入 `$userList`；若输入 `${` 则插入 `userList}`。
8. **SQL**：在 `<sql-update>` 正文输入 `sel` → `SELECT`；选择后得到 `SELECT`。
9. **普通 XML**：Maven POM 中 `<` 不出现 XProc4J 标签/属性候选（Gate 拒绝）。

## 6. 工程索引与 refid 导航

### 6.1 索引数据模型

索引只保存定位所需信息，不保留文档文本与完整元素树。

```ts
// src/domain/index/index-model.ts
export interface IndexedParam {
  name: string;          // 基础名
  features: string[];    // 该参数出现过的 feature 组合（合并去重）
}

export interface IndexedEntry {
  id: string;
  kind: 'procedure' | 'script-segment';
  uri: string;                 // 归一化 URI 字符串
  range: LineRange;            // 整个元素
  idRange: LineRange;          // id 属性值（不含引号）
  parentId?: string;           // 最近的 procedure/script-segment 祖先的 id
  params: IndexedParam[];
}

export interface IndexedRef {
  refid: string;
  uri: string;
  range: LineRange;            // refid 属性值（不含引号）
  tagName: string;
}

export interface FileIndex {
  uri: string;
  version: number;             // 文档版本；磁盘文件用 0
  entries: IndexedEntry[];
  refs: IndexedRef[];
  rootTag: string | null;
  skippedReason?: 'too-large' | 'binary' | 'parse-error' | 'not-xproc';
}

export interface IndexSnapshot {
  generation: number;
  files: Map<string, FileIndex>;
  byId: Map<string, IndexedEntry[]>;
  refsById: Map<string, IndexedRef[]>;
  allIds: Set<string>;
  truncated: boolean;
  builtAt: number;
  stats: IndexStats;
}

export interface IndexStats {
  fileCount: number;
  scannedFiles: number;
  skippedFiles: number;
  entryCount: number;
  refCount: number;
  bytes: number;
  durationMs: number;
  truncatedFiles: boolean;
  truncatedEntries: boolean;
}
```

设计说明：

- 索引存 `LineRange` 而非 offset：关闭的文件不需要打开文档即可生成 `vscode.Location`；打开文件的实时位置优先用当前模型计算。
- `uri` 使用 `Uri.toString()` 作为键，避免 Windows 大小写/分隔符差异；显示时用 `fsPath` 相对路径。
- `params` 只保存基础名与出现过的 feature 组合；补全时展开为 `name` 与 `name.feature`。
- `FileIndex.version`：磁盘文件为 0；覆盖层为文档 version，用于判断是否需要重建。
- `IndexSnapshot` 构建完成后不可变；增量更新通过“新文件索引对象 + 映射复制/覆盖”实现，避免查询看到半状态。

### 6.2 首次构建

**触发**：

- 第一次需要 C-04/C-06、定义跳转、引用查找时，调用 `indexService.ensureStarted()`。
- 用户执行“重建工程索引”命令。
- 配置从 `index.enabled=false` 切到 `true` 时不自动全量构建，等下一次需要或手动命令。
- 激活时不构建。

**流程**：

```
ensureStarted():
  if !config.index.enabled: return empty
  if state == ready or building: return
  state = building
  generation = ++buildToken
  snapshot = await buildSnapshot(token)
  if token cancelled: discard
  else: swap snapshot; state = ready
```

`buildSnapshot`：

1. 无工作区文件夹 → 空快照，state=ready。
2. `workspace.findFiles(include, exclude, maxFiles + 1)`。
   - `include` 为空时使用默认 `**/*.xml`。
   - `exclude` 为空时使用默认列表；`null` 表示不排除（配置不允许 null）。
   - 结果按 `uri.toString()` 排序，保证 `maxFiles` 截断稳定。
   - 若数量 > maxFiles：取前 maxFiles，`truncatedFiles=true`，warn 一次（输出通道 + 状态栏提示）。
3. 分批读取，并发 8，每批 64 个文件：
   - `workspace.fs.stat` 可选；直接 `readFile` 后判断字节数。
   - 超过 `maxDocumentSizeKB*1024` → 跳过，`too-large`。
   - 前 1,024 字节含 NUL → 视为二进制，跳过。
   - `TextDecoder('utf-8', { fatal: false })`；去 BOM。
   - 预过滤：文本不包含 `<procedure` 且不包含 `<script-segment` → 跳过（`not-xproc`），不解析。
4. 轻量扫描（见 6.3）；根不是 `procedure` → 丢弃该文件贡献。
5. 累计条目数超过 `MAX_INDEX_ENTRIES = 500_000` → 停止读取后续文件，`truncatedEntries=true`，warn。
6. 每批结束 `await new Promise(r => setImmediate(r))`，让出事件循环；检查取消。
7. 构建 `byId`/`refsById`/`allIds`；同一 id 的条目按 `uri` 字典序、`range.start` 排序。
8. 计算耗时、字节数、跳过原因；写入日志。
9. 原子替换快照；`state=ready`；更新状态栏；触发一次 `onDidChangeSemanticTokens`（refid 条件着色刷新）。

**并发**：

- 同一时刻只允许一个构建；新的重建先取消旧的（`CancellationTokenSource`），旧结果丢弃。
- 读取文件期间若配置变化（include/exclude/maxFiles），取消当前构建并标记需要重建；下一次请求重新开始。
- 构建失败（非取消）→ 保留旧快照，state=failed，记录 error；30 秒内不自动重试，避免抖动。

**进度**：

- 手动重建：`window.withProgress({ location: Notification, title: 'XProc4J: 重建工程索引', cancellable: true })`，报告 `已扫描 X / Y`。
- 后台首次构建：状态栏 `$(sync~spin) XProc4J 索引 1200/20000`；完成后 `$(check) XProc4J 索引就绪` 3 秒后隐藏；失败显示 `$(warning)`，点击打开输出。
- 不弹通知，避免打扰。

### 6.3 轻量扫描（index scan）

`scanXml` 的完整模型会为每个元素保留属性数组；20,000 文件时内存不可接受。实现“同一状态机 + 不同 sink”：

```ts
export interface XmlScanSink {
  onStart(element: { name: string; startOffset: number; parentIndex: number; depth: number }): void;
  onAttribute(attr: XmlAttributeModel): void;
  onClose(elementIndex: number, endTagStart: number, endOffset: number, closed: boolean): void;
  onText?(range: TextRange): void;
}

export function scanXmlCore(text: string, sink: XmlScanSink, options?: ScanOptions): ScanResult;
```

- 完整模型 sink：收集 `elements`、`protectedRanges`、`issues`。
- 索引 sink：只维护：
  - 元素栈：`{ name, startOffset, id?, entry?, params? }`；
  - 当前文件的 `rootTag`；
  - `entries` / `refs` 暂存；
  - `LineIndex`（构建一次）。
- 索引 sink 在 `onAttribute`：
  - 若当前元素是 `procedure`/`script-segment`：
    - `id` 属性：记录 id 与 `valueRange`；空 id 不生成 entry。
    - 其它属性：排除保留名，加入 `params`；`baseName` + `features` 合并去重。
  - 任意元素 `refid` 属性：记录 `refid` + `valueRange` + tagName；空值不记录。
- `onClose`：若当前元素是 procedure/script-segment 且有 id，生成 `IndexedEntry`：
  - `range` 从 `startOffset` 到 `endOffset`（转 LineRange）；
  - `idRange` 从属性 valueRange 转 LineRange；
  - `parentId` 为祖先栈中最近的 procedure/script-segment 的 id；
  - `params` 排序去重。
- 文件结束：未闭合元素按 `endOffset=text.length` 关闭；未闭合 entry 仍生成（容错）。
- 根元素不是 `procedure`：扫描结束后丢弃所有 entries/refs（避免普通 XML 污染）。
- 不保存属性值文本；只保存 id/refid/参数名（参数名来自 name，不保存值）。
- 索引扫描沿用 `maxElements=100000`；超过上限的文件标记 `parse-error`/truncated，保留已收集条目并 warn。

**根识别与预过滤**：

- 预过滤只做 `includes('<procedure') || includes('<script-segment')`，可能误判注释中的文本；真正根判断由扫描器完成。
- 文件根不是 procedure → `not-xproc`，跳过且不报错。
- XML 声明、注释、DOCTYPE 在根之前，扫描器正常跳过。

**位置换算**：

- 每个文件构建一次 `LineIndex`；所有 `LineRange` 在 sink 内转换，扫描结束后释放 LineIndex。
- 行号 0-based，与 VS Code 一致。

### 6.4 覆盖层与增量更新

**覆盖层**：

- `overlayFiles: Map<uri, FileIndex>`，只包含打开过且仍打开的文档。
- `overlayById: Map<id, IndexedEntry[]>`、`overlayRefsById`、`overlayAllIds` 与 overlayFiles 同步更新。
- 查询合并：
  - `findEntries(id)` = base.byId[id] 过滤掉 `overlayFiles.has(uri)` 的条目 + overlayById[id]；
  - `findRefs(id)` 同理；
  - `allIds` = base.allIds ∪ overlayAllIds，但若 overlay 文件为空索引，需要屏蔽 base 中该文件的 id；用 `maskedUris` 集合处理。
- `peekId(id)` 先查 overlay，再查 base。

**文档变化**：

- `onDidOpenTextDocument`：若 XML，调度 `updateOverlay(uri)`。
- `onDidChangeTextDocument`：300 ms 防抖；同一 URI 的新变化取消旧定时器。
- `onDidSaveTextDocument`：立即调度（去抖 50 ms），并触发 watcher 的磁盘重扫（可能重复，Watcher 去重）。
- `onDidCloseTextDocument`：移除 overlay；若文件仍存在，磁盘内容重新索引（延迟 300 ms，避免立即读盘与保存竞态）。
- 文档不是 XProc（根变化）：仍生成空 `FileIndex` 放入 overlay，屏蔽 base 的旧 id/refs；`skippedReason='not-xproc'`。
- 文档超过大小上限：空 overlay + `too-large`，屏蔽 base；语义功能本身已 Gate 拒绝。
- 覆盖层扫描失败：保留上一次 overlay；记录 warn；不删除，避免补全瞬间丢失。

**Watcher**：

- 索引首次启动时创建 watcher，按工作区文件夹：
  `workspace.createFileSystemWatcher(new RelativePattern(folder, '**/*'))`。
- 事件过滤：
  - URI 必须在工作区内（`workspace.getWorkspaceFolder(uri)` 存在）；
  - 扩展名 `.xml` 或匹配 `projectScan.include`（include 可能包含非 `.xml`，用 glob 匹配）；
  - 不匹配 `projectScan.exclude`；
  - 不在 `files.exclude`？不强制，用户可用 exclude 控制。
- 事件处理：
  - `onDidCreate` / `onDidChange`：300 ms 去抖后 `reindexFileFromDisk(uri)`；
  - `onDidDelete`：立即移除 base 贡献；若 overlay 存在也移除（文件已删）；
  - `onDidRenameFiles`：移除旧 URI，索引新 URI（不等 watcher 的 delete/create，减少空窗）。
- 去重：记录 `uri -> {mtime, size, hash?}`；读盘后若 mtime/size 未变则跳过。`FileStat.mtime` 可用；不可用的虚拟文件系统则总是重扫。
- 保存时 watcher 与 `onDidSave` 可能同时触发；去抖 + 同一 URI 串行队列（`Map<uri, Promise>`）保证最后一次生效。
- Watcher 不可用（远程/虚拟 FS 抛错）：降级为 `onDidSave` + 手动重建；日志 warn。

**增量原子性**：

- 单文件更新：构建新的 `FileIndex`，复制当前 snapshot 的 Map（浅拷贝），删除旧贡献，加入新贡献，生成新 snapshot，`generation++`，整体替换。
- 20,000 文件时复制 `Map` 是 O(n)；为降低频率，watcher 事件合并为 100 ms 批处理：一次批处理只复制一次。
- 覆盖层不复制 base；查询时合并，避免每次键入复制大 Map。
- 全量重建用新 Map，完成后替换；查询始终看到旧或新完整快照。

### 6.5 查询接口

```ts
export interface IndexQuery {
  findDefinitions(id: string, currentUri?: string): IndexedEntry[];
  findReferences(id: string): IndexedRef[];
  getEntry(uri: string, id: string): IndexedEntry | undefined;
  getParams(refid: string, currentUri?: string): { entry: IndexedEntry; params: IndexedParam[] } | undefined;
  getAllIds(limit: number): Array<{ id: string; uri: string; count: number }>;
  peekId(id: string): boolean;
  getStats(): IndexStats;
  getState(): 'idle' | 'building' | 'ready' | 'failed' | 'disabled';
}
```

- `findDefinitions` 排序：同 `currentUri` 优先，其次 `uri` 字典序，再 `range.start`。
- `findReferences` 排序：同文件优先，其次 URI，再 offset。
- `getParams`：多个目标时同文件优先；返回第一个；调用方可在 detail 显示总数。
- `getAllIds`：按 id 去重，保留最短/同文件路径；用于 C-06；结果排序当前文件优先。
- `peekId` 不做懒构建；只查当前快照/覆盖层。
- 所有查询同步、O(1)/O(k)，不做 I/O。

### 6.6 定义跳转与引用查找

**DefinitionProvider**：

1. Gate：`refid.enabled`、`config.enable`、根 procedure、大小限制。
2. 取模型；找包含 offset 的属性值；属性名必须为 `refid`（大小写敏感）。
3. `id = attr.value.trim()`；空 → 返回空。
4. 同文件当前模型优先：查 `procedureIndexes` 中 id 完全匹配的 entry；用当前文档 offset 生成 Range（避免 overlay 300 ms 延迟）。
5. 查索引（排除同 URI 的重复项），合并；`await indexService.whenReady(400, token)`：
   - 若 400 ms 内未就绪，返回当前已有结果（可能为空），不阻塞编辑器；输出通道 debug 记录一次“索引未就绪”。
6. 转 `vscode.Location[]`；去重（uri + range）。
7. 多个结果由 VS Code 显示选择器。
8. `refid` 任何标签都支持（不限于调用标签）。

**ReferenceProvider**：

1. Gate：`refid.enabled`。
2. 光标位于 `procedure`/`script-segment` 的 `id` 属性值内。
3. `id = attr.value.trim()`；空 → 返回空。
4. `refs = indexService.findReferences(id)`。
5. `context.includeDeclaration` 为 true 时，加入所有同 id 的 entry 的 `idRange`（同文件当前模型优先，其他文件用索引 LineRange）。
6. 返回 `Location[]`，去重排序。
7. 不包含声明时只返回 refid。

**Location 转换**：

- 索引 `LineRange` → `new vscode.Range(start.line, start.character, end.line, end.character)`。
- 当前文档 offset → `document.positionAt`。
- 打开文档但索引 range 与当前文本不一致时，优先当前模型；找不到才用索引。
- 索引 URI 用 `Uri.parse`；仅返回 `file`/`vscode-remote`/`vscode-vfs` 等可打开 scheme。

**索引未启用**：

- 同文件定义仍可用（当前模型）；跨文件返回空。
- 索引禁用时，ReferenceProvider 返回空（不扫描工作区）；定义跳转同文件可用。文档说明。

**错误与取消**：

- 任何异常捕获，返回空，日志记录。
- `token.isCancellationRequested` 在等待前后检查。
- 不弹错误通知；输出通道有记录。

### 6.7 索引性能与内存

| 指标 | 目标 | 机制 |
|---|---|---|
| 20,000 文件首次索引 | ≤30 s（SSD；内部预算 25 s） | 8 并发读、批量 yield、轻量 sink、预过滤 |
| 内存 | ≤50 MB（内部预算 40 MB） | 只存 id/ref/参数名/行范围；不存文本/属性数组 |
| 单文件变更到查询可见 | ≤1 s | 300 ms 去抖 + 100 ms 批量提交 + overlay 优先 |
| 查询 | <1 ms | Map 索引、O(k) 合并 |
| 打开大文档 | UI 不卡 | 覆盖层扫描在 `setTimeout` 中执行；2 MB 上限 |
| 条目上限 | 500,000 | 超过停止新增，warn，保留已有 |
| 文件上限 | 20,000（可配） | `findFiles(max+1)` 检测，截断 |

**取消与竞态**：

- 全量构建 token：配置变化、手动重建、扩展停用时取消。
- 单文件更新：同一 URI 串行；最新版本获胜；旧结果比对 `version`/`mtime` 后丢弃。
- 覆盖层与磁盘索引并存：查询合并，overlay 始终优先；关闭文档后移除 overlay，回退磁盘。
- 不在索引构建中持有文档对象；只持有文本副本，扫描后释放。

**索引状态**：

```
disabled ← config.index.enabled=false
idle → building → ready
             ↘ failed（30s 后可重试）
ready → building（手动重建/配置变化）
```

状态栏与输出通道记录状态变化；不阻塞编辑器启动。

## 7. 导航、大纲与折叠

### 7.1 大纲（DocumentSymbolProvider）

**范围**：Gate 通过的 XProc 文档；配置 `symbols.enabled`。

**构建**：

1. 从模型 `elements` 构建树：根元素（`parentIndex=-1`）为顶层；`procedure` 为根；若畸形文档有多个顶层，全部返回。
2. 每个元素生成 `DocumentSymbol`：
   - `name`：标签名 + 关键属性摘要。
   - `detail`：分类（中文，如 `SQL`、`流程`）。
   - `kind`：按表 7.1。
   - `range`：`startOffset..endOffset`；未闭合到文本末尾。
   - `selectionRange`：`nameRange`。
   - `children`：子元素符号。
3. 未知标签也生成符号（FR-09），`kind=Object`，`detail='未知标签'`。
4. 注释、文本、CDATA 不生成。

**名称格式化**：

- 关键属性顺序：`id`、`refid`、`result`、`name`、`test`、`datasource`、`databases`、`value`、`method`。
- 只取第一个存在的 1~2 个，格式 `key=value`（不引号）；值超过 40 字符截断加 `…`。
- 总名称上限 80 字符；超出截断。
- 示例：`sql-query-list result=userList`、`procedure-call refid=B`。
- 无关键属性时只显示标签名。
- 不对值做 HTML/Markdown 转义（DocumentSymbol 是纯文本）。

**SymbolKind 映射**：

| 标签/类别 | SymbolKind |
|---|---|
| `procedure` | `Class` |
| `script-segment` | `Function` |
| `procedure-call`、`function-call`、`java-call` | `Method` |
| `sql-*`、`etl-*` | `Function` |
| `lang-if`/`choose`/`while`/`foreach`/`fori`/`try` | `Control`? VS Code 无 Control；用 `Event` 或 `Operator` |
| `log-*`、`debugger`、`lang-println`/`printf` | `Event` |
| `context-*`、`event-*` | `Namespace` |
| 其它 `lang-*` | `Function` |
| 未知 | `Object` |

> VS Code `SymbolKind` 没有 `Control`；流程控制用 `Operator`，避免语义误导。

**性能**：

- 直接遍历 `elements`，O(n)；10,000 行目标 <200 ms。
- 不重复扫描文本；使用模型缓存。
- 超过 `maxElements` 截断时，仍返回已解析部分，`detail` 标注“已截断”。

### 7.2 折叠（FoldingRangeProvider）

- Gate 通过且 `folding.enabled`。
- 对每个 `closed` 元素，且 `startTagEnd < endTagStart`（多行）：
  - `startLine = positionAt(startOffset).line`
  - `endLine = positionAt(Math.max(startOffset, endOffset - 1)).line`
  - 若 `endLine <= startLine` → 跳过（单行）。
  - `new FoldingRange(startLine, endLine, FoldingRangeKind.Region)`
- 自闭合/未闭合元素不产生折叠（未闭合到 EOF 会产生巨大折叠，跳过）。
- 不在结束标签行隐藏结束标签？VS Code 折叠通常隐藏 startLine+1..endLine；保留结束标签可见更符合 XML 习惯。设计：若结束标签独占一行，`endLine = endLine - 1`，避免把 `</tag>` 一起折叠；若 `endLine <= startLine` 则跳过。该行为与 XML 扩展可能不同，但两者合并后用户可选择；测试确认不冲突。
- 不处理注释折叠（XML 扩展负责）。
- 结果上限 5,000；超过截断。

### 7.3 面包屑

- 由 DocumentSymbol 自动提供，无需额外代码。
- `name` 已包含关键属性，面包屑可读。
- 配置关闭 symbols 时面包屑也不可用（VS Code 行为）。

### 7.4 边界场景

| 场景 | 行为 |
|---|---|
| 根不是 procedure | 所有 Provider 返回空 |
| 文档 > maxDocumentSizeKB | 语义 Provider 返回空；语法仍生效 |
| XML 畸形（未闭合标签） | 扫描器容错；符号/折叠使用已有范围 |
| CDATA 中包含 `<procedure>` | 扫描器跳过 CDATA，不误判 |
| 注释中包含 `refid` | 不索引、不补全 |
| 同名 id 多处 | 定义返回多个；引用返回全部；补全去重 |
| 未保存的新文件 | overlay 索引；同文件定义/引用可用 |
| 文件删除后仍打开 | overlay 保留，跳转用内存；关闭后失效 |
| 多根工作区 | 单一索引，URI 全局唯一 |
| 远程工作区 | `workspace.fs` 读写；watcher 不可用时降级 onSave |

## 8. TextMate 语法详细设计

### 8.1 生成物与总体结构

`syntaxes/xproc4j.injection.tmLanguage.json` 由 `tools/generate-grammar.mjs` 生成，顶层：

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/martinring/tmlanguage/master/tmlanguage.json",
  "name": "XProc4J Injection",
  "scopeName": "xproc4j.injection",
  "injectionSelector": "L:text.xml",
  "patterns": [
    { "include": "#tagRules" },
    { "include": "#dynamicSqlTopLevelNever" } // 不生成；仅注释说明动态标签不在顶层
  ],
  "repository": {
    "tagRules": { "patterns": [ /* 每个标签的规则 include */ ] },
    "variables": { "patterns": [ /* 空占位符、占位符、短变量 */ ] },
    "attrContent": { "patterns": [ /* 已知属性、通用属性对、值注入 */ ] },
    "attrContentOpen": { "patterns": [ /* 同上 + 任意参数名 */ ] },
    "sqlContent": { "patterns": [ /* 变量、动态 SQL、source.sql */ ] },
    "javaContent": { "patterns": [ /* 变量、Java 子标签、source.java */ ] },
    "jsContent": { ... },
    "tag_<name>_selfClosing": { ... },
    "tag_<name>_body": { ... },
    "tag_<name>_start": { ... },
    "tag_<name>_end": { ... }
  }
}
```

- 顶层只放 `#tagRules`；所有具体规则通过 repository 引用。
- 动态 SQL 标签规则只出现在 `#sqlContent`，不出现在顶层，避免污染 MyBatis Mapper。
- `injectionSelector` 与 `package.json` 的 `injectTo` 同时声明；S0-01 验证实际生效路径。
- 生成器保证 repository key 唯一；标签名转 key 时用 `[^A-Za-z0-9]` → `_`，冲突追加序号并断言。

### 8.3 规则架构

每个标签生成以下规则（按需）：

| 规则 | 适用 | 作用 |
|---|---|---|
| `tag_X_selfClosing` | 正文注入标签 | 匹配 `<X ... />`，着色标签/属性，不开启正文 |
| `tag_X_body` | 正文注入标签 | 匹配 `<X ...>` 到 `</X>`，正文嵌入目标语言 |
| `tag_X_start` | 所有标签 | 匹配 `<X ...>`（可跨行）到 `>`，只着色开始标签 |
| `tag_X_end` | 所有标签 | 匹配 `</X>`，着色结束标签 |

**顶层顺序**：

1. 所有 `tag_X_selfClosing`（仅注入标签）
2. 所有 `tag_X_body`
3. 所有 `tag_X_start`
4. 所有 `tag_X_end`

原因：

- 自闭合必须在正文之前，否则 `<X/>` 会开启一个永不结束的正文规则。
- 正文在开始标签之前，正常标签优先完整注入；多行开始标签使正文 `begin` 失败，才会落到 `start` 规则。
- 结束标签最后；正常正文规则已消费结束标签时不会命中。

**正文规则模板**：

```jsonc
{
  "begin": "(<)(sql-update)(?=[\\s/>])((?:[^>\"']|\"[^\"]*\"|'[^']*')*)>",
  "beginCaptures": {
    "1": { "name": "punctuation.definition.tag.begin.xproc4j" },
    "2": { "name": "entity.name.tag.xproc4j entity.name.tag.sql.xproc4j" },
    "3": { "patterns": [{ "include": "#attrContent" }] }
  },
  "end": "(</)(sql-update)(\\s*>)",
  "endCaptures": {
    "1": { "name": "punctuation.definition.tag.begin.xproc4j" },
    "2": { "name": "entity.name.tag.xproc4j entity.name.tag.sql.xproc4j" },
    "3": { "name": "punctuation.definition.tag.end.xproc4j" }
  },
  "contentName": "meta.embedded.block.sql.xproc4j",
  "patterns": [{ "include": "#sqlContent" }]
}
```

要点：

- `begin` 的属性段 `(?:[^>"']|"[^"]*"|'[^']*')*` 能容忍属性值中的 `>` 与单/双引号；不能跨行（Oniguruma 按行匹配）。
- `beginCaptures[3]` 用 `#attrContent` 重新分词属性；S0-02 验证；未通过则移除该 capture 的 patterns，属性退化为纯文本（Fallback）。
- 正文 `contentName` 先给 `meta.embedded...`，再由 `include` 目标语法叠加目标 scope。
- `end` 必须匹配同名标签；不支持同名嵌套（XProc 不应出现）。
- 正文中的结束标签若出现在 SQL 字符串/注释中，仍会被提前结束；这是 TextMate 的固有限制，记录为已知限制。

**自闭合规则模板**：

```jsonc
{
  "match": "(<)(sql-update)(?=[\\s/>])((?:[^>\"']|\"[^\"]*\"|'[^']*')*)/>",
  "captures": {
    "1": { "name": "punctuation.definition.tag.begin.xproc4j" },
    "2": { "name": "entity.name.tag.xproc4j entity.name.tag.sql.xproc4j" },
    "3": { "patterns": [{ "include": "#attrContent" }] },
    "4": { "name": "punctuation.definition.tag.end.xproc4j" }
  }
}
```

**开始标签规则模板**：

```jsonc
{
  "begin": "(<)(sql-update)(?=[\\s/>])",
  "beginCaptures": {
    "1": { "name": "punctuation.definition.tag.begin.xproc4j" },
    "2": { "name": "entity.name.tag.xproc4j entity.name.tag.sql.xproc4j" }
  },
  "end": "(/?>)",
  "endCaptures": { "1": { "name": "punctuation.definition.tag.end.xproc4j" } },
  "patterns": [{ "include": "#attrContent" }]
}
```

- 该规则可跨行匹配开始标签（`begin` 只到标签名，`end` 是 `>`），因此多行属性仍能着色。
- 它不消费正文，正文由宿主 XML 或其它注入规则处理。
- 对正文注入标签，它是 Fallback；对普通标签，它是唯一结构规则。

**结束标签规则模板**：

```jsonc
{
  "match": "(</)(sql-update)(\\s*>)",
  "captures": {
    "1": { "name": "punctuation.definition.tag.begin.xproc4j" },
    "2": { "name": "entity.name.tag.xproc4j entity.name.tag.sql.xproc4j" },
    "3": { "name": "punctuation.definition.tag.end.xproc4j" }
  }
}
```

**`#attrContentOpen`**：在 `#attrContent` 基础上，把 `#attrNoValue` 之前加入 `#paramAttrNamePair`/`#paramAttrName`，使未知属性名得到 `entity.other.attribute-name.xproc4j`（与普通属性同名 scope，保持颜色一致）。

**通用属性对**（双引号）：

```jsonc
{
  "begin": "([A-Za-z_][\\w.:-]*)(\\s*=\\s*)(\")",
  "beginCaptures": {
    "1": {
      "name": "entity.other.attribute-name.xml",
      "patterns": [
        { "include": "#knownAttrName" },
        { "include": "#paramAttrName" }   // 仅 open 版本包含
      ]
    },
    "2": { "name": "punctuation.separator.key-value.xml" },
    "3": { "name": "punctuation.definition.string.begin.xml" }
  },
  "end": "(\")",
  "endCaptures": { "1": { "name": "punctuation.definition.string.end.xml" } },
  "contentName": "string.quoted.double.xml",
  "patterns": [{ "include": "#attrValueContent" }]
}
```

单引号版本同理；`#attrNoValue` 处理 `<tag foo>` 这类无值属性。

**已知属性名**：

```jsonc
{
  "match": "\\G((?:id|refid|result|value|_lang|__file|__line|datasource|propagation|...)(?:\\.(?:in|out|int|...|cause-root))*)(?=\\s*=)",
  "captures": {
    "1": {
      "name": "entity.other.attribute-name.xproc4j",
      "patterns": [
        {
          "match": "\\.[A-Za-z0-9_-]+",
          "name": "entity.other.attribute-name.feature.xproc4j"
        }
      ]
    }
  }
}
```

- 基础名交替表来自 `attributes.json` + builtin，按长度降序，避免 `value` 抢先匹配 `value-body`（实际由分隔符/`(?=\s*=)` 保证）。
- feature 后缀只匹配已知 58 个（生成交替表），避免把任意后缀当 feature。
- `\G` 确保从 capture 起点整名匹配；若 `\G` 在内嵌 capture 中行为异常（S0-02），改用 `^` + 整 token 约束或去掉 `\G` 依赖长度排序。
- 未匹配的已知标签内的未知属性保持 `entity.other.attribute-name.xml`（与 XML 默认一致）。

**开放标签参数名**：

```jsonc
{
  "match": "\\G([A-Za-z_][\\w.:-]*)(?=\\s*=)",
  "captures": {
    "1": {
      "name": "entity.other.attribute-name.xproc4j",
      "patterns": [
        { "match": "\\.[A-Za-z0-9_-]+", "name": "entity.other.attribute-name.feature.xproc4j" }
      ]
    }
  }
}
```

- 只在 `#attrContentOpen` 中；已知属性规则在前，未声明/开放参数仍统一显示为属性名色。早期版本使用 `variable.parameter.xproc4j`，在 VS Code Light 下为橙色，与普通属性红色不一致，已废弃。

**值规则模板**（以 propagation 为例）：

```jsonc
{
  "begin": "(propagation)(\\s*=\\s*)(\")",
  "beginCaptures": {
    "1": { "name": "entity.other.attribute-name.xproc4j" },
    "2": { "name": "punctuation.separator.key-value.xml" },
    "3": { "name": "punctuation.definition.string.begin.xml" }
  },
  "end": "(\")",
  "endCaptures": { "1": { "name": "punctuation.definition.string.end.xml" } },
  "contentName": "string.quoted.double.xml",
  "patterns": [
    {
      "match": "\\b(REQUIRED|SUPPORTS|MANDATORY|REQUIRES_NEW|NOT_SUPPORTED|NEVER|NESTED)\\b",
      "name": "constant.language.propagation.xproc4j"
    },
    { "include": "#variables" }
  ]
}
```

- 每个值类型生成双引号/单引号两个版本；`begin` 的属性名需要含 feature 链时用 `([A-Za-z_][\w-]*(?:\.[\w-]+)*)`，再在 captures 中嵌套 feature（对 `_lang` 等固定名不需要）。
- `isolation` 的值匹配同时接受带/不带 `TRANSACTION_` 前缀：正则 `(?:TRANSACTION_)?(?:NONE|READ_UNCOMMITTED|READ_COMMITTED|REPEATABLE_READ|SERIALIZABLE)`。
- `jdbc-type` 用 39 个名称的交替；`time-unit` 7 个；`database`/`datasource` 支持多值：值模式 `(?:mysql|oracle|...)(?:\s*[,;|/]\s*(?:mysql|...))*`，每个值单独 scope。
- `_lang` 用语言 ID 交替，多值分隔符同上。
- `boolean` 匹配 `true|false`；`.boolean` feature 也走该规则（属性名正则允许点）。
- `numeric` 匹配 `-?\d+(?:\.\d+)?` 与 `0x[0-9A-Fa-f]+`；`radix` 单独。
- `date-pattern` 不做特殊 token；整个值保持字符串 scope；补全提供模板。
- `method` 匹配 21 个方法名 + 点号成员，scope `entity.name.function.xproc4j`。
- `typeName` 匹配点分标识符 → `entity.name.type.xproc4j`；`package` 属性 → `entity.name.namespace.xproc4j`；通配符 `*` → `punctuation`.
- `test`/`collection`：`#attrTestCollection` 内容模式为变量、字符串、数字、运算符；不引入 OGNL 语法。
- `*.eval-java`：属性名正则 `[A-Za-z_][\w-]*(?:\.[\w-]+)*\.eval-java`；`contentName: meta.embedded.attribute.java.xproc4j`；patterns `#variables` + `{include: source.java}`。
- `*.eval-js` / `*.eval-groovy` 同理。
- `*.render`：通用属性对，值内只变量，不注入。
- 未知值：通用属性对 → `string.quoted...` + `#attrValueContent`（变量、数字、布尔？设计只变量 + 数字，避免把普通单词染成常量）。

**`#attrValueContent`**：

```jsonc
{
  "patterns": [
    { "include": "#variables" },
    { "match": "\\b(?:true|false)\\b", "name": "constant.language.boolean.xproc4j" },
    { "match": "-?\\d+(?:\\.\\d+)?", "name": "constant.numeric.xproc4j" }
  ]
}
```

- 这会把任意属性值中的 `true`/数字着色；可接受，且与框架语义一致（属性值最终会被解析为字符串/数值）。
- 空占位符规则在 `#variables` 内优先，使用 `invalid.illegal`。

### 8.5 正文注入映射

生成表（与 FR-03 对应）：

| 标签 | 规则 | `contentName` | 目标 scope | 附加 |
|---|---|---|---|---|
| `sql-query-list`、`sql-query-row`、`sql-query-object`、`sql-query-columns`、`sql-update`、`sql-dialect`、`sql-script` | `body` | `meta.embedded.block.sql.xproc4j` | `source.sql` | `#sqlContent`（动态 SQL） |
| `lang-eval-java` | `body` | `meta.embedded.block.java.xproc4j` | `source.java` | `#javaContent`（Java 子标签） |
| `lang-java-import`、`lang-java-member`、`lang-java-body` | `body` | 同上 | `source.java` | `#javaContent` |
| `lang-eval-javascript`、`lang-eval-js` | `body` | `meta.embedded.block.javascript.xproc4j` | `source.js` | 变量 |
| `lang-eval-groovy` | `body` | `meta.embedded.block.groovy.xproc4j` | `source.groovy` | 变量；缺失时退化 |
| `lang-shell` | `body` | `meta.embedded.block.shell.xproc4j` | `source.shell` | 变量 |
| `lang-string`、`lang-render` | 默认 `body` | 无（仅变量） | — | `#variables`；`_lang` 变体见 8.6 |
| `lang-eval`、`lang-eval-ts`、`lang-eval-tinyscript`、`lang-eval-funic` | `body` | 无 | — | `#variables`（仅变量，不注入 DSL） |
| 动态 SQL 标签 | 仅 `#sqlContent` 内 | `meta.embedded.block.sql.xproc4j` | `source.sql` | 递归 `#sqlContent` |

**`#sqlContent`**：

```jsonc
{
  "patterns": [
    { "include": "#variables" },
    { "include": "#sql-nested-self-sql-dialect" },
    { "include": "#sql-nested-body-sql-dialect" },
    { "include": "#sql-nested-name-sql-dialect" },
    { "include": "#dynamicSqlSelfClosing" },
    { "include": "#dynamicSqlBody" },
    { "include": "#dynamicSqlStart" },
    { "include": "#dynamicSqlEnd" },
    { "include": "source.sql" }
  ]
}
```

- 动态标签在 SQL 之前匹配，避免 `<` 被 SQL 当作运算符；动态标签正文继续 `#sqlContent`。
- `sql-dialect` 是 SQL 正文里的 XML 子标签（`sql-query-object` 内按数据库分派），必须排在 `source.sql` 之前；否则 SQL 语法会把 `<sql-dialect` 解析为比较符/标识符，标签名与属性失去 XML scope。其规则与普通标签一致：自闭合、正文、结束标签三条。
- `source.sql` 缺失时，正文仍带 meta + 变量色；S0-08。

**`#javaContent`**：

```jsonc
{
  "patterns": [
    { "include": "#variables" },
    { "include": "#javaChildSelfClosing" },
    { "include": "#javaChildBody" },
    { "include": "#javaChildStart" },
    { "include": "#javaChildEnd" },
    { "include": "source.java" }
  ]
}
```

- Java 子标签规则与顶层同名标签规则相同，但只生成 `lang-java-import/member/body` 三个，避免在 Java 正文中误匹配其它标签。
- `lang-eval-java` 自身正文启动 Java；子标签正文再次启动 Java（嵌套一层），可接受。
- Java 正文中的 `</lang-eval-java>` 会结束外层；子标签结束标签不会误结束外层，因为名称不同。

**JS/Groovy/Shell/其它**：`#variables` + 目标语法；无子标签。

**排除注入**：

- `lang-body`、`lang-catch`、`lang-finally`、`script-segment`、`lang-synchronized`、`lang-async`、`sql-scope`、`sql-cursor`、`sql-etl`、`sql-transactional` 不生成 `body` 规则，只生成 `start`/`end`。
- 这些标签的正文由宿主 XML 处理，子标签各自注入。
- 若这些标签嵌套在 SQL 正文中，SQL 语法会把它们当文本；这是已知限制（框架通常将其作为顶层容器）。

### 8.6 `_lang` 动态正文

**支持范围**：

- 仅 `lang-string`、`lang-render`。
- 原因：TextMate 规则无法在运行期读取当前标签的 `_lang` 再切换语法；必须为“标签 × 语言”预生成规则。若对所有 111 个标签 × 16 种语言生成，规则数约 1,776，语法体积与启动成本不可接受。
- `_lang` 属性本身的补全/高亮对所有标签生效；只是“正文按 `_lang` 注入”限制在这两个通用内容标签。
- 需求 FR-03 的 `_lang` 任意标签属于平台能力上限内的裁剪，记录为 DD-014 与已知限制；如后续需要，可按标签白名单增量生成。

**规则生成**：

对每个语言值别名，生成一条 `body` 规则，`begin` 在标签名后使用 lookahead 检查同一行开始标签内是否包含 `_lang` 值：

```jsonc
{
  "begin": "(<)(lang-string)(?=[^>]*\\b_lang\\s*=\\s*[\"'][^\"']*(?:sql)[^\"']*[\"'])((?:[^>\"']|\"[^\"]*\"|'[^']*')*)>",
  "beginCaptures": { "...": "..." },
  "end": "(</)(lang-string)(\\s*>)",
  "contentName": "meta.embedded.block.sql.xproc4j",
  "patterns": [{ "include": "#sqlContent" }]
}
```

- 语言优先级：`sql`、`java`、`javascript/js`、`json`、`xml`、`yaml`、`shell/bash`、`css/sass`、`markdown/md`、`regex/regexp`、`groovy`、`vtl/velocity`、`freemarker`、`thymeleaf`、`spel/el/expr`、`typescript`。
- 规则按优先级排列，先匹配者生效；多值 `_lang="java,sql"` 时 java 优先（与参考实现的“第一个可识别项”不完全一致，文档记录）。
- `_lang` 必须在开始标签同一行；跨行写法不保证（TextMate 行匹配限制）。
- 默认 `lang-string`/`lang-render` 的 vars-only 规则排在所有 `_lang` 变体之后，确保没有 `_lang` 时仍消费正文并着色变量。

### 8.7 动态 SQL 标签

标签集合（14 个）：`if`、`where`、`set`、`trim`、`foreach`、`choose`、`when`、`otherwise`、`bind`、`include`、`dialect`、`dialect-choose`、`dialect-when`、`dialect-otherwise`。

生成规则：

- 自闭合 match、正文 begin/end、fallback start、end。
- 正文 `contentName: meta.embedded.block.sql.xproc4j`，patterns `#sqlContent`。
- 属性使用 `#attrContent`；`test`/`collection` 走表达式；`refid` 在 `include`/`dialect` 上语义 token 着色。
- 标签名 scope：`entity.name.tag.xproc4j entity.name.tag.dynamic.xproc4j`。
- 只在 `#sqlContent` 中引用，不在顶层。

`<if>` 等标签在 MyBatis Mapper 中不会被本扩展匹配，因为顶层没有动态规则，Mapper 也不是 XProc 文件（无 `procedure` 根）；即使根是 procedure，动态标签也只在 SQL 正文内。

### 8.8 变量规则（TextMate 降级）

```jsonc
{
  "patterns": [
    {
      "match": "[#$]!?\\{\\s*\\}",
      "name": "invalid.illegal.xproc4j"
    },
    {
      "match": "[#$]!?\\{[^{}]*\\}",
      "name": "support.variable.xproc4j"
    },
    {
      "match": "\\$[A-Za-z0-9_]+",
      "name": "support.variable.xproc4j"
    }
  ]
}
```

- 只在注入正文的 `patterns` 中使用；不做全局变量规则，避免污染普通 XML。
- 使用 `support.variable.xproc4j`：在 VS Code Light 2026 下解析为蓝色 `#0550AE`，与括号/标点一致，符合用户对醒目度的要求；`variable.other` 会退化为正文色，`variable.parameter` 偏橙，均不采用。
- 空占位符优先；`${}`、`$!{}`、`#{}`、`#!{}` 均匹配。
- `$name` 短变量匹配；`#name` 不匹配（需求只要求 `$name`）。
- 语义 token 开启时，变量颜色以语义 token 为准；规则保留用于降级。
- 变量在 SQL 字符串内可能被目标语法先消费；语义 token 覆盖。

### 8.9 语法体积与加载

- 预估规则数：111 标签 × 平均 2 条 + 注入标签额外 2 条 + 动态 14 × 4 + 属性 20 + 正文 10 ≈ 600 条；JSON 约 300~500 KB。
- `vscode-textmate` 按需编译正则；首次 tokenization 可能 10~30 ms；语法加载发生在 XML 文档打开时。
- 生成器输出后运行 `node -e "JSON.parse(...)"` 与 `vscode-textmate` 加载测试；若单条正则长度 > 20 KB，拆分或改用 `include`。
- 不使用嵌套量词 `(a+)+`；属性段正则使用互斥分支，降低回溯。
- 生成文件必须为有效 JSON（无注释、无尾逗号）；`report.md` 记录规则数与最大正则长度。

### 8.10 S0 实验与 Fallback 细化

| 实验 | 最小原型 | 结论落点 |
|---|---|---|
| S0-01 跨语法 include | 宿主 stub + 注入规则 + `source.sql` stub | 若失败：正文只保留 `contentName`，不 include；FR-03 降级 |
| S0-02 capture 重分词 | `<sql-update result="x">` 断言属性 scope | 若失败：去掉 `beginCaptures[3].patterns`，属性交给宿主/语义 token |
| S0-03 污染 | POM/Spring/MyBatis token diff | 若失败：移除标签名规则中非 XProc 专属项 |
| S0-04 Snippet 触发 | 输入 `<sql-query-list` | 若失败：Provider 模式 |
| S0-05 semanticTokenScopes | 空占位符颜色 | 若失败：只靠 TextMate invalid scope |
| S0-06 自闭合 | `<sql-update/>` + 后续 XML | 若失败：禁用该标签正文注入 |
| S0-07 多行开始标签 | 多行 fixture | 接受降级，文档记录 |
| S0-08 缺失语法 | 无 Groovy | 接受降级，文档记录 |

### 8.11 已知语法限制

1. 多行开始标签不注入正文，只着色开始标签/属性；`_lang` 跨行不生效。
2. 正文注入标签的属性级语言注入依赖 S0-02；失败时属性只保留基础 XML scope。
3. SQL/Java 字符串或注释中包含 `</tag>` 会提前结束正文；XML 本身也不允许这种写法，影响有限。
4. 同名标签嵌套不支持（XProc 结构不应出现）。
5. `_lang` 正文注入仅 `lang-string`/`lang-render`；其它标签固定映射。
6. 第三方语法未安装时正文退化为纯文本/变量色；不报错。
7. 语法静态生效，`xproc4j.enable=false` 不能关闭高亮；文档明确。
8. 变量在正文中的 TextMate 降级可能受目标语法字符串规则影响；语义 token 是主路径。
9. 嵌套在 SQL 正文中的排除容器（如 `sql-scope`）不会被识别为 XML；框架通常不这样写。
10. 主题对自定义 scope 的配色差异；提供示例配置，不保证所有主题一致。

## 9. Snippets 与新建文件

### 9.1 生成物与数据流

```
tools/sources/XProc4j.xml                 手写输入：90 个 IDEA Live Template
        │  idea-template-parser.mjs（容错、计数断言）
        ▼
统一模型（prefix/body/description/sourceName）
        │  snippet-builder.mjs + convert-snippets.mjs
        ├──────────────► snippets/xproc4j.code-snippets   原生 Snippets（运行期唯一来源）
        └──────────────► metadata/snippets.json → src/generated/metadata.ts
                                                          METADATA.snippets（目录数据，不注册 Provider）
```

统一模型：

```ts
export interface SnippetDefinition {
  prefix: string;          // 含前导 '<'，如 '<sql-query-list'
  description: string;     // 中文描述
  body: string;            // 已转义的 VS Code Snippet 文本
  sourceName: string;      // IDEA 模板名，用于报告与排错
}
```

- S0-04 已通过：`contributes.snippets` 指向原生片段文件，运行期不注册 Snippet Provider，也不存在 `src/generated/snippets.ts`。
- `metadata/snippets.json` 是构建期中间产物，由 `gen:module` 并入 `src/generated/metadata.ts` 的 `METADATA.snippets`；该数据当前只用于元数据完整性与测试，不参与补全。
- `snippets/xproc4j.code-snippets` 与 `METADATA.snippets` 均来自同一次 `convert-snippets.mjs` 转换，模板数（90）与前缀集合在生成期断言。
- `metadata/snippets.json` 不随 VSIX 发布；发布物包含原生片段文件与打包后的 JS。

### 9.2 IDEA Live Template 转换规则

**输入事实（已核对，构建期断言）**：

| 项 | 数量 | 说明 |
|---|---|---|
| 模板数 | 90 | `name` 全部以 `<` 开头，无空格，无重名 |
| 变量声明 | 187 | 全部 `alwaysStopAt="true"` |
| 空表达式变量 | 183 | `expression=""` |
| 宏表达式变量 | 4 | 2×`concat(fileName(),":",lineNumber())`、1×`fileNameWithoutExtension()`、1×`concat("error at ",fileName(),":",lineNumber())` |
| `$END$` | 89 个模板各 1 次 | `<lang-thread-pool` 没有 `$END$` |
| 空默认值 | 97 个 `defaultValue="&quot;&quot;"` + 4 个 `defaultValue=""` | 均视为“无默认值” |
| 空 context | 62 | 在 IDEA 中为全局；迁移后统一限定 `xml` |
| XML context | 28 | 与迁移目标一致 |

**逐项转换**：

| IDEA | VS Code | 规则 |
|---|---|---|
| `name="&lt;sql-query-list"` | `prefix: "<sql-query-list"` | XML 实体解码；保持大小写 |
| `value="..."` | `body` | XML 实体解码（`&#10;`→换行）；保留原始缩进与空行 |
| `$END$` | `$0` | 只允许 0 或 1 次；缺失时不补 |
| `$VAR$` 首次出现 | `${n:default}` 或 `${n}` | `n` 从 1 开始，按首次出现顺序分配 |
| `$VAR$` 再次出现 | `${n}` | 同一变量镜像同一 tabstop；默认值只写在首次出现处 |
| 默认值 `"text"` | `text` | 去掉最外层一对引号；`\"` 还原为 `"`；其余字符不解释 |
| 默认值 `""` / 缺失 | 无默认值 | 生成空占位符 `${n}` |
| `expression="fileNameWithoutExtension()"` | `$TM_FILENAME_BASE` | 直接内联变量，不占 tabstop |
| `expression="concat(fileName(),\":\",lineNumber())"` | `$TM_FILENAME:$TM_LINE_NUMBER` | 整段替换为内联变量串 |
| `expression="concat(\"error at \",fileName(),\":\",lineNumber())"` | `error at $TM_FILENAME:$TM_LINE_NUMBER` | 保留字面前缀 |
| 未知 `expression` / 未声明 `$VAR$` / 残留 `$` | 构建失败 | 报告模板名与变量名；禁止静默生成错误占位符 |

**转义顺序（关键）**：

1. 先按 XML 解析得到原始文本（实体已解码）。
2. 扫描 `$END$` 与 `$VAR$`，把变量替换为占位符 token（此时不转义占位符自身的 `$`）。
3. 对其余字面文本做 Snippet 转义：`\`→`\\`、`$`→`\$`、`}`→`\}`。
4. 对默认值单独做同样的字面转义，再放入 `${n:...}`。
5. 拼装后再次扫描“未被识别为占位符的 `$`”；若有，构建失败（当前 90 个模板预期为 0）。

> 不能先转义再替换，否则 `$VAR$` 会变成字面量；也不能对默认值里的引号做额外处理，`params_share="true"` 本身是合法片段文本。

**示例**：

源模板 `<function-call`：

```xml
<function-call refid="$ID$" result="$RESULT$" $PARAM_SHARE$
    $PARAMS$ $ATTR$/>
$END$
```

生成 body（JSON 中的字符串，此处按行展示）：

```text
<function-call refid="${1}" result="${2}" ${3:params_share="true"}
    ${4:params="callParams"} ${5}/>
$0
```

源模板 `<debugger`：

```text
<debugger tag="$TM_FILENAME:$TM_LINE_NUMBER" test="${1:true}"/>
$0
```

**输出格式**：

```jsonc
{
  "XProc4J 片段：<sql-query-list>": {
    "prefix": "<sql-query-list",
    "body": [
      "<sql-query-list result=\"${1}\">",
      "    $0",
      "</sql-query-list>"
    ],
    "description": "XProc4J 片段：<sql-query-list>",
    "scope": "xml"
  }
}
```

- 顶层 key 使用 `XProc4J 片段：<prefix>`，保证唯一且可读；`prefix` 才是触发文本。
- `scope: "xml"` 避免污染其它语言。
- 缩进保留模板原文；VS Code 插入时按当前行缩进自动调整。
- JSON 使用 2 空格缩进、UTF-8 无 BOM、LF 换行；由 `json-writer.mjs` 统一输出。

**构建期校验**：

- 模板数 = 90；prefix 唯一；每个 prefix 以 `<` 开头且无空白。
- 变量声明数 = 187；4 个宏表达式全部命中白名单。
- `$END$` 出现 89 次；`<lang-thread-pool` 必须无 `$END$`。
- 每个 body 的 tabstop 编号连续（1..max，允许 `$0`），且同一变量的多次出现索引一致。
- 每个 body 不含未转义的 `$`（`$0`/`${n...}` 与白名单内联变量除外）。
- `<procedure` 条目必须与 9.3 的覆盖内容逐字节一致。
- 源文件 SHA256 与 `tools/sources/SHA256SUMS.json` 一致。

### 9.3 `<procedure` 专用骨架

参考模板中的 `<procedure` 只有 `id`、`$ATTR$` 与空正文，不满足 FR-07 对 DOCTYPE、作者/日期注释的要求。转换器对该条目做**唯一覆盖**：

```text
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE procedure SYSTEM "procedure.dtd">

<procedure id="${1:procedure}">
    <!--

    @author ${2}
    @date $CURRENT_YEAR-$CURRENT_MONTH-$CURRENT_DATE
    @time $CURRENT_HOUR:$CURRENT_MINUTE:$CURRENT_SECOND
    -->

    $0
</procedure>
```

- 其余 89 个模板不做结构改写；仅对拼写明显错误的占位符名做映射（见下表），映射同时作用于模板正文与 `<variable>` 声明，并在转换报告中列出。
- 该骨架用于“文件起始”。若用户在已有根元素内触发，XML 声明/DOCTYPE 会出现在正文中，语义功能会将其视为错误结构；README 提示“在文件开头使用，或删去前两行”。
- `$CURRENT_*` 为 VS Code 内置 Snippet 变量，插入时求值；不依赖扩展运行期代码。
- 日期变量均为两位数；`$CURRENT_YEAR` 为四位。

**拼写修正表（仅占位符名）**：

| 原变量 | 修正为 | 模板 | 出现位置 |
|---|---|---|---|
| `DATASURCE` | `DATASOURCE` | `<etl-load` | `datasource="$DATASOURCE$"` |
| `FEATUERE` | `FEATURE` | `<lang-do-while` | `test$FEATURE$="$TEST$"` |

> 修正只影响占位符名与 Tab 顺序中的显示，不改变生成的 XML 结构；报告中必须列出修正项，便于对照 IDEA 行为。

### 9.4 S0-04：原生 Snippets（已定稿）

**最终实现**：

- `contributes.snippets` 指向 `snippets/xproc4j.code-snippets`，`scope: "xml"`。
- 不注册同前缀的 CompletionItemProvider，避免候选重复。
- 原生片段作用域是 `xml`，无法按根节点门控；POM/Spring/MyBatis 等普通 XML 的 `<` 建议中可能看到片段候选，但不会自动插入，用户可在 VS Code 的片段设置中禁用。该行为符合 FR-07 的验收约定。
- 用户可在 VS Code 的“配置用户代码片段”中禁用整个文件；这是需求允许的关闭方式。

**未采用的备选方案（S0-04 失败时曾计划）**：

- 删除 `contributes.snippets` 段，改为注册 `CompletionItemProvider`，自行计算 `filterText`、`range` 与 `sortText`。
- S0-04 实测原生片段可在 XML 中输入 `<` 触发并按 `xml` 限定，因此未启用该方案；代码与生成物中均无对应实现。

**验收**：90 个前缀可发现、插入结构完整、Tab 顺序与 9.2 一致、`<procedure` 骨架正确。

### 9.5 新建 Procedure 文件命令

**命令**：`xproc4j.createProcedureFile`，标题 `XProc4J: 新建 Procedure 文件`。

**入口**：

| 入口 | 参数 | 说明 |
|---|---|---|
| 命令面板 | 无 | 默认工作区根目录 |
| 资源管理器右键（文件夹） | 文件夹 `Uri` | `explorerResourceIsFolder` |
| 资源管理器右键（文件） | 文件 `Uri` | 取其父目录（附加便利，不额外加菜单项） |
| 编辑器标题 | 不提供 | 需求为可选；本期不做，减少误触 |

**流程与 API**：

```
createProcedureFile(arg?: Uri):
  1. dir = resolveDirectory(arg)          // 取消 → return
  2. id = await showInputBox({ prompt, value: 'procedure', validateInput })
                                          // 取消 → return
  3. fileName = await showInputBox({ prompt, value: `${id}.xml`, validateInput })
                                          // 取消 → return
  4. target = joinPath(dir, fileName)
  5. exists = await stat(target) 成功?
       是 → showWarningMessage('文件已存在，是否覆盖？', { modal: true }, '覆盖')
            未选择“覆盖” → return
  6. content = renderProcedureTemplate({ id, author, date, time, eol })
  7. applied = await applyWorkspaceEdit(createFile + insert)
       失败 → showErrorMessage，return
  8. await showTextDocument(target, { preview: false })
```

**目录解析**：

```ts
async function resolveDirectory(arg?: vscode.Uri): Promise<vscode.Uri | undefined> {
  if (arg) {
    const stat = await vscode.workspace.fs.stat(arg).catch(() => undefined);
    if (stat?.type === vscode.FileType.Directory) return arg;
    if (stat?.type === vscode.FileType.File) return vscode.Uri.joinPath(arg, '..');
  }
  const folders = vscode.workspace.workspaceFolders ?? [];
  if (folders.length === 1) return folders[0].uri;
  if (folders.length > 1) {
    const picked = await vscode.window.showQuickPick(
      folders.map((f) => ({ label: f.name, description: f.uri.fsPath, uri: f.uri })),
      { placeHolder: '选择目标工作区文件夹' }
    );
    return picked?.uri;
  }
  const picked = await vscode.window.showOpenDialog({
    canSelectFiles: false, canSelectFolders: true, canSelectMany: false,
    openLabel: '选择目标目录'
  });
  return picked?.[0];
}
```

- 不调用 `createDirectory`：目标来自已存在的文件夹或工作区根；若目录在流程中被删除，写入会失败并提示。
- 多根工作区必须显式选择，不使用“第一个”作为隐式默认。

**id 校验**：

| 规则 | 提示 |
|---|---|
| `trim()` 后非空 | `请输入 procedure id` |
| 长度 ≤ 128 | `id 不能超过 128 个字符` |
| 不含空白、控制字符 | `id 不能包含空白或控制字符` |
| 不含 `< > & " ' / \` | `id 不能包含 < > & " ' / \` |
| 不以 `.` 开头 | `id 不能以点开头` |

- 允许中文、字母、数字、`_`、`-`、`.`；不做 XML Name 严格校验（id 是属性值，不是元素名）。
- id 仅用于 `<procedure id="...">`，不直接拼路径；文件名单独校验。

**文件名校验**：

| 规则 | 提示 |
|---|---|
| `trim()` 后非空 | `请输入文件名` |
| 不含 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` | `文件名不能包含路径分隔符或非法字符` |
| 不是 `.` / `..` | `文件名无效` |
| 不以空格或点结尾 | `文件名不能以空格或点结尾` |
| 无扩展名时自动补 `.xml` | 输入框下方提示“将保存为 xxx.xml” |
| 扩展名不是 `.xml` | 拒绝：`XProc4J 文件必须使用 .xml 扩展名` |

- 使用 `path.posix`/`path.win32` 的 `basename` 双重检查，确保 `basename(fileName) === fileName`；杜绝 `../`。
- 文件名长度交给文件系统；`EEXIST`/`ENAMETOOLONG` 等错误统一提示。

**覆盖确认**：

- `showWarningMessage(..., { modal: true }, '覆盖')`；不提供“另存为”分支，用户可取消后重新执行。
- 默认按钮为“取消”（VS Code modal 只有显式项可点；按 Esc 返回 `undefined`）。
- 需求中的“不覆盖”解释为“不静默覆盖”；用户明确选择“覆盖”后才写入。

### 9.6 模板渲染器

**模板源**：`templates/procedure.xml.tpl`（唯一手写源），内容：

```text
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE procedure SYSTEM "procedure.dtd">

<procedure id="{{id}}">
    <!--

    @author {{author}}
    @date {{date}}
    @time {{time}}
    -->

</procedure>
```

- `gen:module` 读取该文件，生成 `src/generated/procedure-template.ts`（导出常量字符串）；运行期零文件 I/O，`gen:check` 校验生成物与源文件一致。
- 生成器中把 CRLF 归一化为 `\n`，避免仓库换行设置影响输出。

**纯函数**：

```ts
export interface ProcedureTemplateParams {
  id: string;
  author: string;
  date: string;   // YYYY-MM-DD
  time: string;   // HH:mm:ss
  eol: '\n' | '\r\n';
}

export function renderProcedureTemplate(
  template: string,
  params: ProcedureTemplateParams
): string;
```

规则：

1. 单次扫描 `/\{\{(\w+)\}\}/g`；未知占位符抛 `TemplatePlaceholderError`（构建期测试覆盖；运行期由命令捕获并提示）。
2. `id` 做 XML 属性转义（`& < > " '`）；虽然校验已禁止这些字符，仍做防御。
3. `author` 仅用于 XML 注释：移除 `--`（替换为 `- -`）、`-->`、换行、控制字符；`trim()` 后为空则写 `unknown`；最长 64 字符。
4. `date`/`time` 由 `Clock` 生成，零填充；不依赖系统 locale。
5. 转义后再把 `\n` 替换为 `eol`；文件以单个 `eol` 结尾。
6. 不修改缩进：固定 4 空格，与参考文件模板一致。

**作者与时间**：

```ts
export interface Clock { now(): Date; }

function resolveAuthor(fallback = 'unknown'): string {
  try {
    return os.userInfo().username || fallback;
  } catch {
    return process.env.USER || process.env.USERNAME || fallback;
  }
}
```

- 远程/容器工作区取扩展宿主所在机器的用户名，符合“作者=当前环境用户”的直觉。
- 不把作者写入日志；只在生成的文件中出现。

**EOL 选择**：

```ts
const filesEol = workspace.getConfiguration('files', target).get<'auto' | '\n' | '\r\n'>('files.eol');
const eol = filesEol === '\r\n' ? '\r\n' : '\n';
```

- `auto` 在桌面端按操作系统换行；Windows 上 VS Code 通常写 CRLF。测试直接传 `eol`，不依赖平台。
- XML 声明中的 `UTF-8` 是编码声明，不随 EOL 改变。

### 9.7 写入、覆盖与错误

**写入策略**：`WorkspaceEdit` 创建文件并插入全文，保留撤销能力（DD-021）。

```ts
const edit = new vscode.WorkspaceEdit();
edit.createFile(target, { overwrite: true, ignoreIfExists: false });
edit.insert(target, new vscode.Position(0, 0), content);
const applied = await vscode.workspace.applyEdit(edit);
if (!applied) throw new Error('无法写入文件（工作区文件系统拒绝编辑）');
```

- 新文件与覆盖都走同一路径；覆盖时 `overwrite: true` 会替换内容。
- 先 `createFile` 再 `insert`，避免“文件存在但内容为空”的中间态在编辑历史中留下两次撤销步骤；编辑器最终只看到一次应用。
- 若目标文件系统不支持 `WorkspaceEdit`（极少见），命令失败并提示“请检查目录写入权限或文件系统能力”；不回退到静默 `fs.writeFile`。
- 写入前再次 `stat` 目标（防止用户在确认后、写入前创建同名文件）；若出现竞态且用户未确认覆盖，则中止并提示。

**错误矩阵**：

| 场景 | 行为 |
|---|---|
| 目录只读/权限不足 | 错误提示：`无法创建文件：权限不足`；日志记录 URI 与错误码 |
| 目录已删除 | 提示重新选择目录；不自动创建 |
| 文件名过长 | 提示缩短文件名；保留输入框内容供复制 |
| 文件系统不支持编辑 | 提示具体错误；不写半成品 |
| 模板占位符缺失 | 内部错误；提示“模板损坏，请反馈”；日志记录缺失键名 |
| 命令执行中窗口关闭/取消 | 在每一步检查 `undefined`；已应用编辑不回滚（用户可撤销） |

- 错误信息使用 `showErrorMessage(message, '显示输出')`，选择后打开 `XProc4J` 输出通道。
- 不在错误弹窗中展示完整路径以外的文档内容。

### 9.8 安全、兼容与验收

**安全**：

- 目标路径只能来自用户选择的目录 + 通过校验的 basename；不使用输入框拼接目录。
- `id` 与 `author` 均做上下文转义；`author` 额外清理 XML 注释非法序列。
- 不创建 `procedure.dtd`、不访问网络、不执行模板内容。
- 模板写入是唯一副作用；取消任一步骤不产生文件或目录。

**兼容**：

- 远程/虚拟工作区：`workspace.fs` 与 `WorkspaceEdit` 均通过 FileSystemProvider，不假设 `file://`。
- Windows：文件名非法字符、保留名（`CON`、`PRN` 等）由文件系统报错；命令捕获并提示。
- 大小写不敏感文件系统：存在性检查使用 VS Code FileSystemProvider，避免自行 `toLowerCase` 比较导致误判。

**验收映射**：

| 需求验收 | 设计落点 |
|---|---|
| 空目录执行命令，生成文件可被识别并启用全部功能 | 9.6 模板包含 XML 声明/DOCTYPE/`procedure` 根；Gate 按根节点识别 |
| 取消任一步骤不产生文件 | 9.5 流程每步 `undefined` 直接 return；写入只在最后一步 |
| 已存在同名文件时提示确认，拒绝后不修改 | 9.5 覆盖确认；默认取消 |
| 90 个模板可通过前缀触发，结构完整、可折叠、可继续补全 | 9.2 转换 + 9.3 覆盖 + S0-04 原生 Snippets |
| `<procedure` 含 DOCTYPE、id、作者/日期注释 | 9.3 |
| SQL 模板正文按 SQL 高亮 | 8.5 `#sqlContent` |
| POM 输入 `<` 不自动插入 | 9.4 只展示候选，不自动插入 |

## 10. 扩展装配、配置与运行期行为

### 10.1 激活流程

```
activateExtension(context):
  1. 创建 Logger 与状态栏，加入 subscriptions
  2. 创建 DocumentModelCache、DocumentGate、IndexService（不立即扫描）
  3. 创建 6 个 Provider（补全/定义/引用/大纲/折叠/语义 token）与装饰器（嵌入块 + 属性值 + 关键字 + 非 XML 变量），并常驻注册
  4. 注册文档监听：模型与 Gate 失效、XML 文档 overlay 更新
  5. 注册工作区与配置监听：enable、大小上限、refid、索引开关、扫描范围、装饰开关、变量后缀
  6. 注册命令：新建 Procedure 文件、重建工程索引、显示输出
  7. 对当前可见编辑器应用一次嵌入块、属性值、关键字与非 XML 变量装饰
  8. 记录激活耗时（输出通道 info）
```

- `activate` 不读取工作区文件、不构建索引；索引在首次补全/导航时调用 `ensureStarted()` 惰性启动。
- 激活目标 ≤300 ms（NFR-P-01）；实测写入输出通道（debug 级别）。
- 任何可选子系统初始化失败只降级该子系统，不阻止扩展激活；核心（logger/config）失败才抛出。

**为什么 Provider 常驻注册**：VS Code 1.90 没有“按配置动态启用 Provider”的声明式能力；动态 `dispose`/重新注册会引入竞态与闪烁。常驻注册 + Gate 返回空结果更稳定（DD-019）。

| `DefinitionProvider` | `{ language: 'xml' }` | 位置 | `enable`、`refid.enabled`、索引可用 |
| `ReferenceProvider` | `{ language: 'xml' }` | 位置 | 同上 |
| `DocumentSymbolProvider` | `{ language: 'xml' }` | 文档 | `enable`、`symbols.enabled`、文件大小 |
| `FoldingRangeProvider` | `{ language: 'xml' }` | 文档 | `enable`、`folding.enabled`、文件大小 |
| `DocumentSemanticTokensProvider` | `{ language: 'xml' }` | 全量 tokens | `enable`、`variableHighlight.extensions` 是否含 `xml`、文件大小；refid 片段受 `refid.enabled` |
| 编辑器装饰（SQL 黄 / eval 绿 / 属性值浅绿 / 关键字蓝 / 数值蓝、字符串绿） | `visibleTextEditors` | 可见编辑器、文档变化（200 ms 防抖）、活动编辑器/主题切换 | `enable`、`blockBackground.enabled`、`attributeValueBackground.enabled`、`evalKeywordHighlight.enabled`、`evalLiteralHighlight.enabled`、文件大小、根节点 |
| 非 XML 变量装饰（Light 深蓝 / Dark 亮蓝） | `visibleTextEditors` | 可见编辑器、文档变化（200 ms 防抖）、活动编辑器/主题切换 | `enable`、`variableHighlight.extensions`、文件大小、scheme |
| `FileSystemWatcher` | include/exclude | 创建/修改/删除 | `index.enabled` |
| 文档监听 | — | `onDidChangeTextDocument`、`onDidCloseTextDocument` | 始终 |
| 工作区监听 | — | `onDidChangeWorkspaceFolders` | 始终 |
| 配置监听 | — | `onDidChangeConfiguration` | 始终 |

- 语义 Provider 全部使用 `language: 'xml'` + Gate，不按文件名/路径注册；`scheme` 不限制，兼容远程与虚拟文件系统。
- 不在 `onLanguage:xml` 之外增加激活事件；命令事件已在 `activationEvents` 中。
- `DocumentSemanticTokensProvider.onDidChangeSemanticTokens`：索引快照替换、Gate 状态变化、`refid.enabled` 或 `variableHighlight.extensions` 改变时触发，让 refid/变量颜色及时刷新。
- 非 XML 变量使用装饰而非语义 token，避免与 yaml/java 语言扩展的 Provider 竞争；详见 4.9。

### 10.4 文档 Gate

每次语义请求先经过 Gate：

```
gate.ensure(document):
  if (!config.enable) return false
  if (document.languageId !== 'xml') return false
  if (document.getText().length > maxDocumentSizeKB * 1024) {
    logOnce(document, '跳过：超过大小上限')
    return false
  }
  const info = detector.detect(document.getText())
  return info?.isProcedure === true
```

- 识别只读取前 4 KB 与根节点起始片段；完整模型在通过 Gate 后构建。
- 缓存键 `uri + version + languageId`；配置变化清空。
- `maxDocumentSizeKB` 按 UTF-16 代码单元计，与 VS Code 文本一致；日志写明阈值与实际长度。
- 普通 XML（POM/Spring/MyBatis）在 Gate 处返回空，不进入扫描、不构建模型、不查询索引。
- 嵌入块背景装饰同样经过 Gate（purpose `decoration`），普通 XML 与非 procedure 文档不会被着色。
- 非 XML 变量装饰使用 `decideRaw`：只检查 `enable`、scheme 与文档大小，不要求 `languageId=xml` 或 procedure 根节点；后缀是否命中由装饰器判断。
- `xproc4j.enable=false` 时所有语义 Provider 返回空；语法注入仍生效（平台限制，README 说明）。

### 10.5 配置服务

```ts
interface XProcConfig {
  enable: boolean;
  indexEnabled: boolean;
  include: string[];
  exclude: string[];
  maxFiles: number;
  completionEnabled: boolean;
  sqlKeywords: boolean;
  builtinVariables: boolean;
  refidEnabled: boolean;
  symbolsEnabled: boolean;
  foldingEnabled: boolean;
  blockBackgroundEnabled: boolean;
  attributeValueBackgroundEnabled: boolean;
  evalKeywordHighlightEnabled: boolean;
  evalLiteralHighlightEnabled: boolean;
  variableHighlightExtensions: string[];
  maxDocumentSizeKB: number;
  traceLevel: 'off' | 'messages' | 'verbose';
}
```

- 读取时做边界钳制：`maxFiles` 1..100000，`maxDocumentSizeKB` 1..102400；非法 JSON 值回退默认并 warn。
- `include`/`exclude` 为空数组时使用默认值；字符串项去空、去重。
- `variableHighlightExtensions` 由 `normalizeFileExtensions` 归一化：接受 `xml`、`.xml`、`*.xml`，统一小写并去重；非数组回退 `["xml","yaml","yml","java"]`，空数组表示显式关闭变量高亮。
- 只监听一次 `onDidChangeConfiguration`，按 `affectsConfiguration('xproc4j')` 分支处理：

| 变更 | 动作 |
|---|---|
| `enable` | 清空 Gate/模型缓存；触发语义 token 刷新；重绘块背景、属性值背景、关键字与非 XML 变量装饰；不重建索引 |
| `blockBackground.enabled` | 立即对所有可见编辑器重绘/清除 SQL 与 `lang-eval*` 背景 |
| `attributeValueBackground.enabled` | 立即对所有可见编辑器重绘/清除属性值背景 |
| `evalKeywordHighlight.enabled` | 立即对所有可见编辑器重绘/清除 `lang-eval*` 关键字颜色 |
| `evalLiteralHighlight.enabled` | 立即对所有可见编辑器重绘/清除 `lang-eval*` 数值与字符串颜色 |
| `index.enabled=false` | 取消构建、dispose watcher、释放快照；保留本地文档能力 |
| `index.enabled=true` | 惰性触发首次构建 |
| `include`/`exclude`/`maxFiles` | 300 ms 防抖后全量重建 |
| `maxDocumentSizeKB` | 清空 Gate/模型缓存；刷新语义 token 与所有可见编辑器装饰；按需淘汰 |
| `refid.enabled` | 触发语义 token 刷新 |
| `variableHighlight.extensions` | 触发 XML 变量 token 刷新；立即对可见的非 XML 编辑器重绘/清除变量装饰 |
| `trace.server` | 调整 Logger 级别 |

- 配置变更不重启扩展；索引重建在后台进行，旧快照继续服务直到新快照原子替换。

### 10.7 日志、输出与状态栏

**Logger**：

```ts
type LogLevel = 'error' | 'warn' | 'info' | 'debug';

logger.error(module, message, details?)
logger.warn(module, message, details?)
logger.info(module, message, details?)
logger.debug(module, message, details?)
```

- 格式：`[2026-10-23 14:30:01.234] [info ] [index] ...`；时间本地时区。
- `trace.server` 映射：`off` → warn/error；`messages` → info；`verbose` → debug。
- `details` 只允许标量/数组/普通对象；序列化失败时降级为 `String(details)`，不抛异常。
- **禁止**写入文档内容、属性值、变量值、SQL 文本、用户名以外的个人信息；只记录 URI、偏移、长度、耗时、计数、错误码（DD-022）。
- 单个错误按 `uri + version + message` 去重，避免每次按键刷屏；每 60 秒最多 1 条重复。

**状态栏**：

- 索引构建中：`$(sync~spin) XProc4J 索引`，tooltip 显示已处理文件数。
- 截断/失败：`$(warning) XProc4J 索引`，点击打开输出。
- 空闲/未启用：隐藏。
- 状态栏项随扩展停用释放；不使用 `setInterval` 轮询。

### 10.8 异常边界与取消

```ts
function guard<T>(provider: string, fallback: T, fn: () => T | Promise<T>) {
  return async (...args: unknown[]) => {
    try {
      return await fn();
    } catch (err) {
      logger.error(provider, 'Provider 执行失败', { error: toErrorInfo(err) });
      return fallback;
    }
  };
}
```

- 所有 VS Code Provider 回调、命令、事件监听都经过 guard；绝不向 VS Code 抛异常。
- 每次重活前检查 `CancellationToken.isCancellationRequested`；索引构建使用独立的 `CancellationTokenSource`，重建/禁用/关闭工作区时取消。
- 事件监听里的 Promise 使用 `void promise.catch(...)`，避免 unhandledRejection。
- 用户输入导致的解析错误只记 debug，不进错误弹窗；只有命令失败与索引失败才提示。

### 10.9 生命周期与资源释放

| 事件 | 处理 |
|---|---|
| 文档变化 | 失效模型缓存；更新索引覆盖层（300 ms 防抖）；语义 token 由 VS Code 自动重取；嵌入块、属性值、关键字、数值/字符串与非 XML 变量装饰 200 ms 防抖后重绘 |
| 文档关闭 | 丢弃覆盖层；取消待执行的背景/变量重绘定时器；磁盘版本已由 watcher 维护 |
| 文档保存 | 不特殊处理；watcher 的 change 事件更新索引 |
| 工作区文件夹变化 | dispose 旧 watcher；清空快照；按新文件夹重建 |
| 主题变化 | 重新创建非 XML 变量装饰类型（Light `#0550AE` / Dark、HC `#9CDCFE`）与数值/字符串字面量装饰类型（Light `#1565C0`/`#2E7D32`，Dark、HC `#90CAF9`/`#81C784`），并重绘可见编辑器 |
| 扩展停用 | 取消所有构建/定时器；dispose watcher、状态栏、OutputChannel、装饰类型、所有注册 |
| 配置禁用索引 | 同“停用索引”分支；保留命令与语法能力 |

- 所有一次性资源放入 `context.subscriptions`；自建 `DisposableStore` 统一释放。
- 不注册 `deactivate` 之外的全局钩子；`deactivate` 只做同步清理。

### 10.10 文案与国际化

- 本期仅中文文案，不设 `src/i18n/` 间接层（与 2.4 一致）；运行期提示集中在各模块的中文常量/字面量中。

## 11. 非功能设计

### 11.1 性能预算

| 指标 | 需求目标 | 内部预算（P95） | 机制 |
|---|---|---|---|
| 扩展激活 | ≤300 ms | ≤250 ms | 不扫描、不读文件、Provider 常驻注册 |
| Gate 识别 | — | ≤5 ms | 只读前 4 KB；缓存 |
| 10,000 行文档模型 | — | ≤120 ms | 单遍扫描、无 DOM、无正则回溯 |
| 大纲（5,000 行） | ≤150 ms | ≤120 ms | 模型缓存 + 线性转换 |
| 折叠（5,000 行） | — | ≤80 ms | 复用模型 |
| 补全（索引就绪） | ≤300 ms | ≤150 ms | 模型缓存、候选预排序、去重后上限 1000 |
| 定义跳转 | ≤500 ms | ≤100 ms | 快照 Map 查询 + 二分定位 |
| 首次索引 5,000 文件 | ≤8 s | ≤6 s | 8 并发读、批量 yield、预过滤 |
| 首次索引 20,000 文件 | ≤30 s | ≤25 s | 同上 + 上限 |
| 增量索引可见 | ≤1 s | ≤700 ms | 300 ms 防抖 + 单文件轻扫 |
| 内存增量 | ≤50 MB | ≤40 MB | 索引只存 id/参数/range；模型缓存 32 MB 上限 |
| 扫描分批 | ≤100 文件或 ≤20 ms/批 | 同左 | 每批 `await yieldToEventLoop()` |

- 以上为设计预算，不是承诺；编码完成后用 `test/perf` 在固定 fixture 上测量并记录到测试报告。
- 冷启动首次补全可能触发索引构建：补全**不等待**索引，只返回本地结果；索引就绪后下一次补全自动包含工程 id（用户无感）。
- 定义跳转在索引未就绪时最多等待 400 ms；仍未就绪则返回本地结果并提示一次“索引构建中”，不阻塞 30 秒。

### 11.2 并发、取消与背压

- 扩展宿主是单线程事件循环；所有 CPU 计算必须可中断，不能出现 >50 ms 的同步长任务（索引读取除外，见分批）。
- 索引读取并发 8；用固定 worker 池而不是 `Promise.all(files)`，避免 20,000 个 Promise 同时挂起。
- 每批 ≤100 个文件或 ≤20 ms 让出一次事件循环（`await new Promise(setImmediate)`）；让出前检查取消。
- 构建使用 `generation` 编号；新构建开始即递增，旧构建返回的结果若 `generation !== current` 直接丢弃，不写快照。
- 同一 URI 的模型构建使用 in-flight Map 去重；并发请求共享同一个 Promise，失败后移除。
- 文档变化/索引 watcher 使用 300 ms 防抖；同一 URI 的连续事件合并为最后一次。
- 快照替换是原子引用赋值；读者持有旧快照直到本次查询结束，不需要锁。
- 不使用 `setInterval` 轮询；所有定时器为 `setTimeout` 且随 Disposable 清理。

### 11.3 可靠性与降级矩阵

| 故障 | 影响 | 降级行为 | 用户可见 |
|---|---|---|---|
| 元数据加载失败 | 补全/大纲不可用 | 语义功能停用 | 错误提示一次；输出通道详情 |
| 扫描达到上限/截断 | 结构不完整 | 保留已扫描部分；补全/大纲可用 | 输出 warn；状态栏警告 |
| 单个文件读取失败 | 该文件未索引 | 跳过并记录 | 输出 warn，含 URI/错误码 |
| 索引构建失败 | 跨文件能力缺失 | 本地文档补全/跳转仍可用 | 状态栏警告 + 输出 |
| 语法目标缺失 | 正文无语言色 | 只保留 meta/变量色 | 无弹窗 |
| 语义 token 异常 | 变量/refid 无色 | TextMate 兜底 | 无弹窗 |
| 大文档 >2 MB | 无语义功能 | TextMate 高亮 | 输出 info（每个文档一次） |
| 非 procedure XML | 无功能 | Gate 返回空 | 无提示 |
| Snippet 原生不触发 | 无片段 | 无自动降级（S0-04 已通过；若回归需新增 Provider） | 无片段 |
| 模板损坏 | 新建文件失败 | 命令报错，不写文件 | 错误弹窗 |
| 配置值非法 | 行为不确定 | 回退默认并 warn | 输出 warn |
| 工作区无 XML | 索引为空 | 不扫描内容；watcher 仍监听新建 | 无提示 |

### 11.4 安全与隐私

- **不联网**：无 `fetch`、无 `http`、无遥测、无崩溃上报。
- **不执行内容**：不 `eval`、不 `new Function`、不启动子进程；XML 只做文本扫描。
- **不解析外部实体**：不加载 DTD、不访问 `SYSTEM` 标识符；`procedure.dtd` 仅作为构建期元数据源，运行期不读取。
- **写操作最小化**：唯一写操作是 `createProcedureFile`，目标由用户选择；不修改现有文件，除非用户明确确认覆盖。
- **路径安全**：文件名必须通过 basename 校验；不使用输入框拼接目录；拒绝 `..` 与路径分隔符。
- **输出安全**：日志不写文档内容/属性值/变量值；对 URI 中的控制字符做转义后再输出。
- **工作区信任**：只读扫描 + 显式命令写入，声明 `capabilities.untrustedWorkspaces.supported = true`；不因受限模式改变行为。
- **供应链**：`package-lock.json` 提交，CI 用 `npm ci`；VSIX 只含构建产物、语法、片段、模板、README/LICENSE/NOTICE；发布附件提供 SHA256。
- **许可证**：扩展 GPL-3.0；随包/随仓库的第三方资源（DTD、示例 XML、VS Code 语法测试夹具）在 NOTICE 中逐项署名并保留许可证文本。

### 11.5 兼容性

| 维度 | 策略 |
|---|---|
| VS Code 版本 | 只用 `^1.90.0` 稳定 API；CI 用 1.90 类型定义；不使用 1.91+ API |
| 远程/WSL/容器 | 只用 `workspace.fs`、`Uri`、FileSystemWatcher；无原生模块、无绝对路径 |
| 虚拟工作区 | 声明 `virtualWorkspaces: limited`；语法/补全可用，索引依赖 `findFiles` |
| 多根工作区 | 所有工作区文件夹都参与索引；URI 为键，不合并同名 id |
| Windows | 路径用 `Uri.joinPath`；文件名非法字符显式校验；大小写不敏感文件系统按 URI 去重 |
| 大小写敏感 | 不假设 id 大小写等价；索引 Map 区分大小写 |
| Untitled | 识别/补全/大纲可用；不进入索引；定义仅本地 |
| 换行/BOM | LineIndex 统一处理 `\r\n`/`\n`/`\r`；BOM 由 VS Code 提供文本时已处理 |
| 主题 | 只输出 scope；默认 Dark+/Light+ 可读；不强制颜色 |
| 其它 XML 扩展 | 不切换语言、不改设置；Provider 返回值与其它扩展合并；重复候选由 VS Code 展示 |
| Cursor/Windsurf | 冒烟测试；不依赖专有 API；差异记录到问题与经验 |

### 11.6 可观测性

- 激活时记录：扩展版本、VS Code 版本、OS、工作区文件夹数、`enable/indexEnabled`。
- 会话计数器（仅 debug）：模型构建次数/命中率、补全请求数、索引文件数/id 数/ref 数、错误数。
- 索引摘要：扫描文件数、跳过数与原因、entries、refs、耗时、是否截断。
- 所有错误包含模块名、URI（可选）、偏移（可选）、错误码/消息；命令错误附带“显示输出”动作。
- 不引入遥测；用户反馈时只需提供输出通道文本（不含文档内容）。

### 12.3 语法测试 Harness

**目标**：在没有 VS Code 进程的情况下，验证 `xproc4j.injection.tmLanguage.json` 与宿主 XML 语法、目标语法的组合行为。

**依赖**：

- `vscode-textmate` + `vscode-oniguruma`（devDependency）。
- 宿主语法：优先使用 vendored 的 VS Code `xml.tmLanguage.json`（MIT，test-only），保证与真实编辑器一致；`stub-host-xml.tmLanguage.json` 只用于快速规则单测。
- 目标语法：vendored `sql.tmLanguage.json`、`java.tmLanguage.json`、`javascript.tmLanguage.json`（MIT，test-only）；其它语言用 stub 验证 include 机制，不验证真实配色。
- WASM 路径：`node_modules/vscode-oniguruma/release/onig.wasm`；Node 20 `WebAssembly` 直接加载。

**Harness API**：

```ts
export interface Token { line: number; start: number; end: number; scopes: string[]; }
export interface Harness {
  tokenize(text: string, hostScope?: string): Token[];
  scopesAt(tokens: Token[], line: number, character: number): string[];
  grammarLoadMs(): number;
}
export async function createHarness(): Promise<Harness>;
```

**快照格式**：

```
line 4: <sql-query-list result="users">
  entity.name.tag.xproc4j
  meta.tag.xml
  ...
```

- 每个 fixture 只断言“关键字/字符串/注释/属性/变量”的关键 scope，不比较完整栈，降低主题与宿主语法升级带来的噪声。
- 快照更新命令：`UPDATE_GRAMMAR_SNAPSHOTS=1 npm run test:grammar`；更新必须人工审阅 diff。
- S0-01/02/03/05/06/07/08 各自独立用例，失败时按 1.6 的 Fallback 修改设计，不直接改断言通过。

**语法测试用例**：

| 用例 | 输入 | 断言 |
|---|---|---|
| 结构 | `<procedure id="p"><sql-query-list result="r">...</sql-query-list></procedure>` | 标签/属性/feature scope 正确 |
| SQL 正文 | `<sql-query-list>SELECT * FROM t WHERE id = #{id}</sql-query-list>` | `keyword`、`string`、变量 |
| 自闭合 | `<sql-update result="x"/>` 后跟 `<procedure>` | 后续标签不被 SQL 覆盖 |
| 多行开始标签 | `<sql-update\n result="x"\n>` | 标签/属性有色；正文不注入；后续正常 |
| 动态 SQL | `<if test="...">` 嵌套在 SQL 正文 | 动态标签名 scope + 正文 SQL |
| Java 正文 | `<lang-eval-java>return 1;</lang-eval-java>` | Java 关键字；子标签不误判 |
| 变量 | `${a}`、`$!{a}`、`#{}`、`$name` | 变量 scope；空占位符 invalid |
| `_lang` | `<lang-string _lang="sql">SELECT 1</lang-string>` | SQL 关键字 |
| `_lang` 多值 | `_lang="java,sql"` | Java 优先（记录差异） |
| 非 XProc | POM/Spring/MyBatis | 只允许已知标签名差异；属性/文本无差异 |
| 缺失目标语法 | 不注册 `source.groovy` | 无异常；正文为 meta + 变量 |
| CDATA | `<sql-script><![CDATA[...]]></sql-script>` | CDATA 内不误解标签；SQL 注入边界记录 |

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| S0-01 跨语法 include 失败 | 中 | 注入能力降级 | 仅 `contentName` + 语义 token；文档说明 |

### 17.2 已知限制（设计接受）

1. 语言注入只能做到词法级；Java/JS/Groovy 等正文没有语义补全、类型检查或重构。
2. 多行开始标签（`<tag\n attr="x">`）不注入正文，只着色标签/属性；`_lang` 跨行不生效。
3. 属性级语言注入依赖 S0-02；失败时属性只保留基础 XML scope（变量仍可由语义 token 着色）。
4. `_lang` 动态正文仅 `lang-string`/`lang-render`；其它标签使用固定映射。
5. 正文中出现 `</tag>` 会提前结束（XML 本身也不允许该写法）；SQL 字符串/注释中的同名结束标签同样受限。
6. 同名标签嵌套不支持（XProc 结构不应出现）。
7. 第三方语法未安装时正文退化为纯文本/变量色，不报错。
8. `xproc4j.enable=false` 不能关闭 TextMate 注入；只能关闭语义功能。原生 Snippets 需通过 VS Code 片段设置关闭。
9. 普通 XML 中若出现与 XProc 同名的标签（如 `<include>`），可能获得标签名 scope；S0-03 用于评估并收紧白名单。
10. 大纲包含未知标签，但未知标签没有属性补全/高亮。
11. 片段只覆盖 90 个模板，不等于 111 个标签全覆盖；`dialect-*` 等 DTD-only 标签可能没有片段。
12. 索引只扫描匹配 `projectScan.include` 的文件；默认 `**/*.xml`，非 `.xml` 的 procedure 文件不会进入索引。
13. 索引纯内存，重启后首次请求重建；大工作区首次使用有等待。
14. 不做跨工作区、跨窗口共享索引。
15. 不提供诊断/格式化/悬停/CodeLens/Java 类跳转。
16. Web 扩展（浏览器）不支持；`virtualWorkspaces` 仅有限支持。
17. 主题对自定义 scope 的配色不同；只保证默认主题可读。
18. Cursor/Windsurf 等分支可能缺少部分 API 或行为差异；只做冒烟，不承诺完全一致。
19. 新建文件模板的作者来自扩展宿主 OS 用户；远程/容器环境显示的是远端用户。
20. 索引上限按排序后前 N 个文件截断；结果可能缺少字母序靠后的文件，输出通道会提示。

### 17.3 后续演进（本期不做）

- 诊断校验（未知标签/属性/refid、结构错误）基于已生成的元数据，可作为 v0.2。
- 格式化/重排（需要完整 AST 与保留注释策略）。
- 标签/属性 → Java 类跳转、悬停文档（需要框架源码索引）。
- TinyScript/Funic/Funvi/OGNL 语法与补全。
- 持久化索引/Worker 后台解析（当前性能达标前不引入）。
- 虚拟文档/只读预览、代码动作、重构。
- Web 扩展入口（需纯浏览器文件系统与 Web Worker 方案）。
- 第三方语言 scope 的可配置映射（当前固定表 + 降级）。
