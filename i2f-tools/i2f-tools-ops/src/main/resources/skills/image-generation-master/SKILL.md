# 图片生成大师

## 概述

本技能提供AI图片生成的专业指导，帮助用户快速掌握图片生成工具的使用技巧，通过精准的模型选择和描述词编写，以最少调整次数生成符合预期的图片。

**提示词形态（v1.7 起默认）：** 按《提示词结构规范》写成 Markdown 四段——`人物` / `动作` / `环境` / `要求`，前三段写正文，`要求` 段逐条以 `【必须】` / `【重要】` / `【禁止】` 开头。紧凑式逗号长串降为备用形态。

**两道校验都要过：** 生成前的**结构自检 6 问** + 生成后的**图片自检 11 项**。结构合规不等于图片合格，任何一道没过都要改——但生成后那道**只负责出检查报告，不自动重试**（见《生成策略》的调用预算）。

## 生成策略（最高优先·调用预算）

### 铁律：一次需求 = 一次调用，先出报告，再等授权

**默认只调用一次生成工具；出图后立即进入"自检 + 出第一版检查报告"，然后停下来等用户决定。未经用户明确同意，不得发起第二次生成调用。**

这是成本约束，不是风格建议。用户看不到收益的那部分重试（"我觉得不够好，再来一版"）花的是用户的钱，**必须由用户自己拍板**。

**标准动作序列（四步，缺一步都算违规）：**

1. **一次调用** —— 写好提示词 → 调用生成工具 1 次（返回 1–3 张，看模型）→ 本轮生成结束，到此为止
2. **自检** —— 对着《生成后自检闸门》11 项逐条比对这一次的结果，**只判断、不补救**
3. **出第一版检查报告** —— 结果与结论一起交给用户：哪张最好、哪几项没过、每项的具体原因、建议改哪一句
4. **停下等授权** —— 明确问用户要不要继续。用户点头后，才允许下一次调用

**第一版检查报告模板（照此写，不许省略未通过项）：**

```
## 第一版检查结果
- 通过：面孔 / 肤色 / 年龄 / 服饰 / 构图 / 氛围 ……（列出实际通过的）
- 未通过：#? 构图（脚被裁）、#? 指定元素（墨镜遮脸）
- 原因定位：×××（是提示词里哪一句导致的，还是模型先验）
- 建议改法：把「……」改成「……」（指名到具体那一句）
- 下一步：要我按上面的改法重出一版吗？（需你确认后我再调用）
```

### 允许的例外（不需先请示）

只有"用户根本拿不到任何可用结果"的技术性失败，才可以不请示直接重试 **1 次**：

- 任务报错 / 超时 / 返回 0 张
- 返回的图完全不可用（纯噪点、纯色块、崩坏到看不出内容）

**以下不属于例外**（一律先问，不许自作主张）：

- "还不够好看""不够御姐""氛围差一点"
- "想换个模型对比一下"
- **"想多出几张让用户自己挑" ← 这条最烧钱，明确禁止**

### 一次需求的默认预算

| 项 | 上限 |
|---|---|
| 生成调用（默认） | **1 次** |
| 未获同意的追加调用 | **0 次** |
| 技术性失败的重试 | 1 次（仅限结果不可用） |
| 异步任务轮询查询（不产生生成费用） | 不限，但别空转 |

### 用户放行之后

- 用户说"再出一版 / 按上面的改 / 换模型试试" → 这时才发起第 2 次调用
- 用户说"多来几张" → 先问清数量（"要 2 张还是 4 张？"），按他给的数量生成，**不要顺手多加**
- 每次追加调用后，仍然回到"自检 → 报告 → 停下"
- 不同工具每次返回的图片数量不同：Kling / Vidu / Wan 通常各返回 3 张

### 示例（对照这个节奏）

```
1. 用户请求生成图片
2. 调用生成工具 1 次（返回 1–3 张）
3. 自检 11 项 → 出第一版检查报告（含未通过项、原因、改法）
4. 停下，问："效果如何？要我按上面的改法重出一版吗？"
5. 用户同意 → 才调用第 2 次；用户说够了 → 结束，不再调用
```

**反例（本技能真实踩过的坑）：** 一次"沙滩高跟"需求，发现墨镜与姿势问题后自作主张连调 4 次（Kling 两轮 + Wan 一轮 + 兜底一轮），产出约 12 张，用户最终只用得上 3 张。**正确做法：第 1 次出图后就把"有墨镜 / 姿势成抬腿 / 根因是提示词写了『脚背绷直』"报告给用户，等他说"改"再调第 2 次。**

## 生成后自检闸门（Before Presenting·一次通过的关键）

**自检的产出是"报告"，不是"重试"。** 图片生成完成后，先自己按需求逐条比对，**比对结果要如实写进第一版检查报告，而不是默默再调一次生成**。技术判断归你，**花钱的决定归用户**——发现不合格就想自己重生成，正是用户成本被烧掉的地方。

> **本闸门与提示词形态无关，永远必过。** 无论提示词写成紧凑式长串还是《提示词结构规范》的 Markdown 四段式，出图后都要走完下面 11 项；"提示词结构写得规范"不能当作免检理由——结构合规只是生成前的检查，**图片合格是生成后另一道门**，两层都要过。

### 强制核对清单（11 项，逐条过）

| # | 核对项 | 判定标准 |
|---|---|---|
| 1 | 面孔体系 | 是否为目标族裔？有没有冒出混血感/欧美脸/拉丁脸？ |
| 2 | 肤色 | 是否为目标色？有没被光线晒深？脸与身体是否同色？ |
| 3 | 年龄感 | 是否落在目标区间？（**默认 18–23，上限 25**；只有用户明确给了年龄、或说了中年/老年/学生这类指向词时才偏离——"御姐/成熟/知性"是风格词，不算年龄） |
| 4 | 服饰一致性 | 是否满足季节/场合要求？（"清凉"就不能长袖；"正式"就不能拖鞋） |
| 5 | 指定元素 | 用户点名的元素（鞋跟高度、颜色、姿势、道具、发型）是否都在？ |
| 6 | 构图完整 | 全身照是否真全身出镜？头顶和脚有没有被裁？ |
| 7 | 解剖正确 | 手指脚趾是否分明？有无多余肢体、扭曲关节、粘连？ |
| 8 | 画面干净 | 背景有无路人、杂物、乱码文字、悬浮物？ |
| 9 | 质感 | 有没有落进动漫感/塑料感/CG感/油画感？ |
| 10 | **氛围 / 季节** | **遮住人物只看背景：能不能一眼认出用户要的季节与场所？**"夏日沙滩"要热、"冬夜街头"要冷，认不出来就是氛围没写 |
| 11 | **冷暖调性一致** | 整图调性与用户情绪是否一致？用户说"夏天/热情"却给你灰蓝冷调 = 不合格；说"高级冷艳"却给你暖橘 = 不合格 |

> **为什么必须有第 10、11 项（本技能真实踩过的坑）**：旧版清单 9 项全是"人物技术指标"，一张冷灰调、阴天感的海边图，因为"白皮对、全身对、服饰对"就全部通过了闸门，被当成合格品交付，用户第一句话是"太冷了，感觉不到夏天海边"。**技术项全过 ≠ 氛围对**。氛围必须有自己的核对格，否则永远没人查它。

### 判定规则（默认只判不重试）

| 情况 | 动作 |
|---|---|
| **1–5 项、10–11 项任一不过** | **写进检查报告**：标明哪一项、由哪句提示词导致、建议怎么改；**不自行重生成** |
| **6–9 项不过**（构图/解剖/杂物/质感） | 同上，并在"建议改法"里写到具体句（如"脚被裁 → `要求` 段补『头顶到鞋跟完整入画』"） |
| 结果基本可用，只有小瑕疵 | 正常交付 + **主动标注瑕疵**（如"图3 背景有路人，可修掉"），别装作完美 |
| 任务报错 / 返回 0 张 / 图完全不可用 | 允许不请示重试 **1 次**；仍失败就把错误原样报给用户 |
| 用户已明确说"按这个改，重出" | **这时才**发起下一次调用，并同样回到"自检 → 报告" |

**禁止：** 用自己的审美判断代替用户的授权，连续调用多次"碰一张好的"。一次需求的默认生成调用是 **1 次**，追加必须由用户放行。判定为不合格 ≠ 立刻重来，而是**先说清问题、等用户决定**。

## 人物身份基线（默认配置·最高优先级）

### 设计原则：凡有偏见的维度，必须显式赋值

模型对"族裔 / 肤色 / 年龄 / 体型"自带先验偏好，**只要留空，它就会自己填**——填出来的通常不是用户想要的。所以默认锚点不能是一串形容词，而必须是一张**逐格填满的身份表**。

| 维度 | 默认值（硬默认） | 为什么必须显式写 | 留空的后果 |
|---|---|---|---|
| 族裔 / 面孔体系 | 东亚中国面孔 | 模型对"美女"的默认输出偏欧美/混血 | 冒出混血脸、拉丁脸 |
| 肤色 | 冷白皮（白瓷冷调） | "白"会被理解成白种人的白 | 要么偏黄，要么变成欧洲人 |
| 年龄 | **20 岁（可接受区间 18–23）** | 数字是相对刻度，模型有系统性偏老 | 年龄忽大忽小，且普遍偏大 |
| 骨架 / 比例 | 九头身、极致的腰臀比 | 不写就随机 | 比例失真 |
| 主体受光 | 柔和漫射光 / 反光板补光（**不是"整张图阴天"**） | 光线会改写肤色呈现 | 硬光直射把白皮打成小麦色 |
| 环境调性 | 按场景单独指定（盛夏海边 = 明亮高调 + 高饱和） | 环境光决定"季节感与氛围"，跟肤色是两码事 | 明明是盛夏，出图却是阴天灰蓝 |

**三条铁律：**
1. **留空即失守**——上表任一维度不写，模型就会用先验补，补出来的往往要返工
2. **整维度替换**——用户明确指定时，要整格替换，不能只改一半。例如用户说"欧美风"，族裔切到欧洲面孔后，肤色描述也要跟着换成"白种人冷白皮"，不能留着"冷调粉白"制造内部矛盾
3. **光线是两件事，不能用一个开关管两头**——"主体受光"负责肤色对不对，"环境调性"负责季节感对不对。旧版把两者合成一句"阴天柔光"，等于用保护肤色的手段牺牲了整个场景，见下文《双层光照模型》

### 年龄默认值的判定顺序（先判"该不该改年龄"，再判"改成多少"）

**总原则：默认即年轻。用户没有明确说"中年 / 老年 / 具体年龄"或年龄指向性极强的说法时，一律按年轻标准（20 岁，区间 18–23，上限 25）。** 气质词不是年龄词，别自己替用户变老。

**判定顺序（从上往下，命中即停）：**

| 顺序 | 用户这么说 | 年龄取值 | 说明 |
|---|---|---|---|
| 1 | **明确年龄数字**（"32岁""45岁左右"） | 用该数字，但按模型偏移**减 2–3 岁**写 | 例：说 32 → 写 29–30；说 45 → 写 42 |
| 2 | **明确年龄段 / 年龄指向性极强的说法**（中年、大叔、退休、奶奶、阿姨、少女、学生、JK、宝妈、老年人、青少年） | 按该阶段给 | 这才是真正该改年龄的情形 |
| 3 | **气质 / 风格 / 职业 / 穿搭类词**（御姐、知性、优雅、成熟风、干练、冷艳、高级感、大女主、职场、御姐范、姐姐感、温柔、气质好） | **不改年龄**，仍 20 岁（18–23，上限 25） | 这些词落到**穿搭 / 妆容 / 姿态 / 眼神 / 光线**上，不落到年龄上 |
| 4 | 什么都没说 | 20 岁（18–23） | 默认值 |

**两条判定细则：**
- **"成熟"≠"年长"**：用户说"成熟风""成熟一点"，指的是**风格**（剪裁、妆容、姿态），不是年龄。真要年长，用户会说"中年""40岁"或"看起来有阅历的中年女性"。
- **不确定时选年轻**：改小比改大便宜得多——改大等于整张图报废（脸一老，气质、皮肤、光影全部连带失真），而每一版都是花用户的钱。

### 年龄锚定的偏移校正（务必下锚）

**核心事实：年龄数字不是绝对刻度，各模型都有"显老"的系统性偏移。** 同一个"25岁"，在 Kling 上常被渲染成接近 28–30 岁的观感；"30岁"更容易直接跳到中年感。所以年龄既要写数字，**也要写可观察的年轻特征**，两者互为校验。

**默认配置：**
- **锚定 20 岁**，可接受区间 **18–23 岁**，**硬上限 25 岁**
- 需要"更年轻"就往 18–20 走；**不要用 24、25 当"年轻"的写法**，那是偏老区
- **不要为了"气质"去抬年龄**——成熟感、御姐感、知性感一律走穿搭与姿态，见下节
- 只有命中上面判定顺序的 1、2 两类时，才上调/下调年龄，并同步换掉年轻特征词（"32岁"就别再写"婴儿肥/少女感"）

**双锚写法（数字 + 特征）：**
- 数字锚：18岁 / 20岁
- 特征锚：胶原蛋白充足、皮肤紧致有弹性、脸颊微带婴儿肥、无眼袋、无法令纹、无眼角细纹、颈部线条干净、"少女感"或"从容感"
- 反向排除：不要成熟感、不要中年感、不要法令纹、不要眼袋、不要眼窝凹陷、不要面部松弛

**为什么必须加特征锚：** 只写"20岁"时，模型可能给你一张"保养很好但确实不年轻"的脸；只写"少女感"又可能飘成未成年或幼态。**数字定区间、特征定观感**，两条一起才稳。

**注意分寸：** 18–23 的锚点是为了"年轻"，不是为了"幼态"。要同时保留"成年女性"的骨架特征（九头身、腰臀比），否则会滑向不适合的方向。

**"御姐"的正确解法（关键认知：御姐是穿搭与气场的变量，不是年龄的变量）**

用户说"御姐"，90% 指的是**成熟风的穿搭 + 从容锐利的气场**，人依然是年轻漂亮的年轻女性。**年龄锚保持 20 岁（18–23），最多放宽到 25，绝不要靠抬年龄数字去做御姐感**——抬年龄只会换来一张"保养得好的中年脸"，正好是用户不想要的。

| 维度 | 做法 | 反面 |
|---|---|---|
| 年龄数字 | **仍写 20 岁（18–23），硬上限 25**，写法："20岁（18-23岁区间），御姐风的成熟气质" | 写 27、30+ → 直接跳中年感，脸和"御姐穿搭"打架 |
| 特征锚 | **保留年轻特征**：皮肤紧致无细纹、无眼袋、无法令纹、脸颊微带婴儿肥可保留；只把"少女感"换成"从容感" | 换成"成熟感/阅历感"→ 法令纹、眼窝凹陷全冒出来 |
| 气场来源 | **眼神**（锐利、直视、微上扬）+ **姿态**（交叠腿、微侧身、手部从容）+ **穿搭**（收腰、利落剪裁、露肩吊带、尖头细高跟）+ **妆容**（上扬眼线、正红/蜜桃唇） | 靠脸部年龄感表达气场 |
| 反向排除 | 不要成熟感、不要中年感、不要法令纹、不要眼袋、不要面部松弛、不要网红脸 | 只排除"不要中年感"而其余留空 |

**一句话：御姐写在穿搭、眼神、姿态、妆容上，写在脸以外的地方。** 需要"更御"就加穿搭与气场的具体项（红唇、上扬眼线、收腰、尖头细跟、交叠腿），不要加年龄。

### 偏见维度的通用处理法（任意族裔/肤色组合都适用）

这不是针对某个族裔的补丁，而是**普适公式**。"面孔体系 × 肤色"的任意组合都容易翻车，处理步骤完全一致：

1. **正面赋值**：直接写目标面孔体系，不要只写"美女"再指望模型猜
2. **特征细化**：用可观察的五官结构锚定人种（眼型、鼻型、唇形、脸型轮廓）。五官越具体，模型越难"漂移"
3. **反向排除**：显式列出不要的邻近候选（如"不要混血感、不要欧美面孔"）
4. **全场一致**：声明"全身肤色与脸部一致"，否则常见"脸白腿黑"
5. **光线适配**：目标肤色必须配相容光位，见下文《光线与肤色的耦合规则》

**肤色色卡写法（比形容词稳）：**

| 目标 | 正面写法 | 反向排除 |
|---|---|---|
| 极白 | 冷白皮、白瓷冷调、冷调粉白 | 小麦色、古铜色、蜜色、偏黄、暗沉 |

**口语翻译：** 用户只说"白皮亚洲"这类**组合短语**时，要把它展开成上面 5 步再写进描述词，不要原样丢给模型——原样丢等于没写。

### 核心原则

1. **明确风格定位**：开头就确定整体风格

### 重要技巧：使用明确事实替代笼统描述

**核心问题：**
不同AI模型对抽象、笼统的描述理解不一致，导致生成效果不稳定。使用明确的事实性描述可以大幅提高生成的一致性和准确性。

**原则：**
- ❌ 避免使用主观、抽象的形容词
- ✅ 使用客观、具体、可量化的事实

**对比示例：**

| 笼统描述（❌） | 明确事实（✅） | 说明 |

> **⚠️ 默认形态已改为结构化：** 正式产出请使用《提示词结构规范（Markdown 分段 + 着重标记）》——四个大标题（人物 / 动作 / 环境 / 要求）+ `【必须】/【重要】/【禁止】` 着重标记 + 标题内分条列表。**下面这条逗号长串是紧凑式备用形态**，只在用户明确要"一条连着写的提示词"、或目标模型吃不进换行与标题时才用；两种形态的**信息量必须完全一致**，不许因为换了形态就少写身份锚点或氛围四要素。

```
[风格定位：电影级写真风格]，

[鞋子描述]，[服装下装]。
[场景描述]，[环境细节]，[季节道具]。
[姿态描述]，[表情描述]。

**注意顺序：** 面部结构和肤色要放在人物句的**最前面**，不能藏在中间或末尾。模型对越靠前的描述权重越高，身份信息写在后面很容易被后面的服装/场景描述冲淡。

**唯二例外（氛围定调句）：** 允许在开头放**一句很短的**季节/氛围定调句（≤30字，例如"盛夏热带海岛正午，明亮通透的高调曝光，色彩明快鲜亮"），作用是先给整图定色温与明度；**但第二句必须立刻回到身份句**，氛围句最长不超过一句，否则会把人物身份挤到低权重区。

| 紧凑式里的片段 | 结构化后归到哪个标题 |
|---|---|

| 面部结构 / 肤色 / 年龄 / 身材 / 发型 / 服装 / 鞋 / 配饰 | `## 人物` |

| 场景 / 环境细节 / 季节道具 / 主体受光 / 环境调性 | `## 环境` |

- 金色高光点缀，暖调光晕
- 温柔气质

**硬规则：色调词只允许出现在"场景句"里，禁止写进通用锚点或示例模板的固定末尾。** 一旦写进通用块，它就会被无差别复制到所有图里，包括不该冷的场景——这是旧版把盛夏海边做冷的直接原因之一。

### 双层光照模型（本技能核心·必须按此写）

**核心事实：一张照片的光其实有"两层"，它们可以、而且经常应该分开指定。**

| 层 | 管什么 | 怎么给值 | 写错会怎样 |
|---|---|---|---|
| **主体受光**（人物这一层） | 肤色、皮肤质感、面部立体感 | 柔和的漫射日光 / 树荫散射 / 白色反光板补光 / 柔和顶光 | 写强直射 → 白皮变小麦色、脸上出硬阴影 |
| **环境调性**（整图这一层） | 季节感、氛围、情绪、色彩 | 明亮度 + 饱和度 + 天气 + 时间 + 主色（如高饱和青蓝海水） | 不写 → 模型用默认中性灰，季节感消失 |

**关键结论：想让"冷白皮"和"盛夏海边"同时成立，不是二选一，而是分层写。**

```
主体受光：柔和的漫射日光，皮肤处在柔和光线下保持白瓷冷调，无硬光斑，无晒痕
环境调性：盛夏正午，明亮通透的高调曝光，饱和度很高的青蓝色海水、鲜绿椰叶、白到发亮的沙滩，
          短而锐利的投影，画面整体明快鲜亮
```

这两句**在物理上不矛盾**：现实中"树荫下 / 遮阳伞下 / 薄云遮日的正午"就是"主体柔光 + 环境高亮高饱和"。旧版把"光线"当单一开关，才会得出"要白皮就必须整张图阴天"的错误结论。

**五条写法规则：**
1. **肤色句挂在"主体受光"上**，氛围句挂在"环境调性"上，两句话都要写，不许用一句"阴天柔光"同时打发
2. 需要"热"就抬**环境层的明度与饱和度**（高调曝光、锐利短投影、饱和的青蓝/鲜绿），不要去抬主体层的直射光
3. 允许"金色高光只出现在背景与水面的反射、发丝轮廓光上"，但**禁止让暖光直射面部**
4. 需要"冷"（冬夜、雨天）就压环境层的明度与饱和度，主体层照样可以柔光
5. 交付前用第 10 项自检做验证：**遮住人物，背景能不能一眼看出季节**

### 光线 × 肤色耦合矩阵（v1.6 改写版）

| 目标肤色 | 主体受光（必写） | 环境调性（必写） | 允许 | 禁止 |
|---|---|---|---|---|
| 冷白皮 / 白瓷感 + **盛夏海边** | 柔和漫射日光、树荫或遮阳伞下的散射光、反光板补光 | 明亮通透的高调曝光、高饱和青蓝海水、鲜绿椰叶、白得发亮的沙滩、锐利短投影 | 背景与水面金色高光、发丝轮廓光 | 整图阴天灰蓝、冷灰色调、暖光直射面部、把沙滩强反光当主光直打脸 |
| 冷白皮 + 室内 / 影棚 | 柔光箱、窗边漫反射 | 按场景定（可冷可暖） | 冷调补光 | 硬光顶光压出脏阴影 |
| 健康小麦色 + 海边 | 午后斜阳直射 | 金色时刻、暖调 | 强反光 | 阴天冷光（会显灰白） |
| 通透奶油肌 | 逆光轮廓光 + 正面柔和补光 | 明亮通透 | 逆光金边 | 硬光顶光 |

**旧版错误做法（已废弃）：** "要白皮 → 整张图阴天柔光、避开海滩强反光、二选一"。这条规则能保肤色，但会把所有夏日/海边/阳光场景压成冷灰调，代价比肤色偏移大得多。**正确做法是分层，不是二选一。**

**唯一仍然必须避开的：** 暖色直射光（日落金光、正午硬光）直接打在人物脸上——那才是真的会把白皮晒深。

### 氛围与季节锚点（决定"像不像"，比肤色更容易被忽略）

**问题本质：** 用户说的"夏天""冬日""深夜""清晨"是**氛围词**，模型不会自动翻译成画面要素。不翻译，它就按通用默认（中性、偏冷、偏灰）出图，于是"技术全对，感觉全错"。

**四要素翻译法——任何氛围词都必须落成这四格里的具体事实：**

| 要素 | 盛夏海边（热） | 冬夜街头（冷） | 清晨室内（柔） |
|---|---|---|---|
| **光** | 明亮通透的高调曝光、充足日光、被薄云柔化 | 低照度、路灯点光源、高对比 | 侧窗斜射、柔和低反差 |
| **色** | 饱和青蓝海水、鲜绿椰叶、白到发亮的沙、透亮蔚蓝天空 | 深蓝黑、冷白灯光、湿地面反光 | 米白、浅木色、暖灰 |
| **物** | 草编遮阳帽、挂水珠的冰饮、条纹沙滩巾、椰树、海鸥、遮阳伞、白色帆船（⚠️ 想露脸就别放"墨镜"道具，模型会让它上脸，见问题16） | 大衣领口、呼出的白气、霓虹招牌、雪堆 | 冒热气的咖啡杯、棉麻窗帘、绿植 |
| **影**（热感的隐藏开关） | 短而锐利的投影、被阳光晒亮的沙面反光 | 长而软的影子、湿反射 | 柔和的渐变阴影 |

**反向排除（必须写）：** "不要阴天灰暗、不要冷灰调、不要降低饱和度、不要冬日清冷感"。

**验证法（第 10 项自检的具体操作）：** 把人物遮住，只看背景——能不能一眼说出"夏天海边"？说不出来，就是氛围没写，必须补，而不是靠调衣服。

**一个反直觉的要点：** 承载"热感"的往往不是人物，而是**环境的高光与投影**。同一套衣服，把背景从"灰蓝阴天"换成"高饱和青蓝 + 锐利短投影"，"夏天"立刻就出来了。

### 季节与服饰的一致性（很容易被忽略）

**问题：** 写了"夏日清凉"，模型照样给你长袖针织裙——因为"包臀裙 + 针织"的材质先验盖过了"清凉"这个抽象词。

**解法：**
1. 把"清凉"翻译成**可核对的事实**：细吊带、露肩、无袖、短袖、露背、裙长及大腿中部、面料轻薄透气
2. 明确排除："不要长袖、不要针织长袖、不要外套"
3. 抽象词只做总结，不承担主要信息量——真正干活的是那些具体名词
4. **服饰只是季节感的一半**：衣服对了，环境和光错了照样不像夏天。服饰句与《氛围与季节锚点》必须成对写，缺一半都会翻车
5. 注意"长裙/开叉长裙"是模型对"包臀裙"的高频误读，要"短款"就显式写"裙摆短至大腿中部，不要长裙、不要开叉长裙"

## 提示词结构规范（Markdown 分段 + 着重标记·默认写法）

> **本节是默认写法，不是可选项。** 除用户明确要求"一条逗号串到底"外，交给生成工具的提示词一律按本节写。
>
> **本节管的是"提示词写得对不对"，不管"图片出得对不对"。** 结构合规不能替代出图后的《生成后自检闸门》11 项核对——**生成前结构自检 + 生成后图片自检，两层都要过，缺一层都不算完**。

### 为什么改成结构化

旧写法是一条几百字的逗号长串，问题有三：

1. **漏项无法自查**——看不出"清凉"落在哪句、"禁止"到底有没有写
2. **权重被稀释**——关键约束淹没在中段，模型前半段抓人物、后半段抓氛围，谁都没抓住
3. **改动会连坐**——改鞋子要重写整条串，很容易把已经命中的肤色句改坏

结构化的三条收益：**分段 = 可核查**（每个标题对应一类需求）、**标记 = 提权重**（着重词把约束从叙述里拔出来）、**列表 = 可局部替换**（改一条不碰其他条）。

### 标准形态（照此抄）

```markdown
## 人物
<族裔面孔 + 五官结构逐项 + 肤色 + 年龄与年轻特征 + 身形比例 + 发型 + 服装（材质/剪裁/长度）+ 鞋（高度/颜色/鞋型/鞋跟）+ 配饰>

## 动作
<姿态 + 身体朝向 + 手部位置 + 视线方向 + 表情与眼神 + 腿部交叠/脚背等细节>

## 环境
<季节与场所 + 天气与时间 + 主体受光 + 环境调性 + 色彩 + 2–4 个季节道具 + 投影形状>

## 要求
- 【重要】画面清晰，真实画风
- 【禁止】包含眼镜
- 【重要】全身出镜
```

**四个标题的写法约定（对齐用）：**

- `人物` / `动作` / `环境` 三段写**陈述性正文**（2–4 句连写即可，也可分条），不强制每句带标记
- `要求` 段**必须写成列表，且每一条都以着重标记开头**——这一段的每行都是硬性收口，不允许出现"没带标记的裸句子"
- 简写等价：`## 人物` 可写成行首标签 `人物：`，两种都算合规；**推荐用 `##`**，因为模型对行首的结构标记更敏感

### 四个大标题的职责边界（顺序不可调换）

| 顺序 | 标题 | 装什么 | 不许混进来的东西 |
|---|---|---|---|
| 1 | `人物` | 族裔/五官/肤色/年龄/身形/发型/服装/鞋/配饰——**人本身的一切** | 环境、光线、画质、排除声明 |
| 2 | `动作` | 姿态、手部位置、视线方向、表情、身体朝向、交叠腿/绷脚背 | 服装款式（属人物）、环境道具 |
| 3 | `环境` | 季节与场所、天气与时间、主体受光 + 环境调性两句、色彩、道具、投影、背景排除 | 人物五官、服装、画质 |
| 4 | `要求` | 硬性收口：清晰度与真实感、构图完整、解剖正确、面部无遮挡、画面干净、调性一致 | 新的场景参数（该放环境）、新的服装（该放人物） |

**为什么 `人物` 必须第一：** 模型对越靠前的内容权重越高。身份信息被推到中后段，就会被前面的氛围词和后面的服装词冲淡，出来的脸最先跑偏。

**定调例外（唯一允许插队的一句）：** 若场景对氛围极度敏感（盛夏海边、冬夜街头、暴雨夜），允许在 `## 人物` **之前**加 **一行、≤30 字**的定调句，例如 `# 定调：盛夏热带海岛正午，明亮通透的高调曝光，色彩明快鲜亮`——**只此一句，且下一行必须立刻是 `## 人物`**。

### 着重标记体系

| 标记 | 管什么 | 判失败的标准 | 典型用法 |
|---|---|---|---|
| `【必须】` | 不可协商的硬约束 | 缺了就算不合格（对应自检 1–5 项） | `- 【必须】东亚中国面孔，杏眼内双、眼型细长上挑` |
| `【重要】` | 高权重但可微调 | 明显偏了要改提示词，允许小幅偏离 | `- 【重要】画面清晰，真实画风` |
| `【禁止】` | 明确排除 | 出现即不合格 | `- 【禁止】包含眼镜` |
| `【建议】`（可选） | 加分项 | 不满足不算失败 | `- 【建议】椅背搭一条蓝白条纹沙滩巾` |

**六条用法硬规则：**

1. **标记写在句首**，紧跟被约束的内容；禁止写成"人物是东亚面孔（必须）"这种尾注——模型读到句尾时权重已经分配完
2. **一句一个标记**，禁止叠用（`【必须】【重要】`）；要强调就拆成两条
3. **每条 `【禁止】` 尽量配一条正面兜底的 `【必须】`/`【重要】`**：`【禁止】包含眼镜` 要配 `【重要】完整清晰的面部与双眼，眼睛眉毛睫毛可见`。只有否定句时模型常照做反义——这是《问题16》踩过的坑
4. **同一维度先正后反**：先写"要什么"，再写"不要什么"；顺序反过来，模型容易只抓住最后半句
5. **一条 `【禁止】` 不超过 3 个排除项**，超过就拆条；长排除串会互相稀释，最后什么都不生效
6. **`要求` 段的标记要克制**：全段 5–9 条为宜，条条 `【必须】` 等于没有 `【必须】`

### `要求` 段的推荐顺序（五组，可按需增删）

1. **清晰度与真实感**：`【重要】画面清晰，真实画风`、摄影参数、`【禁止】动漫感/塑料感/油画感`
2. **构图完整性**：`【重要】全身出镜，头顶到鞋跟完整入画`、`【禁止】裁切`
3. **解剖正确**：`【必须】手指脚趾分明`、`【禁止】多余肢体/扭曲关节`
4. **面部无遮挡**：`【必须】完整面部与双眼清晰可见`、`【禁止】包含眼镜`（详见《问题16》）
5. **画面与调性**：`【禁止】路人/杂物/文字`、`【重要】冷暖调性与季节一致`（夏天不许冷灰、冬天不许暖橘）

### 生成前结构自检（6 问，缺一项就回去补）

1. 四个标题是否齐、顺序是否对（人物 → 动作 → 环境 → 要求）？
2. `要求` 段是否每条都带标记、没有裸句子？
3. 每个 `【必须】` 是否都能对上用户口头需求里的某一项？（对不上 = 写多了；用户提了却找不到 = 漏了）
4. 每条 `【禁止】` 是否都有正面兜底句？
5. `环境` 段里"主体受光"和"环境调性"是否分成两句？
6. 提交给工具时，是否去掉了 Markdown 代码围栏（` ``` `）和"以下是提示词"这类寒暄，只留正文？

## 常见问题解决

> **先记住：下面每一条的"解决方案"都是「改提示词」的动作，不是「自动重试」的许可。** 改完以后要把改动点和建议写进第一版检查报告，**等用户放行再发起下一次生成调用**（见文首《生成策略·调用预算》）。把"换模型""再出一版"当成可以自己连做的动作，是烧用户钱的最常见方式。

### 问题1：生成的图片不是全身照

**原因：** 描述词没有强调全身构图

**解决方案：**
- 明确声明："人物全身出镜"
- 描述头部和脚部细节作为锚点
- 强调："手指脚趾分明"
- 使用35mm镜头而非85mm镜头

### 问题2：图片看起来像CG或插画

**原因：** 缺少真实感关键词

**解决方案：**
- 添加"电影级写真风格，专业真人摄影"
- 添加"真实高端布料，布料纹理清晰"
- 添加"细腻真人皮肤纹理"
- 明确排除："不要出现动漫感、漫画感、塑料感、油画感"

### 问题3：人物面部不够真实

**原因：** 面部描述不够具体

**解决方案：**
- 使用身份基线的五官锚点："东亚中国面孔、杏眼内双、鼻梁细窄挺直、鼻头小巧、薄唇樱粉、柔和鹅蛋脸"
- 强调"肤若凝脂"、"白瓷般冷调白皙肤色"
- 添加"细腻真人皮肤纹理"

### 问题4：亚洲面孔但皮肤太黄 / 太深

**原因：** 模型偏见（亚洲面孔默认黄皮肤）＋ 光线把肤色晒深，两者常常同时发生

**解决方案：**
- 用《人物身份基线》的默认肤色写法："极白的冷白皮，白瓷般冷调白皙肤色"
- 排除清单要写全："不要小麦色、不要古铜色、不要蜜色、不要偏黄、不要暗沉"
- 加全场一致约束："全身肤色与脸部一致雪白"
- **同时检查光线**：如果场景写的是暖阳直射/金色时刻，先改光线，光改形容词是无效的

### 问题5：白皮肤但变成欧洲面孔

**原因：** 模型偏见（白皮肤默认欧洲面孔）；"冷白皮 + 五官精致"这类写法本身带欧美先验

**解决方案：**
- 族裔与肤色**成对指定**，不要只写其中一个
- 用可观察的五官结构锚定：杏眼内双、眼型细长上挑、鼻梁细窄挺直、鼻头小巧、薄唇、柔和鹅蛋脸
- 排除声明："不要混血感、不要欧美面孔、不要拉丁面孔、不要东南亚感"
- 更完整的操作见《偏见维度的通用处理法》

### 问题6：手指脚趾模糊或多余

**原因：** AI生成常见问题

**解决方案：**
- 明确声明："手指脚趾分明，不要出现肢体多余问题"
- 强调"保证人物清晰"
- 添加"顶级清晰度"

### 问题7：图片虚焦模糊

**原因：** 缺少清晰度要求

**解决方案：**
- 明确声明："保证人物清晰，不出现虚焦模糊"
- 添加"高清画质"、"顶级清晰度"
- 使用"大师级的获奖作品"提升整体质量

### 问题8：服装细节丢失

**原因：** 服装描述过于简单

**解决方案：**
- 分层描述：外套、内搭、下装
- 描述材质："真实高级质感布料，布料纹理清晰"
- 描述颜色细节："深蓝色渐变"、"黑色修身"
- 描述配饰："银色细链项链"、"金色扣饰"

### 问题9：场景与人物不协调

**原因：** 场景描述与人物风格不匹配

**解决方案：**
- 确保场景风格与人物风格一致
- 描述场景光线与人物光线的关系
- 使用统一的色调关键词

### 问题10：生成效果不稳定，时好时坏

**原因：** 使用了笼统、抽象的描述词

**解决方案：**
- 使用明确的事实性描述（见"重要技巧"章节）
- 用"20岁"替代"年轻"
- 用"九头身比例"替代"腿长"
- 用具体服装名称替代"时尚"
- 用具体场景描述替代"高档"

### 问题11：用户说了"清凉/厚重/正式"，出来的衣服还是不对

**原因：** 材质先验压过了抽象的场景词（"包臀裙 + 针织"→长袖）

**解决方案：**
- 抽象词必须配可核对的事实："垂坠感真丝无袖"而不是只写"清凉"
- 显式排除相邻错项："不要长袖、不要针织长袖、不要外套"
- 详见《季节与服饰的一致性》

### 问题12：已经交代过的要求，下次还得再强调一遍

**原因：** 要求只停留在对话里，没有沉淀进"默认基线"，于是每次生成都要重新手工补

**解决方案：**
- 反直觉但有效：**把一次性的口头要求，升级成技能里的默认值**
- 判断标准：这条要求是"这次专用"还是"以后大概率还要"？后者就该写进《人物身份基线》的默认格，或写进 Checklist 的固定核对项
- 但默认值要克制：只在**普适性成立**的维度上设默认（肤色/族裔/比例/光线这类跨需求稳定的属性），一次性元素（今天的服装颜色、道具、姿势）不设默认
- 交付前用《生成后自检闸门》兜底，**把问题在第一版报告里说清楚**；要不要重出由用户决定，不要自己偷偷再调一次

### 问题13：生成的图看着比要求老（"25岁出来像30岁"）

**原因：** 年龄数字是相对刻度，各模型有系统性"显老"偏移；而且只写数字、不写年轻特征时，模型只能靠"25岁"这个孤立刻度去猜，往往猜偏大

**解决方案：**
- **下锚**：默认用 20 岁，可接受区间 18–23；不要拿 24、25 当"年轻"
- **双锚**：数字 + 可观察特征（胶原蛋白充足、皮肤紧致、脸颊微带婴儿肥、无眼袋、无法令纹、无眼角细纹、少女感）
- **反向排除**：不要成熟感、不要中年感、不要眼袋、不要法令纹、不要眼窝凹陷、不要面部松弛
- **别写矛盾组合**："20岁 + 成熟御姐气场"要拆开处理——气场靠姿态/眼神/穿搭表达，不要靠脸部年龄感表达
- 详见《年龄锚定的偏移校正》

### 问题14：画面太冷 / 不像夏天海边，但肤色是对的（本技能最大的一次返工）

**症状：** 白皮对了、服装对了、全身也对，但整图灰蓝、没有太阳味，用户一句"太冷了，感觉不到夏天"。

**真实根因（三处叠加，缺一不可）：**
1. 身份表把"光线"默认成"柔光/阴天漫射"——这是**为保肤色牺牲场景**的默认值
2. 《光线与肤色的耦合规则》写成"白皮 ↔ 阴天，且必须避开沙滩强反光"，把"海边 + 白皮"判定成互斥，唯一合法解就是阴天
3. 通用真实感锚点里写死了"画面冷色调"，被复制到每张图末尾

**解决方案（分层修，不要整段重写）：**
- 保留肤色句不动（它是对的）
- 把原来那**一句**"阴天柔光"拆成**两句**：主体受光（保白皮）+ 环境调性（保夏天）
- 环境层加："明亮通透的高调曝光、饱和度很高的青蓝色海水、鲜绿椰叶、白到发亮的沙滩、短而锐利的投影、画面明快鲜亮"
- 加反向排除："不要阴天灰暗、不要冷灰调、不要降低饱和度、不要冬日清冷感"
- 删掉任何"画面冷色调"，换成"色彩通透有层次"
- 加 2–4 个季节道具（草编帽、墨镜、挂水珠的冰饮、条纹沙滩巾、椰树、海鸥）——道具是最便宜的季节信号
- 详见《双层光照模型》《氛围与季节锚点》

**验证：** 遮住人物看背景，能否一眼认出夏天海边。

### 问题15：环境很空，季节感全靠人物硬撑

**原因：** 只描述了人物和地面/墙面材质，没有任何"季节性道具"与"光影痕迹"，模型给的背景是通用中性背景。

**解决方案：**
- 每张图至少给 **2–4 个季节道具**（见《氛围与季节锚点》四要素表"物"这一格）
- 至少给 **1 条光影痕迹**：锐利短投影（夏日正午）/ 长而软的影子（黄昏）/ 湿地面反光（雨后夜街）
- 道具要**与人物不抢焦点**：描述其"虚化""在背景中""在小圆桌上"，避免抢主体

### 问题16：海边 / 强光场景，人物被模型自动戴上墨镜遮住脸（v1.6 验证时新发现）

**症状：** 描述里根本没提墨镜，出来的 3 张里有 2 张人物自己戴上了大框墨镜，脸被遮掉一半，"御姐眼神"和"面部五官锚点"全部失效。

**原因（两条，第二条是实测才发现的）：**
1. "海滩 + 强光 + 冷峻气质"这组词会激活模型的道具先验，太阳镜是高频补全项；墨镜还能帮模型"回避"难画的眼睛
2. **手部动作靠近面部会诱发道具上脸/上手**——凡是写了"手托下颌、手扶脸颊、手搭在头侧"，模型极易给这只手塞一副墨镜（实测：加了"不戴墨镜"仍 3 张里 2 张中招，且两张都是手在脸旁）

**解决方案（按有效性排序）：**
1. **改手的位置**（最有效）：让双手离开头部——"一只手搭在椅臂上，另一只手自然放在膝上"；真要摸脸就写明"手指轻触脸颊，手中不握任何物品"
2. **正向描述代替纯否定**："完整清晰的面部与双眼，脸上没有任何遮挡物，眼睛、眉毛、睫毛清晰可见"，比单独写"不戴墨镜"更管用
3. 保留否定句作补充："不戴墨镜、不戴太阳镜"
4. **不要把"墨镜"写进氛围道具清单**——那等于主动递刀。要墨镜造型感时，写"墨镜推在头顶 / 挂在手上"
5. 上述都失效 → 换模型（Wan/Vidu）或换构图（手部完全离开画面上半部）

**交付前检查：** 第 1、3 项自检在脸被遮住时根本无法判定，等于两项失效——脸被遮住就按不合格处理。

11. **自检闸门**：交付前自己过一遍 11 项清单，把不合格项写进第一版报告，**不自行重生成**
12. **一次一调用**：默认 1 次生成调用，追加必须用户放行；"多出几张让你挑"是禁止项
13. **事实性描述**：使用明确的事实替代笼统描述（如"20岁"替代"年轻"）
14. **光线分层**：主体受光管肤色、环境调性管氛围，**永远是两句话，不是一句"阴天柔光"**
15. **抽象词必须有具体名词兜底**："清凉"要落到细吊带/无袖/短裙上；"夏天"要落到高调曝光/高饱和/锐利短投影/季节道具上
16. **数字要有特征配平**：年龄、身材这类数字锚必须配可观察特征，否则模型会按自己的先验偏移
17. **氛围单独成项**：交付前遮住人物看背景，认不出季节/场所就是没过
18. **色调词不许进通用块**：冷暖写进场景句，通用锚点里只留"色彩通透有层次"
19. **结构化优先**：提示词按"人物 / 动作 / 环境 / 要求"四段写，`要求` 段逐条带 `【必须】/【重要】/【禁止】`——分段才可核查，标记才提权重
20. **禁止要成对**：每条 `【禁止】` 后面都要有正面兜底的 `【必须】`，否则模型会照做反义

## 注意事项

1. 图片生成是异步任务，需要等待
2. 每次调用生成工具通常返回3张图片
3. 描述词使用中文，模型对中文理解良好
4. 避免过于复杂的场景，保持焦点在主体
5. 人物描述要具体，避免模糊词汇
6. 全身照必须使用锚点技巧
7. 写实风格必须添加排除声明和质量保证
8. **族裔 + 肤色是天然的组合维度，必须成对指定**（只写一个必然漂移）
9. 用户未明确要求时，使用完整基础锚点减少调整轮次
10. **默认只调用 1 次生成工具**；出图后先自检、出第一版报告，等用户同意才追加——"不好看就再来一版"是烧用户的钱，必须用户自己拍板
11. 必须包含质量保证关键词：手指脚趾分明、不出现肢体多余问题、不出现虚焦模糊
12. **使用明确的事实性描述，避免笼统、抽象的形容词**
13. **写"白皮"时禁止让暖光直射面部**（日落金光、正午硬光）；但**不必把整个场景写成阴天**——换成"主体柔光 + 环境高亮"即可
14. **用户提出的每一条要求，都要能找到描述词里对应的那一句**；找不到就是漏了，不是模型不听话
15. **默认年龄锚 20 岁（18–23，硬上限 25）**；只有用户明确给年龄、或说了"中年/老年/学生/JK/退休"这类指向词才偏离；"御姐/成熟/知性/干练"属于**风格词**，落到穿搭与气场上，绝不用来抬年龄
16. 年龄、身高、罩杯这类数字必须配可观察特征，纯数字会被模型按先验偏移
17. **季节/氛围必须有独立的描述句**，只靠服装和"夏日清凉"这类抽象词不生效
18. **"包臀裙"要配"短款"约束**：不写"裙摆短至大腿中部，不要长裙、不要开叉长裙"，模型常给长裙开叉款
19. **提示词默认用 Markdown 四段写**（人物 / 动作 / 环境 / 要求），`要求` 段每条都以 `【必须】/【重要】/【禁止】` 开头；交出提示词时也把这个结构展示给用户，方便他自己加约束
20. **着重标记只标真正要紧的**：`要求` 段 5–9 条为宜；满屏 `【必须】` 等于没有 `【必须】`
21. **`【禁止】` 必须配正面兜底**：只写"禁止眼镜"模型会自行发挥，要同时写"完整面部与双眼清晰可见"
22. **提交工具前去掉围栏与寒暄**：` ``` ` 与"以下是提示词"这类话要删掉，否则会被当成画面内容或稀释正文权重

## 总结

掌握本技能的核心理念：
- **精准描述**：细节决定成败
- **年龄判定优先**：先判"该不该改年龄"，再判"改成多少"——默认 20 岁（18–23，上限 25），只有明确年龄数字或中年/老年类指向词才偏离；御姐/成熟/知性是风格词，写在穿搭与姿态上
- **身份基线**：五个维度显式赋值，留空即失守
- **年龄双锚**：数字定区间（20 岁 / 18–23）、特征定观感（无法令纹无眼袋、少女感），只写数字必偏老
- **锚点思维**：确保构图完整
- **质量保证**：清晰度、手指脚趾分明、无肢体问题
- **真实感**：使用摄影参数和排除声明
- **模型匹配**：选择最合适的工具
- **偏见处理**：正面赋值 + 特征细化 + 反向排除 + 全场一致 + 光线适配（普适公式，不是某个族裔的补丁）
- **双层光照**：肤色由"主体受光"决定，季节感由"环境调性"决定——两件事分开写，白皮和盛夏可以同时成立
- **氛围锚点**：氛围词必须落成光/色/物/影四要素，并有独立自检项；遮住人物看背景能否认出季节
- **自检闸门**：交付前自己当质检员，把问题如实写进第一版报告
- **调用预算**：一次需求 → 一次调用 → 出报告 → 等用户放行 → 才追加；只有"结果完全不可用"的技术性失败才允许不请示重试 1 次
- **事实性描述**：使用明确的事实替代笼统描述
- **结构化提示词**：人物 / 动作 / 环境 / 要求 四段 Markdown，`要求` 段逐条带 `【必须】/【重要】/【禁止】`；分段为了可核查，标记为了提权重

**判断一条描述词是否合格的标准**：把用户的每句口语需求逐条对照过去，都能在描述词里指到具体那一句——指不到，就补上再生成。**再加一条**：把所有人物句删掉只读环境句，读出来的季节/场所必须是用户要的那个。

通过本技能，你可以以最少调整次数生成符合预期的高质量图片。
