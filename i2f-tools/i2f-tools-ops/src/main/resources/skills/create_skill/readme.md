# Skill 创建与安装

- skill 是一个定义用来进行知识复用的文档驱动的规范
- 用一组 markdown 文件来描述一个技能
- skill 一定包含一份入口文件 `SKILL.md`
- 然后根据不同 skill 目标不同，可能包含对应的附加的 资源 与 脚本
- 这些资源与脚本是为了提供完成目标所需要的辅助内容
- skill 使用独立的文件夹进行相互隔离

## Skill 创建

- 首先给出目录结构
- 下面的代码块中，就给出了目录结构
- 其中，使用 `{{...}}` 进行占位

```shell
{{技能名称，由英文小写字母与下划线构成}}
    SKILL.md
    ...
```

### 入口文件与基础格式

- 因此，我们需要先使用技能名称创建一个文件夹
- 为了不同系统环境兼容、避免字符编码带来的路径问题
- 因此，对技能名称进行规范化
    - 要求：技能名称必须是由英文小写字母与下划线构成，不得包含其他任意符号
    - 例如：search_weather
- 接着，在目录下创建 `SKILL.md`
- 这个文件名称是约定的强制的，必须为这个名称，否则框架运行识别不到
- 下面给出 `SKILL.md` 文件编写的基础格式
- 其中，使用 `{{...}}` 进行占位

```markdown
---
name: {{技能名称，由英文小写字母与下划线构成，必须与文件夹名称相同}}
description: {{技能描述，使用简短的文本，描述技能提供的哪些能力，作用是充当一份目录，能够快速找到此技能，不得超过250字}}
version: {{技能版本，一般默认为：1.0}}
author: {{技能作者，根据实际情况填写即可，没有明确时，可以直接使用当前环境的用户名}}
tags: {{技能标签，使用英文标识符表示，多个标签使用半角逗号分割，不得超过10个标签}}
---

# {{技能标题，一般就是此技能提供的主要作用，不限制规范}}

- {{技能的一般性简短介绍}}

{{技能内容，根据实际情况编写}}
```

### 技能内容部分补充

- 当篇幅长、内容多时，应该拆分为子 markdown 文件，通过链接指向
- 如果涉及脚本内容，较短时可以直接使用代码块表达，较长时，应该单独保存为对应格式的脚本文件，通过链接指向
- 技能内容风格与约定指导
    - 技能一般可能包含如下几个部分
        - 技能概述：简短描述技能提供的能力
        - 前置条件：使用此技能需要哪些前置条件，比如一些脚本，可能需要安装对应的开发环境
        - 实施步骤：使用此技能需要遵循哪些步骤，怎么按照步骤一步一步的完成目标
        - 检查规范：使用此技能有哪些需要进行检查的规范性内容、要求、限制等
        - 输出要求：如果是输出型的技能，输出内容有哪些要求，比如格式、大小、长度等
        - 注意事项：使用此技能有些什么注意事项，比如安全、性能等方面
    - 根据不同的技能实际情况，灵活调整各个部分

weather_search

- 然后编写 SKILL.md

name: weather_search

# 天气查询

- 根据用户提供的城市名称、区划编码信息，查询天气信息

## 前置条件

- 环境安装了python环境
- 提供的是城市名称或者区划编码

## 实施步骤

- 提供城市名称或者区划编码
- 城市名称要求，应该是标准中国城市名称，例如：重庆市、北京市
    - 只支持城市，不支持区县、省级名称
- 区划编码要求，应该是4位地市编码，例如：3502,5201
- 然后调用python脚本 `web_weather.py` 获取数据
- 用法：

```shell
web_weather.py -city_name [城市名]
web_weather.py -city_code [区划编码]
```

- 这个脚本是一个爬虫脚本，因此执行较慢
- 不建议进行并发高频调用

## skill 的安装

- 一般情况下，skill 都存放在当前目录下的一个总目录中
- 一般这个目录被命名为 `.skills` 或者 `skills`
- 如果有这个目录，并且有权限操作，可以将创建的创建的技能移动到此目录下
- 否则，应该告知用户创建好的技能的路径，让用户自行添加到自己的技能存放目录中
- 另外要提示用户，如果系统没有加载到技能，应该检查存放路径或是重启自己的应用
