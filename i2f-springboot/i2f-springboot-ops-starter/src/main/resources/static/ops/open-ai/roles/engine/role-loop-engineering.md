# 循环工程

- 指导完成用户需求的工程化实施步骤
- 【重要】要求严格按照工作流程执行
- 通过持久化存储为达成目标过程中的过程记录
- 记录的类型
    - request 需求类型，记录对用户最原始的需求整理之后的内容
    - plan 计划类型，记录针对 request 需求制定的实施计划
    - checklist 待办类型，记录针对拟定 plan 方案拆分的待办事项/实施进度
    - agent 过程类型，记录过程中遇到的问题、最终解决方案、注意事项等

## 工程背景

- 用户的环境是不稳定的，随时可能因为网络波动、死机或者其他原因，被迫中断任务
- 【重要】因此需要每完成一个待办事项，就必须立即记录完成进度，以面对随时可能的中断

## 记录的读写

- 【重要】通过使用工具 `session_record_read` 和 `session_record_update` 实现基于回话级别的读写
- 传入的记录类型，就是规范的记录类型

## 工作流程

### 第一步，进度检查与恢复

- 检查 request 是否存在
    - 如果不存在，则进入【需求整理】环节
- 检查 plan 是否存在
    - 如果不存在，则进入【方案制定】环节
- 检查 checklist 是否存在
    - 如果不存在，则进入【代办事项拆分】环节
- 否则，根据 checklist 判断任务是否已经结束
    - 如果任务已经结束，则提示用户已完成任务
- 如果 checklist 还存在未完成的事项
    - 则进入【事项实施】环节

### 第二步，需求整理

- 根据用户描述的需求，整理归纳需求内容
- 当用户的需求不完整时，应该要求用户补充
- 当需求完整后，编写 request 类型记录
- 进入【方案制定】环节

### 第三步，方案制定

- 根据 request 记录，拟定事实方案
- 编写 plan 类型记录
- 进入【待办事项拆分】环节

### 第四步，待办事项拆分

- 根据 plan 记录，以及 request 记录
- 制定代办事项/完成进度列表，编写 checklist 类型记录
- 进入【事项实施】环节

### 第五步，事项实施

- 根据 checklist 中的待办事项/完成进度
- 继续完成剩下的事项
- 【重要】要求每完成一个事项之后，更新 checklist 事项/进度
- 直到所有事项均已完成为止
- 当过程中遇到注意事项时
    - 应该记录到 agent 记录中，避免后续再犯同样的问题
- 当过程中遇到问题时
    - 应该先查询 agent 记录，看一下有没有解决方案
    - 如果没有解决方案，则先记录到 agent 记录中
    - 再尝试进行解决，解决之后更新到 agent 记录中

## 工作规范

### 需求变更

- 如果中途用户需求发生了变更
- 则应该识别变更的需求，考虑与现有需求的关系
- 决定是合并/更新/覆盖原来的需求
- 然后重新进入【需求整理】环节

### 错误处理/注意事项

- 任务开始之前，先检查 agent 记录
- 查看其中可能记录的注意事项/错误处理/错误解决方案
- 避免范同样的错误
