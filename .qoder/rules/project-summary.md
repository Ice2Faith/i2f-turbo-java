# 项目资料总结

## 目的

- 按照固定的步骤，系统化的理解项目
- 并且根据步骤，输出各个阶段的文档
- 构建完善的项目文档索引目录
- 并且对文档组织结构进行索引化
- 形成渐进式项目文档披露

## 文档编写规范

- 下文中提到的文档
- 统一存放在项目根目录的 `docs` 目录中
- 要求，单个文档的长度不超过2500字符
- 如果超出字数限制，则应该变为一个目录
- 文档拆分存放到目录中
- 并且对目录添加额外的目录索引文档
- 进行索引连接到拆分文档

## 总体步骤

- 技术架构识别
- 核心依赖识别
- 核心构件识别
- 运行环境识别
- 核心业务识别
- 主要业务流识别
- 非功能性需求识别
- 特殊处理逻辑识别

## 信息来源

- 主要依靠项目源代码、项目内的文档
- 另外，如果项目被 git 等版本管理工具管理
- 则 git 的提交历史，也可作为信息参考来源
- 但是应该始终以源代码为准
- 因为，git 提交消息、文档、注释等，可能存在不准确或者错误

## 注意事项

- 注意，避免扫描依赖(node_modules等)、输出产物(classes等)、编译产物、日志目录等
- 注意，不要全盘扫描整个项目，以模块、目录为主、少量源码扫描

## 构建过程

### 技术架构识别

- 通过读取项目根目录文件形态
- 识别项目类型、识别项目配置项
- 比如 Maven、Gradle、Msvc、Python、Golang 项目
- 识别架构类型、架构风格
- 输出【01-技术架构】文档

### 核心依赖识别

- 识别项目使用的主要依赖
- 获取并推测技术方案
- 输出【02-核心依赖】文档

### 核心构件识别

- 判断项目组成的的核心模块
- 区分项目的公共模块、业务模块
- 模块划分、模块职责、模块组织关系
- 输出【03-核心构件】文档

### 运行环境识别

- 项目的运行形态
- 运行环境、运行平台
- 部署形态、单体、容器化、分布式、云原生等
- 输出【04-运行环境】文档

### 核心业务识别

- 通过业务模块的划分
- 判断模块的业务模型
- 初步梳理总体核心业务模型
- 判断哪些是核心业务、哪些是主要业务流
- 可通过模块的代码行数、源代码数量进行判断
- 输出【05-核心业务】文档

### 主要业务流识别

- 针对重模块、核心模块的源代码
- 以及架构风格
- 梳理核心的业务流
- 得出N条核心业务流程
- 输出【06-主要业务流】文档

### 非功能性需求识别

- 梳理公共模块、非功能性模块
- 识别项目主要的非功能性诉求
- 得出主要的权衡点、敏感点
- 梳理得到项目的核心质量属性
- 输出【07-质量属性】文档

### 特殊处理逻辑识别

- 通过模块的划分
- 识别一些不常见的模块
- 用来判断项目特殊性的处理
- 这种往往具有一定的业务特殊性、管理特殊性、政策特殊性等
- 往往需要特殊考虑或者处理
- 输出【08-特殊处理】文档
