# 模块文档编写

- 当用户需要编写模块文档时
- 阅读对应模块的代码实现了解实现
- 编写模块文档、更新索引文档
    - 如果模块文档已经存在，检查并进行更新
- 示例中使用 `{{}}`包裹的内容需要你进行根据模块实际情况补充
- 如有需要图表呈现
    - 优先使用mermaid进行嵌入到文档中
        - 以代码块 `mermaid` 语言类型进行包裹mermaid图形
    - 其次可以单独撰写独立的svg文件，并通过连接引入文档中
        - svg文件，应该包含标准的xmlns
        - svg文件存放到引用进去的文档的 `./imgs/svg-{全英文snakecase名称}.svg` 文件中
        - 比如文档为：/common/text/readme.md
        - 这svg文件存放路径为：/common/text/imgs/svg-xxx.svg

## 模块文档路径存放要求

- 按照模块相对于仓库根目录的路径，对应存放到仓库根目录下的 .wiki/modules/ 下面
- 举例：
    - 模块路径：/common/text/pom.xml
    - 那么文档存放路径：.wiki/modules/common/text/readme.md

## 索引文档要求

- 索引文档路径：.wiki/modules/menus.md
- 索引文档编写要求
    - 按照模块路径，划分标题级别
    - 具体示例格式如下

```markdown
# {{仓库名称}}

> {{一句话总结仓库作用、提供能力、设计目的}}

## {{一级子模块名称}}

> {{一句话总结子模块作用、提供能力、设计目的}}

- 详细文档：{{指向模块的模块文档}}

### {{二级子模块名称}}

{{依照格式类推}}

```

## 模块文档要求

- 编写模块文档，基础内容格式要求如下

```markdown
# {{模块名}}

> {{一句话总结模块作用、提供能力、设计目的}}

## 模块路径

- `{{模块相对于仓库根目录的路径}}`

## 模块依赖

{{列出表格，说明使用的依赖，maven坐标、scope、optional，项目内部依赖排在前面、三方依赖排在后面}}

## 模块设计

{{分点说明模块的设计，可能包含这些方面：架构设计、模块设计、设计模式、算法设计、包结构等}}

## 模块目的

{{模块设计达成的目的}}

## 模块功能

{{模块提供的功能}}

## 模块主要使用方法

{{描述模块核心类、主要的使用方法、注意事项等}}

## 模块特性总结

{{分点简单描述有哪些特性}}

## {{其他章节可以自行拓展}}

```
