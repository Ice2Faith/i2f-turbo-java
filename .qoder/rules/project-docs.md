# 模块文档编写

- 当用户需要编写模块文档时
- 阅读对应模块的代码实现了解实现
- 编写模块文档、更新索引文档
    - 如果模块文档已经存在，检查并进行更新
- 示例中使用 `{{}}`包裹的内容需要你进行根据模块实际情况补充
- 如有需要图表呈现
    - 优先使用mermaid进行嵌入到文档中
        - 以代码块 `mermaid` 语言类型进行包裹mermaid图形
    - 其次可以单独撰写独立的svg文件，并通过连接引入文档中
        - svg文件，应该包含标准的xmlns
        - svg文件存放到引用进去的文档的 `./imgs/svg-{全英文snakecase名称}.svg` 文件中
        - 比如文档为：/common/text/readme.md
        - 这svg文件存放路径为：/common/text/imgs/svg-xxx.svg

## 模块文档路径存放要求

- 按照模块相对于仓库根目录的路径，对应存放到仓库根目录下的 .wiki/modules/ 下面
- 举例：
    - 模块路径：/common/text/pom.xml
    - 那么文档存放路径：.wiki/modules/common/text/readme.md

## 索引文档要求

- 索引文档路径：.wiki/modules/menus.md
- 索引文档编写要求
    - 按照模块路径，划分标题级别
    - 具体示例格式如下

```markdown
# {{仓库名称}}

> {{一句话总结仓库作用、提供能力、设计目的}}

## {{一级子模块名称}}

> {{一句话总结子模块作用、提供能力、设计目的}}

- 详细文档：{{指向模块的模块文档}}

### {{二级子模块名称}}

{{依照格式类推}}

```

# Mermaid 编写检查清单

## 一、特殊字符与引号处理

- 节点或连线文本含特殊字符
    - 错误类型：节点标签或连线标签（如 |文本|、--文本-->）中包含括号 ()、方括号 []、花括号 {}、冒号 :、点号 .、斜杠 /
      或中文等，导致解析报错。
    - 识别方法：渲染失败，控制台报 Parse error。
    - 改正方法：必须使用双引号将文本包裹。节点如 A["REST API (v2)"]；连线如 A--"Iterators.of"-->B 或 A|"Iterators.of"|B。
- 标签内含引号冲突
    - 错误类型：文本内部本身需要显示双引号，导致外层引号被提前截断。
    - 识别方法：渲染失败或文本显示异常。
    - 改正方法：使用反斜杠转义：A["Error: \"Not Found\""]；或改用单引号包裹外层：B['Error: "Not Found"']。
- •全角符号混入
    - ◦错误类型：语法符号（括号、冒号、箭头等）使用了中文全角字符，或混入了不可见的 Unicode 字符。
    - ◦识别方法：渲染失败或显示异常。
    - ◦改正方法：严格检查并替换为英文半角符号。

## 二、节点 ID 命名规范

- 非法节点 ID
    - 错误类型：使用了中文、空格、连字符（如 API-v1）作为节点 ID。
    - 识别方法：报错 Invalid node id 或 Parse error。
    - 改正方法：节点 ID 仅限字母、数字和下划线，如 A["API-v1"]。
- 数字开头 ID
    - 错误类型：使用了数字开头的节点 ID（如 1stNode）。
    - 识别方法：报错 Parse error。
    - 改正方法：将 ID 改为字母开头，如 Node1["1stNode"]。

## 三、关键字冲突与连线陷阱

- 全小写 “end” 冲突
    - 错误类型：节点文本包含全小写的 end，导致 subgraph 等块结构提前闭合报错。
    - 识别方法：渲染失败，报 Parse error。
    - 改正方法：将文本改为大写（如 End / END）或用双引号包裹（如 A["end"]）。
- 连线首字母冲突
    - 错误类型：连接节点首字母为小写 o 或 x，被解析器误认为箭头形状。
    - 识别方法：渲染失败或连线显示异常。
    - 改正方法：在字母前加空格（如 dev--- ops）或改用大写（如 dev--- Ops）。
- 图表类型拼写错误
    - 错误类型：图表关键字拼写错误。
    - 识别方法：渲染失败或显示为纯文本。
    - 改正方法：检查关键字拼写，如将 flowchat 修正为 flowchart。

## 四、排版与格式规范

- 声明后未换行
    - 错误类型：graph LR 或 flowchart TD 等声明与后续代码粘连在同一行。
    - 识别方法：渲染失败。
    - 改正方法：确保声明后必须换行；若编辑器压缩换行，需用分号 ; 强制断句。
- 块结构未缩进
    - 错误类型：loop、alt、subgraph 等控制结构内部内容未缩进，导致渲染失败或结构混乱。
    - 识别方法：渲染失败或结构显示异常。
    - 改正方法：内部内容必须严格缩进（通常 2 个空格或 1 个制表符）。
- 块结构未闭合
    - 错误类型：多余的 end 关键字或嵌套结构不完整匹配。
    - 识别方法：渲染失败。
    - 改正方法：检查 subgraph、rect 等块结构是否成对闭合。

## 五、注释规范

- 行尾注释
    - 错误类型：在代码行末尾使用 %%、// 或 /* */ 进行注释，导致该行解析失败。
    - 识别方法：渲染失败。
    - 改正方法：注释必须以 %% 开头，且单独占一行。
- 非法注释符
    - 错误类型：使用 # 作为注释符。
    - 识别方法：渲染失败或 # 被当作其他语法解析。
    - 改正方法：将 # 替换为 %%（# 在 Mermaid 中有其他特殊含义）。

## 六、样式与转义字符

- 样式语句多余分号
    - 错误类型：class 等样式定义语句末尾添加了分号 ;。
    - 识别方法：渲染失败或样式未生效。
    - 改正方法：删除末尾分号，由换行符终止语句。
- 样式应用格式错误
    - 错误类型：节点 ID 与样式名之间未用空格分隔，或多个节点间未用逗号分隔。
    - 识别方法：样式未正确应用。
    - 改正方法：单节点：class A event；多节点：class A,B styleName。
- 特殊字符转义失败
    - 错误类型：文本中必须使用 # 或 ; 等符号，直接写入导致解析错误。
    - 识别方法：渲染失败。
    - 改正方法：使用 Mermaid 专属转义语法（无需 &）：如 #35; 表示 #，#59; 表示 ;。

## 七、版本兼容与图表专属语法

- 新语法报错
    - 错误类型：使用了 note、~~~ 等新语法，但当前环境 Mermaid 版本过低。
    - 识别方法：渲染失败或语法被当作普通文本显示。
    - 改正方法：降级使用基础语法（如用普通节点 + linkStyle 模拟注释，用 --> 替代 ~~~）。
- 跨图表语法混用
    - 错误类型：在时序图或类图中使用了流程图专属的箭头（如 --o）。
    - 识别方法：渲染失败或连线样式异常。
    - 改正方法：查阅官方文档，确保连线样式与当前图表类型匹配。
